# 斜杠命令注册与分发系统 Spec

## 背景

MewCode 当前在终端输入循环中直接判断少量斜杠命令。命令识别、参数校验、会话调用和界面输出混在同一入口，新增命令时需要继续扩展条件分支，也无法统一提供帮助信息、别名检查和 Tab 补全。

清屏、查询状态、切换模式等操作本质上不需要 Agent 推理。若仍作为普通消息发送给 AI，会增加响应延迟和 Token 消耗，并使确定性操作依赖模型理解。与此同时，代码审查等高频任务适合由固定命令生成预设请求，再交给 AI 执行。

本阶段建立统一的命令注册和分发能力，并保持现有会话、上下文压缩、权限和持久化机制可继续使用。

## 目标

- 让所有斜杠命令通过统一入口注册、解析、查找和执行。
- 让纯本地操作和界面状态操作绕过 Agent，获得快速、确定的响应。
- 支持把固定预设请求作为用户消息交给 AI，同时明确其执行边界。
- 提供大小写不敏感的命令名、兼容别名、参数提示和可发现的帮助信息。
- 在启动阶段发现名称或别名冲突，避免带歧义的注册表进入运行状态。
- 为终端提供跨平台的 Tab 补全和持续可见的 `[DEFAULT]`、`[PLAN]` 模式状态。
- 将命令行为与具体终端渲染方式隔离，为后续界面和 Skill 系统扩展保留稳定边界。

## 功能需求

### 命令定义与注册

- F1：每条命令必须登记规范名称、零个或多个别名、简短描述、用法示例、命令类型和处理行为；可选登记参数提示及隐藏标记。
- F2：命令类型分为纯本地、界面状态和预设提示词三类。类型应作为可查询元数据，用于帮助、测试和后续扩展。
- F3：启动时必须以大小写不敏感的方式检查所有规范名称和别名。任意名称与名称、名称与别名或别名与别名冲突时，程序必须立即终止，并明确指出冲突标识，不得进入交互循环。
- F4：十个公开内置命令和隐藏退出命令必须在启动交互循环前完成注册。除 `/permissions` 和 `/quit` 外，本阶段不增加其他内置别名。

### 输入解析与分流

- F5：提交输入后，空内容应直接返回输入循环，不触发命令或 AI 请求。
- F6：非空输入以 `/` 开头时必须按命令解析；第一个空格前的内容为命令标识，其余内容去除首尾空白后作为完整参数字符串，参数内部内容及大小写保持不变。
- F7：命令标识查找大小写不敏感，规范名称和别名具有相同行为。
- F8：未找到命令时必须显示简洁错误和 `/help` 引导，不得把原输入发送给 AI。
- F9：命令参数不符合用法时必须显示该命令的用法提示，不执行处理行为，也不发送 AI 请求。
- F10：不以 `/` 开头的非空输入按当前模式发送给 AI；命令输入由本地分发器处理，不进入普通对话入口。

### 执行边界与界面控制

- F11：纯本地命令可查询或调用当前进程中的本地服务，但不得进入 Agent Loop；上下文压缩可以直接调用既有压缩能力及其模型请求。
- F12：界面状态命令只能通过统一的界面控制能力显示消息、清理显示、切换模式或刷新状态，不依赖具体终端渲染实现。
- F13：预设提示词命令通过统一的用户消息发送能力进入对话，并像普通用户请求一样产生可见回复和会话记录。
- F14：命令处理失败时必须显示简洁错误并返回输入循环；除启动期注册冲突外，单条命令失败不得终止进程。
- F15：界面控制能力必须能够显示普通消息、发送用户消息、切换模式、读取 Token 统计和刷新状态栏。

### 模式状态

- F16：每次启动时初始模式为 `[DEFAULT]`。
- F17：`/plan` 不接受参数，只把后续普通输入切换到 `[PLAN]`；命令本身不调用 AI。
- F18：`[PLAN]` 模式中的普通输入只能使用读取、查找和搜索等无副作用能力，不得修改工作区或调用有副作用的工具。
- F19：`/do` 不接受参数，只把后续普通输入切换回 `[DEFAULT]`；命令本身不调用 AI，也不自动执行此前生成的计划。
- F20：模式切换后，底部状态栏必须立即显示对应的 `[DEFAULT]` 或 `[PLAN]` 标记；切换模式不得清空对话历史。

### 帮助与补全

- F21：`/help` 无参数时列出十个公开命令的名称、别名和简短描述；`/help <命令>` 显示该公开命令的描述、用法、参数提示和别名。
- F22：隐藏命令不出现在帮助列表和 Tab 补全候选中，但仍可直接执行。
- F23：输入斜杠命令前缀并按 Tab 时，匹配应忽略大小写；只有一个候选时直接补全，有多个候选时显示可选择菜单。
- F24：补全候选来自已注册的公开规范名称和公开别名，不维护独立命令清单；注册表变化应自动反映到帮助和补全中。

### 内置命令

- F25：`/help [命令]` 为纯本地命令，提供公开命令列表或单条命令详情。
- F26：`/compact` 为纯本地命令，不接受参数；它绕过 Agent Loop，直接触发现有手动上下文压缩，并显示压缩状态或失败原因。
- F27：`/clear` 为界面状态命令，不接受参数；它只清除当前终端显示，不删除或改变消息、会话、记忆、权限和模式状态。
- F28：`/plan` 和 `/do` 为界面状态命令，按 F17-F20 切换持续模式。
- F29：`/session` 为纯本地命令，不接受参数；它显示当前会话 ID、标题、新建或恢复状态、消息数量及是否存在进行中的会话操作，不输出消息正文。
- F30：`/memory` 为纯本地命令，不接受参数；它显示项目级与用户级有效记忆条数、索引容量使用情况和最近一次更新状态，不输出记忆正文。
- F31：`/permission [strict|default|allow]` 为纯本地命令；无参数时显示当前权限模式，有一个合法参数时切换模式，其他参数显示用法。`/permissions` 是其公开兼容别名。
- F32：`/status` 为纯本地命令，不接受参数；它显示当前模式、会话 ID、权限模式、累计 Token、上下文压缩状态和记忆状态，并刷新底部状态栏。
- F33：累计 Token 统计覆盖自当前进程打开该会话以来的全部模型调用，包括普通对话、计划模式、`/review`、上下文压缩和自动记忆更新；无法获得的统计项必须明确标记为不可用，不得猜测。
- F34：`/review` 为预设提示词命令，不接受参数；它向 AI 发送固定请求，审查当前工作区未提交的 Git 变更，优先报告缺陷、行为回归、安全风险和缺失测试。
- F35：`/review` 单次执行必须强制只读，不受当前持续模式影响；完成或失败后持续模式保持不变。
- F36：`/exit` 为隐藏的纯本地命令，用于正常关闭当前进程；`/quit` 是其隐藏兼容别名。正常关闭仍须完成既有会话和记忆收尾。

## 非功能需求

- N1：确定性——相同注册内容和输入必须得到相同的命令匹配、参数文本、帮助排序及补全候选；不得依赖注册顺序解决名称冲突。
- N2：低延迟——除 `/compact`、`/review` 和正常退出时必要的收尾外，纯本地与界面状态命令不得调用 Provider、进入 Agent Loop、访问网络或等待后台模型任务完成。
- N3：Token 可控——不需要 AI 的命令不得产生模型请求；需要模型的命令必须通过明确登记的执行类型进入对应路径。
- N4：跨平台——输入、Tab 补全、候选菜单、清屏和底部状态栏在 Windows、Linux 与 macOS 上提供等价行为。
- N5：界面一致性——普通输出、流式 Agent 输出、错误、清屏和模式切换后，底部状态栏都必须恢复为当前真实模式，不残留过期标记。
- N6：可靠性——运行期单条命令的解析、参数或处理错误不得破坏交互循环、会话历史或当前模式；启动期注册冲突必须稳定地产生非零退出。
- N7：隐私——帮助、状态、会话摘要、记忆摘要、补全菜单和错误信息不得输出消息正文、记忆正文、完整提示词、工具参数、凭据或疑似秘密。
- N8：兼容性——普通对话、上下文压缩、权限控制、会话恢复、自动记忆、工具调用、MCP 和 Provider 行为除明确修改的 Plan/Do 路由外保持兼容；`/permissions` 与 `/quit` 继续可用。
- N9：可测试性——注册冲突、解析、分流、命令处理、模式限制、帮助、补全和状态栏均可在不连接真实终端、网络、模型或用户目录的情况下自动验证。
- N10：可维护性——新增一条普通命令只需登记元数据和处理行为，不应要求修改解析器、帮助生成器、补全器或输入分流规则。
- N11：可演进性——界面控制边界不得暴露特定终端库对象，使未来其他界面能够复用同一命令注册和分发行为。
- N12：可观察性——用户能够区分未知命令、参数错误、命令处理失败、模式切换、压缩状态和 AI 请求失败；错误不得以原始堆栈代替用户可理解信息。
- N13：只读完整性——`[PLAN]` 和单次 `/review` 的只读限制必须由实际可用能力强制保证，不能只依赖提示词要求模型自律。
- N14：固定提示——`/review` 的预设请求在相同版本中保持稳定，不读取配置或根据运行内容动态拼接提示词；具体改动由 AI 使用只读能力自行检查。

## 不做的事情

- 不支持用户自定义命令、项目自定义命令或运行时动态注册。
- 不把 Skill、MCP 工具或普通本地工具自动转换为斜杠命令。
- 不支持根据参数、工作区内容或模型输出动态生成预设提示词。
- 不增加命令级权限策略、命令白名单或逐命令审批。
- 不支持命令管道、重定向、命令串联、引号解析或结构化参数语法；处理函数只接收一个原始参数字符串。
- 不为未知命令提供模糊匹配、自动纠错或自动发送给 AI。
- 不提供转义机制来把以 `/` 开头的输入作为普通用户消息发送。
- 不通过 `/session` 新建、切换、列出、重命名或删除会话。
- 不通过 `/memory` 查看、添加、编辑或删除具体记忆内容。
- 不让 `/clear` 清除上下文、会话记录、记忆或磁盘数据。
- 不让 `/review` 接受目标参数、审查完整代码库或修改工作区。
- 不保留 `/plan <任务>` 立即生成待执行计划、`/do` 立即执行待定计划的旧命令语义。
- 不持久化 `[DEFAULT]` 或 `[PLAN]` 界面模式；每次启动均从 `[DEFAULT]` 开始。
- 不增加命令历史搜索、主题、颜色或用户可配置的补全样式。

## 验收标准

### 注册与元数据

- AC1（F1、F2、F4）：启动后检查注册结果，十个公开命令均具有名称、描述、用法、类型和处理行为；可选字段可缺省；`/exit` 及 `/quit` 被标记为隐藏。
- AC2（F3）：分别构造名称与名称、名称与别名、别名与别名的冲突，并覆盖大小写不同的撞名；每种情况都在显示输入提示前以非零状态退出，并指出冲突标识。
- AC3（F4）：正常启动时注册表恰好包含十个公开规范命令、一个隐藏规范命令以及 `/permissions`、`/quit` 两个兼容别名，没有其他内置别名。

### 解析与分流

- AC4（F5-F7）：依次提交空白输入、普通文本、大小写不同的命令、带一个或多个空格的命令参数；空白输入无动作，普通文本进入当前 AI 模式，命令正确命中，参数内部文本和大小写保持不变。
- AC5（F8）：提交不存在的斜杠命令，终端显示未知命令和 `/help` 引导，Provider 与 Agent 均未收到该输入。
- AC6（F9）：向所有无参数命令追加参数，并向 `/permission` 提交非法模式或多余参数；每次均显示对应使用方法，不执行命令副作用，也不发送 AI 请求。
- AC7（F10-F13）：分别执行纯本地、界面状态、预设提示词命令和普通文本；前三者进入各自登记路径，只有预设提示词与普通文本形成用户请求和 AI 回复，会话记录与显示结果符合各自语义。
- AC8（F14）：让一个命令处理行为抛出预期错误，终端显示简洁错误；随后提交的正常命令仍可执行，原有消息、模式和会话数据保持有效。

### 模式与界面

- AC9（F16-F20、F28）：启动时底部状态栏显示 `[DEFAULT]`；执行 `/plan` 后立即显示 `[PLAN]`，执行 `/do` 后立即恢复 `[DEFAULT]`，两次切换都不产生模型请求或新增对话消息。
- AC10（F18）：在 `[PLAN]` 中提交要求修改文件和执行有副作用工具的任务，Agent 实际只能获得只读能力，工作区保持不变；切回 `[DEFAULT]` 后，相同能力重新受正常权限系统控制。
- AC11（F12、F15、N11）：使用替代界面实现执行显示、清屏、模式切换、Token 查询和状态刷新，全部命令可正常工作，命令处理行为不需要访问具体终端对象。
- AC12（N4、N5）：在 Windows、Linux 和 macOS 的自动化终端场景中执行流式输出、错误输出、清屏及连续模式切换，补全和底部状态栏行为等价，最终模式标记与真实模式一致。

### 帮助与补全

- AC13（F21、F22）：执行 `/help`，输出十个公开命令且包含 `/permissions` 别名，不包含 `/exit` 或 `/quit`；执行 `/help permission` 时显示其描述、用法、参数提示和别名。
- AC14（F23、F24）：对只有一个匹配项的前缀按 Tab，输入被直接补全；对多个匹配项的前缀按 Tab，显示选择菜单；改变输入大小写结果不变；隐藏名称和隐藏别名从不出现。
- AC15（F24、N10）：在测试注册表中新增一个公开命令而不修改帮助、补全或解析逻辑，新命令自动出现在帮助与补全中并可被分发。

### 内置本地与界面命令

- AC16（F25）：`/help` 的列表和详情完全来自注册元数据，别名调用与规范名称调用结果一致。
- AC17（F26）：执行 `/compact` 时不进入 Agent Loop，只触发一次现有手动压缩；成功、无需压缩和失败三种结果均显示对应状态，失败时活动历史保持不变。
- AC18（F27）：建立包含消息、记忆、非默认权限和 `[PLAN]` 模式的会话后执行 `/clear`，终端内容被清除且状态栏重新显示 `[PLAN]`；上述会话数据与状态均未改变。
- AC19（F29）：在新建会话和恢复会话中分别执行 `/session`，输出正确的 ID、标题、新建或恢复状态、消息数量和操作状态，且不包含消息正文或工具结果。
- AC20（F30）：准备项目级和用户级记忆以及成功、失败、进行中等更新状态，执行 `/memory` 后显示正确条数、索引容量和最近更新状态，不包含任何记忆正文。
- AC21（F31）：`/permission` 无参数时显示当前模式；依次设置 `strict`、`default`、`allow` 后权限系统立即使用对应模式；通过 `/permissions` 执行得到相同行为。
- AC22（F32、F33）：使用可控 Provider 分别产生普通对话、计划模式、`/review`、上下文压缩和自动记忆更新的 Token 用量，`/status` 显示的累计值等于当前进程打开该会话后全部调用之和，同时正确显示模式、会话、权限、压缩和记忆状态。
- AC23（F33）：当某次 Provider 调用不返回部分或全部 Token 用量时，`/status` 对缺失项明确显示不可用，已知项仍正确累计，不以估算值冒充 Provider 统计。
- AC24（F34、F35）：在 `[DEFAULT]` 和 `[PLAN]` 中分别执行 `/review`，AI 都收到同一固定审查请求，只能读取当前未提交 Git 变更，产生正常回复和会话记录，工作区无修改；完成或失败后原模式保持不变。
- AC25（F36）：通过 `/exit` 和 `/quit` 分别退出，进程都完成既有会话持久化、后台记忆收尾和资源关闭后返回成功；两者均不出现在帮助或补全中。

### 兼容性、安全与端到端

- AC26（N2、N3）：对 `/help`、`/clear`、`/plan`、`/do`、`/session`、`/memory`、`/permission` 和 `/status` 记录调用轨迹，确认没有 Provider、Agent Loop、网络访问或对后台模型任务的等待。
- AC27（N7、N12）：让会话、记忆、工具参数和异常中包含凭据及可识别正文，帮助、状态、摘要、补全和用户错误中均不出现这些内容，也不显示原始堆栈。
- AC28（N8）：运行既有普通对话、压缩、权限、恢复、记忆、工具、MCP、OpenAI 和 Anthropic 自动化测试；除已替换的 `/plan <任务>` 与 `/do` 立即执行语义外，其余行为继续通过。
- AC29（F1-F36）：端到端执行“启动 → 查看帮助并补全 → 进入 `[PLAN]` 分析任务 → 返回 `[DEFAULT]` → 清屏 → 修改权限 → 查看会话、记忆和状态 → 执行只读 `/review` → 压缩 → 退出”；每一步均走正确路径，状态栏一致，只有预期操作调用模型，最终会话可正常恢复。

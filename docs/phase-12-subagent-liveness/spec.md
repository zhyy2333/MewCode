# 子 Agent 活性保护 Spec

## 背景

定义式子 Agent 非交互运行。当角色采用默认权限模式且持久权限规则没有覆盖实际只读工具参数时，需要确认的调用会被自动拒绝。拒绝结果虽然安全，却会返回模型继续推理；模型可反复尝试直至轮次上限。前台等待上限只负责转入后台，后台没有整体执行期限，因此一个简单探索任务可能长时间运行并持续消耗模型请求。

## 目标

- 让内置只读探索角色在工作区安全边界内开箱可用。
- 对没有取得工具进展的重复拒绝建立确定、低成本的终止条件。
- 为所有前台和后台子任务建立最终墙钟时间上限。
- 保持现有非交互权限原则、工具范围交集和前台转后台语义不变。

## 功能需求

- F1：内置只读探索角色应无需人工确认即可执行其已冻结的只读工具；工作区边界、父模式安全上限、角色工具列表、全局禁用和硬安全检查仍然有效。
- F2：子 Agent 连续 3 个工具批次全部因权限、冻结策略或 Hook 拒绝且没有任何成功执行时，应立即停止，不再请求下一轮模型，并返回可识别的“工具拒绝上限”失败原因。
- F3：只要一个批次包含至少一个真实成功执行的工具，连续拒绝计数应归零；未知工具仍沿用既有独立上限。
- F4：每个子任务从注册开始最多运行 300 秒；达到期限后应取消其活动模型或工具工作，进入单一 `failed` 终态并保留截至超时的用量。
- F5：300 秒期限覆盖定义式与 Fork、前台与后台；10 秒前台上限仍只执行原地转后台，不重启也不延长整体期限。
- F6：权限拒绝熔断和整体超时应生成有界、去敏的任务错误、终端摘要和一次性根通知，并继续支持本地任务查询。

## 非功能需求

- N1：普通根 Agent 的权限交互、轮次上限和工具重试行为保持兼容；拒绝熔断只在子 Agent 运行配置中启用。
- N2：时间与拒绝计数必须可由测试替身确定性控制；测试不得真实等待 300 秒或访问网络。
- N3：超时、取消、自然完成之间的竞态最多产生一个终态、一个终端事件和一个完成通知。
- N4：不得因活性保护扩大子 Agent 的工具集、文件访问范围或权限持久化能力。

## 不做的事情

- 不增加交互式子 Agent 权限确认。
- 不修改角色 frontmatter 格式，也不增加可配置超时字段。
- 不自动写入或放宽项目权限文件。
- 不改变 Fork 的缓存前缀、后台强制规则或跨会话持久化范围。
- 不处理 Worktree 隔离、团队编排或任务恢复等其他阶段能力。

## 验收标准

- AC1：在没有源码通配权限规则的工作区，内置探索角色可成功调用其三个只读工具；写工具、越界路径和全局禁用工具仍被拒绝。
- AC2：连续 3 轮全拒绝时只发生 3 次模型工具响应，随后以明确原因终止；任一成功工具批次会重置计数。
- AC3：达到虚拟 300 秒时，活动定义式/Fork 和前台/后台任务均被取消并只提交一次 `failed`，查询结果、摘要、通知和 usage 一致。
- AC4：10 秒转后台后仍沿用原注册时间计算 300 秒期限，Provider、消息、权限和 usage 不重启。
- AC5：根 Agent、未知工具熔断、用户取消、正常子任务和现有 937 项回归保持通过。

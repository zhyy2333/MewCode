# Hook 自动化系统 Spec

## 背景

MewCode 已具备 Agent Loop、结构化提示、工具调度、权限控制、会话持久化、上下文压缩和 Skill 系统，但 Agent 生命周期中的固定重复工作仍需人工触发或持续监督。格式化、外部通知、动态上下文补充和针对工具参数的附加安全策略都缺少统一的自动化入口。

本阶段引入声明式 Hook 自动化系统。用户以“事件 + 可选条件 + 动作”描述规则，MewCode 在会话、轮次、模型交互、工具调用和少量系统生命周期节点自动执行匹配动作。工具执行前的 Hook 可以在既有硬安全限制之上追加拒绝，并把原因作为工具结果反馈给模型，使 Agent 能调整后续方案。

Hook 是主流程的辅助能力：除经过严格协议返回的显式工具拒绝外，Hook 的超时、进程错误、网络错误、输出错误或内部异常都只进入诊断日志，不能中断 Agent 主流程。

## 目标

- 用统一且可校验的 YAML 规则替代生命周期节点上的人工重复操作。
- 覆盖会话、轮次、模型交互和工具调用四层生命周期，并覆盖上下文压缩和系统错误。
- 允许基于工具名称和嵌套参数实施细粒度附加安全策略，但绝不放宽既有安全限制。
- 支持 shell 命令、提示词注入、HTTP 请求和子 Agent 占位四类动作。
- 为同步、后台、仅首次匹配和命令超时提供确定且有界的执行语义。
- 对配置错误采用启动前原子失败，对运行期动作错误采用隔离、记录和放行。
- 保护用户免受未信任项目共享 Hook 自动执行命令或外发数据的风险。
- 为后续子 Agent 真实运行、`once` 状态持久化和显式优先级保留清晰扩展边界。

## 功能需求

### 规则定义、来源与加载

- F1：每条 Hook 规则必须包含 `event` 和 `action`，可以包含 `if`；缺少 `if` 表示该事件每次发生时均匹配。
- F2：根配置必须以 `hooks` 列表保存规则。根节点、规则、条件、动作及执行控制均采用严格字段校验，未知字段、错误类型、空必填值或非法组合必须使配置无效。
- F3：系统必须依次加载用户全局 `~/.mewcode/hooks.yaml`、项目共享 `<workspace>/.mewcode/hooks.yaml` 和项目本地 `<workspace>/.mewcode/hooks.local.yaml`。缺失文件视为空配置。
- F4：三个来源采用追加语义，不按名称覆盖。默认执行顺序固定为“用户全局 → 项目共享 → 项目本地”，每个文件内保持 YAML 声明顺序；本阶段不提供显式优先级。
- F5：进入交互前必须集中解析和校验全部现有 Hook 文件。任一文件或规则无效时必须拒绝启动并指出文件、规则位置和原因，不得启用部分新配置。
- F6：配置加载不得执行动作、发送网络请求、启动子进程或调用模型；相同文件内容必须生成相同规则集合和执行顺序。
- F7：Hook 配置只在启动时加载。本阶段不监听文件变化，也不在会话运行中自动重载。

### 工作区信任

- F8：用户全局和项目本地 Hook 视为用户直接控制；项目共享 Hook 中可能执行外部副作用的 shell 和 HTTP 动作必须受工作区信任门禁约束。
- F9：首次发现未信任工作区包含项目共享 shell 或 HTTP 动作时，系统必须在执行任何此类动作前显示配置来源并请求用户明确决定。不得把不存在信任记录解释为同意。
- F10：工作区信任决定必须按规范化工作区身份独立持久化，不能写入项目共享文件，也不能把一个工作区的信任扩展到另一个工作区。
- F11：用户拒绝信任后，会话仍可继续，但该项目共享文件中的 shell 和 HTTP 动作必须保持禁用并显示一次清晰诊断；提示词动作仍可使用，子 Agent 动作仍遵循本阶段的占位语义。
- F12：项目共享 Hook 即使已被信任，也不能绕过危险命令防护、工作区路径边界、权限系统或其他系统安全上限；信任只授权 Hook 自身声明的外部动作具备运行资格。

### 生命周期事件

- F13：系统必须支持以下固定事件：`session.start`、`session.end`、`turn.start`、`turn.end`、`message.before`、`message.after`、`tool.before`、`tool.after`、`system.compact.before`、`system.compact.after`、`system.error`。其他事件名必须在启动校验时被拒绝。
- F14：`session.start` 在会话创建或恢复完成、运行环境可用后触发，并标明新建或恢复；`session.end` 在正常退出的会话收尾阶段触发。进程被操作系统强制终止时不保证触发结束事件。
- F15：一次轮次从一条被接受的普通用户任务开始，到该任务完成、失败或取消为止；对应触发一次 `turn.start` 和一次 `turn.end`。仅在本地处理且不启动 Agent 的斜杠命令不形成轮次。
- F16：消息级事件表示一次 Provider 交互，而不是一次历史记录写入。每次向 Provider 发起模型请求前触发 `message.before`，该次响应完成、失败或取消后触发 `message.after`；同一轮工具迭代产生的多次 Provider 交互分别触发。
- F17：每个进入工具调度的调用均形成工具生命周期。不可绕过的危险命令和路径边界检查通过后触发 `tool.before`；工具成功、失败、Hook 拒绝、权限拒绝或取消后均触发 `tool.after`。
- F18：上下文压缩尝试开始前触发 `system.compact.before`，产生成功、失败或无需压缩的确定结果后触发 `system.compact.after`。
- F19：非 Hook 引起且已进入系统统一错误边界的运行时错误触发 `system.error`。Hook 配置错误发生在启动前，Hook 动作错误只记 Hook 日志，两者均不得再次触发 `system.error`，以避免递归。
- F20：所有 `*.after` 和 `*.end` 事件必须携带 `success`、`failure`、`denied` 或 `cancelled` 等适用状态和有界错误摘要。只要对应生命周期已开始，在可控的错误和取消路径上就必须恰好触发一次结束事件。

### 事件数据

- F21：每次触发必须形成统一、带版本的 JSON 事件信封，至少标明事件名、时间、规则可用的工作区与会话标识，并按事件提供轮次、模型交互、迭代、工具调用、压缩或错误上下文。
- F22：工具事件必须提供稳定工具名、调用标识和原始结构化参数；`tool.after` 还必须提供结果状态及有界结果或错误摘要，使条件和外部策略可以按嵌套工具参数判断。
- F23：模型交互事件只提供实现自动化所需的有界元数据和内容摘要，不得默认复制完整系统提示、全部历史、凭据或隐藏推理到 Hook 事件信封。
- F24：内部条件判断使用当前事件的规范化数据；发送给 shell 或 HTTP 的事件信封必须有明确体积上限，发生截断时必须保留字段路径和截断标记，不能生成看似完整的静默截断数据。
- F25：shell 动作必须通过标准输入接收事件信封；HTTP 动作必须以 JSON 请求体发送同一语义的事件信封。工具参数不得通过命令字符串插值或隐式环境变量拼接。

### 条件表达式

- F26：`if` 必须且只能包含 `all` 或 `any` 之一，其值必须是非空条件子句列表；不允许在同一规则中混用两种逻辑组合，也不支持嵌套逻辑组。
- F27：每个条件子句必须声明事件字段路径、匹配方式和值，并可用布尔 `negate` 对该子句结果取反。字段路径必须属于该事件的公开字段；工具参数下的动态嵌套路径允许在运行时解析。
- F28：匹配方式只允许 `exact`、`glob` 和 `regex`。`exact` 与 `glob` 必须复用权限规则的完整值匹配、glob 元字符和反斜杠转义语义；`regex` 必须对完整字段值匹配，非法或超出限制的表达式在启动时拒绝。
- F29：字段不存在、无法沿声明路径解析或值不符合该匹配器支持的标量形式时，基础匹配结果为不匹配，随后再应用 `negate`；条件求值错误不得被当作匹配成功。
- F30：`all` 在全部子句为真时匹配，`any` 在至少一个子句为真时匹配。相同事件数据与配置必须得到确定结果，条件求值不得执行用户代码、访问网络或修改状态。
- F31：Hook 条件对权限系统是扩展超集。新增的 `regex` 与 `negate` 只属于 Hook，不改变现有权限 YAML 对精确和 glob 的语法、优先级或兼容行为。

### 动作类型

- F32：动作类型只允许 `command`、`prompt`、`http` 和 `agent`；每种动作必须只接受自身字段与适用的公共执行控制，不得把未知字段透传给执行器。
- F33：`command` 动作执行显式 shell 命令，以当前工作区为工作目录，通过标准输入接收事件信封，并分别有界收集标准输出和标准错误。
- F34：`command` 动作必须支持可选命令超时；超时值必须为受限的正数，未声明时使用有界默认值。超时后必须终止命令及系统能够识别的关联子进程，并记录超时结果。
- F35：`prompt` 动作必须提供非空提示内容。内容作为动态系统上下文只注入下一次模型请求，不写入会话历史；`message.before` 产生的提示作用于当前即将发送的请求，其他事件产生的提示按规则顺序排队到下一次请求。
- F36：会话结束时尚未消费的提示注入必须丢弃；提示内容不能伪装成用户历史消息，也不能覆盖更高优先级的系统安全约束。
- F37：`http` 动作必须声明合法的 HTTP(S) 目标和受支持方法，可声明有界请求超时及静态请求头；请求体由系统提供的事件信封构成。网络错误、非成功状态、超时或无效决策响应均视为 Hook 动作失败。
- F38：配置、诊断、请求构建和响应处理不得把认证请求头、URL 中的敏感信息或其他凭据写入模型上下文、会话历史或普通日志。
- F39：`agent` 动作在本阶段只完成字段识别和集中校验。匹配时不得启动模型或子 Agent，必须产生明确且有界的“尚未实现、已跳过”诊断，并继续主流程。

### 工具拦截

- F40：只有同步的 `tool.before` 命令或 HTTP 动作可以返回工具决策。空响应表示本 Hook 不拦截；非空响应必须是严格 JSON 对象，只允许 `decision` 和适用字段。
- F41：决策只允许 `allow` 或 `deny`。`deny` 必须携带非空、长度受限的 `reason`；`allow` 只表示当前 Hook 不拦截，不得跳过后续 Hook、现有权限判断或硬安全限制。
- F42：命令的非零退出、HTTP 非成功状态、超时、无效 JSON、未知决策、缺失拒绝原因和读取错误都是 Hook 失败，必须记录并按放行处理，不能误当作拒绝。
- F43：工具调用的安全顺序必须为“不可绕过的危险命令与路径门禁 → `tool.before` Hook → YAML 权限规则、权限模式与人工确认 → 实际工具执行”。Hook 只能增加拒绝，不能把任何既有拒绝改为允许。
- F44：明确拒绝必须阻止工具实现运行，并转成与现有权限拒绝同类的结构化工具失败；结果必须包含有界拒绝原因并反馈给模型，使 Agent 可以调整方案。
- F45：同一 `tool.before` 命中多条同步规则时按默认规则顺序执行。`allow` 或空响应继续下一条；首次 `deny` 立即停止剩余 `tool.before` 规则并确定本次拒绝原因。

### 执行控制与调度

- F46：规则可声明 `once`。缺省为关闭；启用后，每条规则在当前 MewCode 进程中首次匹配时、动作尝试前即被原子标记为已消费，此后不再执行。动作失败也不重试，进程重启后标记清空。
- F47：`once` 状态按具体已加载规则区分；并发事件不能使同一规则执行两次。恢复旧会话不恢复旧进程的消费标记。
- F48：命令和 HTTP 动作可声明后台执行。后台动作按默认规则顺序启动，但主生命周期不等待其完成；完成、失败或超时后只更新 Hook 诊断。
- F49：`tool.before` 规则禁止后台执行，包含该组合的配置必须在启动时被拒绝。提示词动作也不得后台执行，以保证下一次请求的注入顺序确定。
- F50：同一事件的同步规则严格按默认顺序逐条完成；某条规则发生运行期失败时记录错误并继续后续规则，只有合法的工具 `deny` 可以短路。
- F51：后台任务必须被系统跟踪。正常会话退出时系统只进行有界清理，超过清理边界仍未完成的 HTTP 任务必须取消，仍在运行的命令必须终止；不得留下由 MewCode 管理但失去跟踪的任务。

### 故障隔离与诊断

- F52：Hook 运行期失败不得改变轮次、消息、压缩或会话的成功状态，不得抛出到 Agent 主循环，也不得自动重试。工具拦截协议产生的合法 `deny` 是业务决策，不属于 Hook 失败。
- F53：每次动作必须产生有界诊断记录，至少包含时间、事件、配置来源、规则位置、动作类型、同步或后台状态、耗时和成功、失败、跳过或拒绝结果。
- F54：诊断必须区分配置校验错误、未信任禁用、条件不匹配、占位动作跳过、命令退出、命令超时、HTTP 状态、网络错误、决策协议错误、显式拒绝和后台取消，但不得使用原始堆栈或无限输出替代说明。
- F55：Hook 自身的失败、日志写入失败或诊断渲染失败均不得触发 Hook，也不得形成 `system.error` 递归；诊断设施失效时仍须优先维持 Agent 主流程。

## 非功能需求

- N1 确定性：相同配置、工作区信任状态和事件序列必须得到相同的匹配结果、同步执行顺序、后台启动顺序、提示排队顺序和工具拒绝结果。
- N2 原子性：启动配置必须全量校验后一次启用；校验失败时不得留下部分规则、部分信任变更或已经启动的动作。
- N3 故障隔离：除合法 `tool.before` 拒绝外，任何 Hook 运行时异常都不得中断、取消、改写或伪造 Agent 主流程结果。
- N4 安全单调性：Hook 只能在硬安全与权限系统上追加限制，不能扩大模型能力、工具集合、文件边界、命令能力或权限结果。
- N5 工作区安全：未信任项目共享配置不得执行 shell 或 HTTP；信任记录必须绑定规范化工作区且不能由仓库内容自行授予。
- N6 隐私：事件信封、日志、HTTP 诊断和工具拒绝原因必须使用最小必要信息并执行长度限制与凭据脱敏；完整系统提示、隐藏推理、API Key 和认证头不得泄露。
- N7 资源有界：规则数、条件数、字段值、正则、事件信封、命令输出、HTTP 响应、拒绝原因、日志和后台任务都必须有明确限制；命令和网络请求必须有终止边界。
- N8 并发安全：`once` 消费、提示队列、后台任务登记与关闭、同步规则顺序及首次拒绝短路在并发工具调用下必须保持一致，不得重复执行或交叉污染事件数据。
- N9 可观察性：用户必须能区分启动配置错误、工作区未信任、规则未匹配、动作成功、动作失败、动作跳过、工具拒绝与后台取消，同时普通终端输出不得被 Hook 细节淹没。
- N10 兼容性：未配置 Hook 时，普通对话、PLAN、工具并发、权限确认、MCP、Skill、上下文压缩、会话恢复和退出行为必须保持不变。
- N11 跨平台：配置路径、shell 启动、工作目录、标准输入、超时终止、后台清理和日志行为必须在 Windows、Linux 和 macOS 上提供等价语义；具体 shell 语法仍由配置作者针对目标平台负责。
- N12 可测试性：事件触发、加载校验、信任门禁、条件匹配、动作协议、短路、失败放行、并发 `once`、提示注入和后台清理必须能在不连接真实模型、网络、用户目录或执行真实危险命令的情况下自动验证。
- N13 可维护性：四类动作必须共享事件信封、条件求值、执行控制、诊断和失败隔离语义；各生命周期接入点不得各自维护不一致的规则解释器。

## 不做的事情

- 不真实启动子 Agent；`agent` 动作仅解析、校验、记录跳过结果并预留后续接入边界。
- 不持久化 `once` 消费状态；重启进程后允许再次执行。
- 不提供规则 `priority`、依赖关系、前后约束或用户自定义排序；只使用来源和 YAML 声明顺序。
- 不提供 Hook 配置热更新、后台文件监听器或手动重载命令。
- 不支持嵌套 `all`/`any`、混合逻辑树、任意表达式求值、脚本条件或权限 YAML 中的正则与反向匹配。
- 不允许 Hook 修改工具名称、工具参数、工具成功结果、Provider 原始响应、会话历史或事件信封；工具前置 Hook 只能继续或拒绝。
- 不让 Hook 的 `allow` 覆盖危险命令、路径沙箱、权限规则、权限模式、人工拒绝、PLAN 限制或 Skill 工具白名单。
- 不自动重试失败的命令、HTTP 请求或后台任务，也不提供重试退避、熔断、定时任务或 cron。
- 不提供跨进程 Hook 编排、远程队列、分布式锁、执行历史同步或团队级信任同步。
- 不实现通用操作系统沙箱、容器隔离或网络出口代理；已信任 Hook 以当前 MewCode 进程的操作系统身份和网络能力运行。
- 不保证在进程崩溃、强制结束、断电或操作系统无法回收子进程的情况下触发 `session.end` 或完成后台清理。
- 不把 Hook 诊断写入模型对话历史，也不让 `system.error` 捕获并再次触发 Hook 自身错误。

## 验收标准

### 配置、来源与信任

- AC1（F1–F7）：分别加载三层合法配置，确认规则按“用户全局 → 项目共享 → 项目本地”和文件声明顺序追加；缺失文件为空，未知字段、缺失事件或动作、非法组合及任一文件错误均在交互前原子拒绝，且没有动作被执行。
- AC2（F8–F12）：在未信任工作区放置项目共享 shell、HTTP、提示词和 agent 动作，确认系统在任何外部动作前请求信任；拒绝后 shell/HTTP 均不执行，提示词仍可用，agent 只显示占位跳过；信任一个工作区不会授权另一个工作区。
- AC3（F10、F12）：重启并恢复已信任工作区，确认信任决定独立于项目文件恢复，且已信任 Hook 仍无法绕过危险命令、路径边界或权限拒绝。

### 生命周期事件与数据

- AC4（F13–F20）：执行一次包含两次模型调用和一次工具调用的成功轮次，确认会话、轮次、两次消息交互和工具的前后事件各按语义触发，事件名只来自固定 11 项目录。
- AC5（F15–F20）：分别制造 Provider 失败、工具失败、权限拒绝、Hook 拒绝、轮次取消、压缩无需执行和压缩失败，确认已开始的生命周期均恰好产生一次带正确状态的结束事件。
- AC6（F19、F55）：让普通系统路径和 Hook 动作分别失败，确认前者触发一次 `system.error`，后者只进入 Hook 诊断且不递归触发任何 Hook。
- AC7（F21–F25）：检查各层事件信封，确认标识、状态和适用上下文完整，命令 stdin 与 HTTP JSON 请求体语义一致；大字段被显式标记截断，完整系统提示、隐藏推理和凭据未出现。

### 条件匹配

- AC8（F26、F30）：分别使用合法 `all`、合法 `any`、无条件规则、混用逻辑组、空列表和嵌套组，确认前三者按真值触发，后三者在启动时被拒绝。
- AC9（F27–F31）：对工具名和嵌套参数分别验证精确、glob、完整正则和 `negate`；确认 glob 转义与权限规则一致，缺失字段先按不匹配再取反，非法正则在启动时失败，权限配置行为没有变化。
- AC10（F22、F27）：让两个同名工具调用携带不同嵌套参数，确认细粒度条件只命中目标调用，未命中的规则不启动动作且产生可区分诊断。

### 动作与提示注入

- AC11（F32–F34）：运行成功命令、非零退出命令、超时命令和超量输出命令，确认工作目录、JSON stdin、输出边界、终止行为和诊断符合要求，所有失败均未中断主流程。
- AC12（F35、F36）：分别在 `session.start`、`turn.start`、`message.before` 和 `tool.after` 注入提示，确认每份内容只进入下一次适用模型请求、不写入历史、按规则顺序出现，未消费内容在会话结束时丢弃。
- AC13（F37、F38）：模拟 HTTP 成功、非成功状态、网络错误、超时和超量响应，确认请求体为事件信封、失败被隔离、响应有界，认证头和敏感 URL 信息未进入日志或模型上下文。
- AC14（F39）：配置并触发合法 agent 动作，确认启动校验通过、运行时产生明确跳过诊断、没有 Provider 请求、没有子 Agent，主流程继续。

### 工具拦截与权限协同

- AC15（F40–F45）：让多个同步 `tool.before` 动作依次返回空、`allow` 和带原因的 `deny`，确认前两者继续、首次拒绝立即短路，工具实现不运行，拒绝原因作为结构化工具失败反馈给模型。
- AC16（F40–F42）：分别返回非零退出、HTTP 错误、无效 JSON、未知决策和缺失原因的 `deny`，确认它们都作为 Hook 失败记录并放行到后续 Hook 与权限系统，不被误当成拒绝。
- AC17（F41、F43）：让 Hook 返回 `allow`，同时让危险命令门禁、路径门禁、权限规则、人工确认和模式限制分别拒绝，确认所有既有拒绝仍生效。
- AC18（F43）：对需要人工确认且最终被 Hook 拒绝的调用，确认顺序为硬门禁、Hook、常规权限，用户不会先收到无意义的权限确认；对硬门禁拒绝确认 shell/HTTP Hook 未接触其参数。
- AC19（F17、F20、F44）：Hook 或权限拒绝工具后，确认模型收到可调整策略的工具结果，`tool.after` 仍以 `denied` 恰好触发一次。

### 执行控制、并发与失败隔离

- AC20（F46、F47）：让同一 `once` 规则在并发事件中多次匹配并使首次动作失败，确认只有一次尝试；同进程后续不重试，重启后可再次触发，恢复旧会话不恢复消费标记。
- AC21（F48–F51）：混合同步与后台命令/HTTP，确认同步动作严格串行，后台动作按序启动但不阻塞主事件；正常退出时未完成任务在有界清理后被取消或终止，不遗留失管任务。
- AC22（F49）：为 `tool.before` 或提示词动作配置后台执行，确认启动校验明确拒绝；其他合法后台动作仍可加载。
- AC23（F50、F52）：让中间同步规则抛出各类运行时错误，确认后续规则继续执行，轮次和消息结果不变；只有合法工具拒绝产生短路。
- AC24（F53–F55）：核对成功、失败、跳过、未信任、拒绝和后台取消的诊断，确认包含来源、规则位置、耗时和结果且均有界、已脱敏，不包含原始堆栈、无限输出或凭据。

### 兼容性与质量属性

- AC25（N1–N3、N8、N13）：以相同配置和事件序列重复运行，并在并发工具调用下验证，确认匹配、顺序、`once`、提示队列、后台登记和首次拒绝结果稳定，动作执行器共享一致的失败隔离语义。
- AC26（N4–N7）：验证未信任项目不能产生外部副作用，已信任 Hook 不能扩大系统权限；大型参数、正则、输出、响应、原因和任务数量均受限，敏感内容未泄露。
- AC27（N9、N10）：在完全没有 Hook 文件时运行普通对话、PLAN、工具并发、权限、MCP、Skill、压缩、恢复和退出回归，确认行为不变且终端没有额外 Hook 噪声；配置 Hook 后关键状态可被清晰诊断。
- AC28（N11、N12）：在 Windows、Linux 和 macOS 自动化环境验证路径、shell、stdin、超时终止与后台清理；核心测试使用 fake Provider、HTTP transport、时钟、进程和临时目录，不访问真实网络、用户目录或危险命令。

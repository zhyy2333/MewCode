# MewCode REPL 输出层级优化 Spec

## 背景

MewCode 的 Agent Loop 已能实时显示模型文本、迭代进度、工具调用、工具结果和 Token 用量，但当前所有事件都顶格连续输出。长任务中，主步骤与辅助信息缺少视觉层级，相邻迭代也容易连成一片，用户难以快速判断当前处于哪一步。

## 目标

- 让每次 Agent 迭代成为清晰的一级步骤。
- 让工具、Token 和批次进度成为所属步骤下的次级信息。
- 用稳定的空行分隔相邻步骤，提高长任务输出的可扫描性。
- 保持文本流式输出、事件内容和 Agent 执行行为不变。

## 功能需求

- F1：每个 `agent: iteration N` 作为一级步骤顶格显示。
- F2：工具调用、工具结果、Token 用量和工具批次进度统一缩进两个空格。
- F3：相邻 Agent 迭代之间显示一个空行；第一轮迭代前不额外制造多余空行。
- F4：模型生成的正文和最终停止状态保持一级显示，不继承辅助事件缩进。
- F5：取消、流错误和内部错误等停止信息沿用现有内容，只调整必要的步骤分隔，不改变错误语义。

## 非功能需求

- N1：文本增量仍需立即写入终端，不得为了排版缓存完整回复。
- N2：输出不得新增完整工具参数、完整工具结果或隐藏推理内容。
- N3：现有 `/plan`、`/do`、普通对话、退出和取消行为保持兼容。
- N4：排版规则在 Windows 终端及测试用文本流中产生一致的换行和空格。

## 不做的事

- 不增加颜色、图标、终端控制码或第三方富文本库。
- 不修改 Agent 事件模型、工具调度、Provider 或 Token 统计逻辑。
- 不改变现有事件文案和工具结果摘要长度。
- 不为用户增加可配置的缩进宽度或主题选项。

## 验收标准

- AC1：一次包含工具调用和 Token 用量的迭代中，所有辅助事件均以两个空格开头，迭代标题顶格显示。
- AC2：连续两个迭代之间恰好有一个空行，迭代内部的辅助事件之间没有额外空行。
- AC3：第一轮迭代输出不以空白行开始，模型正文和最终状态不带辅助缩进。
- AC4：流式文本仍按分片即时写入，工具参数和大段结果仍不会出现在终端。
- AC5：普通对话、Plan Mode、取消及错误恢复相关测试继续通过。

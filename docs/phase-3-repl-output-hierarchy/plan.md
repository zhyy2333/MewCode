# MewCode REPL 输出层级优化 Plan

## 架构概览

本次改动保持 Agent 事件生产链不变，只在 REPL 消费事件时增加一个单次运行级的状态化渲染器。现有事件到文案的映射继续负责“显示什么”，渲染器负责“如何排列”：识别一级与次级事件、补齐行边界，并在相邻迭代之间插入一个空行。

每次用户任务开始消费事件时创建新的渲染器，因此第一轮状态不会受到上一条用户任务影响。模型文本分片到达后立即经过渲染器并写入输出流，不累积完整回复。

## 核心数据结构

### `_EventRenderer`

维护单次 Agent 运行的终端排版状态。

状态：

- `seen_iteration: bool`：是否已经输出过迭代标题，用于区分第一轮和后续轮次。
- `at_line_start: bool`：当前输出位置是否处于新行开头，用于避免正文与状态行粘连。

接口：

```python
class _EventRenderer:
    def render(self, event: AgentEvent) -> str | None: ...
```

`render()` 每收到一个事件立即返回本次需要写入的字符串；被忽略的进度事件返回 `None`。

### `_format_event`

保留现有的事件文案映射职责，返回不带动态步骤间距的基础文本。渲染器在其结果上应用层级和换行规则，避免把运行状态散落到每个事件分支。

## 模块设计

### REPL 事件消费

**职责：** 为每次 `_consume()` 创建独立渲染器，逐事件渲染、写入并刷新输出。

**对外接口：** `Repl.run()`、命令路由和退出行为保持不变。

**依赖：** Agent 公共事件类型和文本输出流。

### 事件排版

**职责：**

- 将工具调用、工具结果、Token 用量和工具批次进度标记为次级行，并统一添加两个空格。
- 第一轮迭代标题直接输出；后续迭代标题前确保恰好存在一个空白行。
- 在线性状态行前补齐必要换行，防止前一个流式文本分片未以换行结尾时发生粘连。
- 模型文本和停止状态保持顶格，不改变原有文案。

**对外接口：** `_EventRenderer.render()`。

**依赖：** `_format_event()` 提供基础文案。

### 回归测试

**职责：** 用内存文本流验证最终字符序列，而不依赖真实终端或 Provider。

覆盖：

- 单轮层级缩进。
- 两轮之间恰好一个空行。
- 第一轮无前导空行。
- 流式正文未带换行时，后续状态行不粘连。
- 参数隐藏、命令路由、取消和错误恢复保持不变。

## 模块交互

```text
Conversation 异步事件流
        |
        v
Repl._consume()
        |
        +--> 为本次运行创建 _EventRenderer
        |
        +--> event -> _format_event() -> 基础文案
        |                         |
        |                         v
        +----------------> 层级与换行状态处理
                                  |
                                  v
                         stdout.write() + flush()
```

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 排版状态位置 | REPL 内的单次运行渲染器 | 层级与空行是界面关注点，不污染 Agent 事件或业务逻辑 |
| 渲染生命周期 | 每次 `_consume()` 新建 | 第一轮不会继承上一任务的迭代和行状态 |
| 缩进宽度 | 固定两个 ASCII 空格 | 与确认的终端样式一致，在不同终端中稳定 |
| 步骤分隔 | 仅在后续迭代标题前补一个空行 | 提升扫描性，同时避免每条事件都变得松散 |
| 流式处理 | 每事件立即渲染和刷新 | 保留当前实时反馈，不为排版牺牲响应速度 |
| 依赖 | 仅使用现有标准库和事件类型 | 本次改动无需增加运行时依赖或配置项 |

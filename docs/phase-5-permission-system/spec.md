# MewCode 权限系统 Spec

## 背景

MewCode 已具备 Agent Loop、内置文件工具、命令执行工具、基础危险命令拦截和工作区路径检查。当前安全能力分散在具体工具内部，无法按用户、项目或会话配置权限，也缺少权限模式和执行前确认机制。

本阶段建立统一的五层权限防线：不可配置绕过的危险操作黑名单、内置文件工具的项目路径沙箱、可配置规则、整体权限模式，以及人在回路确认。权限拒绝作为可恢复的工具结果返回模型，不终止 Agent Loop，使模型能够调整参数、改用其他工具或选择更安全的方案。

命令子进程不纳入操作系统级文件隔离。命令工具仍在项目目录中启动，并受黑名单、规则、权限模式和人工确认保护，但不保证其无法访问项目外路径。

## 目标

- 在任何可配置策略之前拦截已知高危命令，且不允许用户通过权限模式或规则放开。
- 对内置文件工具实施项目目录边界检查，并在判断边界前解析符号链接，阻止路径逃逸。
- 支持按照实际工具名及其主要参数或路径声明精确和 glob 权限规则。
- 支持严格、默认、放行三档权限模式，并以“安全上限”语义约束具体规则。
- 对需要人工决策的调用提供本次、本会话和永久三种放行范围。
- 将永久放行保存为当前项目的本地规则，不影响其他项目或其他机器。
- 按会话、本地项目、项目共享、用户全局的顺序解析规则，越靠近当前会话的规则优先级越高。
- 在权限拒绝或用户不批准时返回可供模型理解的失败结果，并允许 Agent Loop 继续运行。

## 功能需求

### 统一权限决策

- F1：每个已注册且参数有效的工具调用都必须在实际执行前经过统一权限决策；未知工具或无效参数沿用现有失败处理，不触发权限确认。
- F2：权限决策按“危险操作黑名单 → 路径沙箱 → 权限模式与规则 → 人工确认”的顺序进行；前一层拒绝后不得进入后续层。
- F3：任何被拒绝的调用都不得产生该工具原本的文件、进程或其他副作用。

### 不可绕过的危险操作黑名单

- F4：命令工具执行前必须用内置正则集合检查完整命令，拦截删除根目录或全盘、格式化磁盘、关机重启、破坏系统权限等已知高危操作。
- F5：黑名单命中后直接拒绝，不显示放行确认；用户级、项目级、本地级、会话级规则和任何权限模式均不能覆盖该结果。
- F6：危险命令匹配不区分大小写，并覆盖项目支持的 Windows 与类 Unix 命令形式。

### 内置文件工具路径沙箱

- F7：内置读取、写入、编辑、查找和搜索工具只能访问当前项目目录中的目标。
- F8：系统必须先将目标转换为规范绝对路径并解析已有符号链接，再判断其是否位于项目根目录内；绝对路径、`..` 或符号链接导致的越界均须拒绝。
- F9：路径沙箱拒绝不可被权限规则、权限模式或人工确认覆盖。
- F10：命令子进程不受本路径沙箱隔离；命令工具只保证从项目目录启动，并继续受黑名单和其他权限层约束。

### 可配置规则

- F11：规则使用 `实际工具名(模式)` 形式，例如 `run_command(git *)`、`write_file(src/**)`；每条规则的结果只能是 `allow` 或 `deny`。
- F12：规则支持精确匹配和 glob 匹配。没有 glob 元字符的模式按完整值精确匹配，包含 glob 元字符的模式按完整目标进行 glob 匹配。
- F13：命令工具的匹配目标为去除首尾空白后的完整命令字符串；文件读写和编辑工具的匹配目标为规范化后的项目相对路径；查找和搜索工具的匹配目标为其项目相对搜索范围或路径模式。文件内容、替换文本、搜索关键词和超时值不参与权限匹配。
- F14：路径匹配统一使用 `/` 作为分隔符。路径 glob 中 `*` 匹配单个路径段，`**` 可跨目录递归匹配；命令 glob 中 `*` 可匹配任意后续字符。
- F15：规则分别来自用户全局、项目共享和项目本地三层 YAML 文件；会话放行在内存中形成第四层临时规则。
- F16：规则层级优先级为“会话临时 → 项目本地 → 项目共享 → 用户全局”。系统从高到低查找，第一个存在匹配规则的层级决定结果，低层规则不再参与。
- F17：同一层级命中多条规则时，最具体的规则优先：精确规则高于 glob；glob 中固定文本更多的规则优先；具体程度相同时 `deny` 优先。
- F18：缺失的规则文件视为空规则集；格式错误、未知结果值或非法规则语法不得被静默忽略，系统必须给出明确错误并禁止在不确定策略下执行工具。
- F19：规则文件允许用户直接声明 `allow` 或 `deny`；人工确认自动生成的会话和永久规则仅使用当前调用的精确匹配，不自动推导更宽泛的 glob。

### 权限模式

- F20：系统提供严格、默认、放行三档权限模式，并允许用户整体切换当前模式。
- F21：严格模式下，命中的 `deny` 直接拒绝；会话内已经确认的精确 `allow` 可直接执行；其他调用即使命中持久化 `allow`，首次仍须人工确认。
- F22：默认模式下，规则决定明确命中的 `allow` 或 `deny`；没有规则命中的调用交由用户确认。只读工具与副作用工具遵循相同逻辑。
- F23：放行模式下，规则解析所得 `deny` 仍然拒绝；其他调用自动允许，不要求存在 `allow` 规则。
- F24：任何权限模式都不能放开黑名单或路径沙箱拒绝的调用，也不能把规则解析所得 `deny` 改成 `allow`。

### 人在回路

- F25：需要人工决策时，系统暂停该工具调用并向用户展示工具名、用于权限匹配的目标和确认选项，但不展示写入内容、替换文本或其他不必要的敏感参数。
- F26：用户可拒绝调用，或选择“仅本次放行”“本会话放行”“永久放行”。
- F27：“仅本次放行”只允许当前工具调用，不创建规则。
- F28：“本会话放行”为当前规范化工具调用创建精确 `allow`，仅在当前 MewCode 进程的会话中有效。
- F29：“永久放行”允许当前调用，同时创建会话精确 `allow`，并将相同精确规则写入当前项目的本地权限文件；重新启动后，该规则按照项目本地层参与决策。
- F30：严格模式在新的会话中仍会对持久化 `allow` 进行首次确认；默认模式可直接采用该规则。
- F31：用户拒绝、取消确认、输入结束或当前环境无法交互时，系统必须安全地拒绝调用，不得默认放行。

### Agent Loop 集成

- F32：权限拒绝必须转换为结构化工具失败结果，包含可供模型理解的拒绝类别和简短原因，但不泄露敏感配置内容。
- F33：权限拒绝不得终止 Agent Loop；失败结果回写模型后，模型可以修改参数、换用其他工具或结束任务。
- F34：一次模型响应包含多个工具调用时，每个调用独立进行权限判断；一个调用被拒绝不应自动取消同批次中其他获准调用。
- F35：终端应清楚区分黑名单拒绝、沙箱拒绝、规则拒绝和用户拒绝，并保持现有工具状态与 Agent 进度输出可读。

## 非功能需求

- N1：权限系统必须默认安全；策略无法加载、规则无法解析、权限状态不完整或交互确认不可用时，相关工具调用必须拒绝执行。
- N2：黑名单、路径沙箱和权限判断必须发生在副作用产生之前，文件路径应在尽可能接近实际操作的时点完成最终校验。
- N3：同一工具调用、规则集合、权限模式和会话状态必须产生确定且可重复的权限结果。
- N4：路径规范化和匹配遵循当前操作系统的文件系统大小写语义；命令规则匹配保持大小写敏感，危险命令黑名单保持大小写不敏感。
- N5：权限判断不得依赖网络服务，也不得为单次决策启动额外模型请求。
- N6：永久放行写入必须以防止半写文件的方式完成；已有有效规则不得因新增一条放行而丢失或被重复写入。
- N7：项目本地权限文件不得被默认提交到版本库；项目共享权限文件可以随项目分发。
- N8：会话规则只能保存在当前进程内，退出后不得残留或自动提升为持久化权限。
- N9：多个工具同时需要确认时，终端确认必须串行展示，避免提示交错或将用户输入应用到错误调用。
- N10：用户取消确认或中断 Agent 运行时，不得启动尚未获准的工具；现有取消和返回 REPL 的能力不得退化。
- N11：权限配置错误、确认组件错误或权限拒绝不得导致 REPL、Agent Loop 或整个进程崩溃。
- N12：权限事件、错误信息和终端提示不得输出文件内容、替换文本、环境变量值、API Key 或完整权限配置。
- N13：权限检查带来的非交互式处理开销应保持为本地内存与文件操作量级，不应显著影响正常工具调度。
- N14：现有六个内置工具、Anthropic 与 OpenAI Provider、普通 Agent Loop、Plan Mode、流式事件和工具调度行为必须保持兼容。
- N15：实现继续支持 Python 3.11 及以上版本，并兼容项目当前支持的 Windows 与类 Unix 环境。
- N16：自动化测试不得调用真实模型 API，不得执行真实危险命令，也不得读写测试工作区之外的真实用户文件。
- N17：黑名单规则不得出现在用户可修改的权限配置中；新增或调整黑名单必须通过程序版本更新完成。

## 不做的事情

- 不限制或过滤网络请求、域名、端口、协议或下载内容。
- 不增加 CPU、内存、磁盘、进程数量、工具调用次数或执行时长等资源配额；沿用现有命令超时机制。
- 不建立审计日志、权限决策历史、合规报表或远程事件上报。
- 不为命令子进程提供操作系统、容器或虚拟机级文件系统隔离。
- 不通过解析 shell 语法来保证命令中的每个路径都位于项目内；命令字符串路径分析不作为安全边界。
- 不实现进程降权、系统用户切换、操作系统访问控制列表或平台特定安全令牌。
- 不提供已执行副作用的事务、快照、撤销或自动回滚。
- 不实现基于用户身份、团队角色、组织策略或远程策略服务的访问控制。
- 不支持正则表达式形式的可配置权限规则；可配置规则仅支持精确和 glob 匹配，正则只用于不可配置的危险命令黑名单。
- 不提供独立的权限规则图形化编辑器；项目共享和用户全局规则由用户编辑 YAML，人工确认只自动维护会话与项目本地放行。
- 不在人工确认中自动生成宽泛 glob，也不提供“永久允许所有相似命令”的智能推断。
- 不对权限配置进行加密、签名、远程同步或跨设备同步。
- 不改变现有 Agent Loop 的迭代上限、Provider 协议、工具输出截断或任务恢复语义。
- 不承诺防御能够同时修改符号链接或文件系统结构的敌对本地进程；本阶段采用执行前解析符号链接并检查项目边界的路径防护。

## 验收标准

- AC1：已注册且参数有效的工具调用在实际执行前产生权限决定；未知工具或参数错误直接返回原有失败结果，不弹出权限确认，也不产生副作用。
- AC2：在放行模式且所有配置层都存在匹配 `allow` 时，删除根目录、格式化磁盘、关机重启或破坏系统权限的命令仍被黑名单拒绝，且不显示放行选项、不启动进程。
- AC3：危险命令使用大小写变体或项目支持的 Windows、类 Unix 形式时仍能被对应黑名单规则拦截。
- AC4：内置文件工具能够正常读取、写入、编辑、查找和搜索项目内目标。
- AC5：内置文件工具收到指向项目外的绝对路径或通过 `..` 越界的路径时拒绝执行，并且规则、放行模式和人工确认均不能覆盖。
- AC6：项目内符号链接最终指向项目外时，读取、写入、编辑、查找或搜索操作被拒绝，项目外内容不被读取或修改。
- AC7：黑名单或路径沙箱拒绝后，不进入规则放行或人工确认流程，终端能显示对应拒绝类别。
- AC8：`run_command(git status)` 能精确匹配相同命令而不匹配其他命令；`run_command(git *)` 能匹配符合模式的完整命令。
- AC9：文件规则使用规范化项目相对路径进行匹配；Windows 与类 Unix 路径输入规范化后能得到符合各自平台语义的一致结果。
- AC10：路径规则中的 `*` 不跨越目录层级，`**` 可以匹配递归子目录；命令规则中的 `*` 可以匹配包含空格的命令余部。
- AC11：改变写入内容、编辑替换文本、搜索关键词或命令超时但保持权限目标不变时，仍命中同一条权限规则。
- AC12：同一调用分别命中用户全局、项目共享、项目本地和会话规则时，按照“会话 → 项目本地 → 项目共享 → 用户全局”选择首个有匹配项的层级。
- AC13：同层规则冲突时，精确规则覆盖 glob，固定文本更多的 glob 覆盖更宽泛的 glob，具体程度相同的冲突由 `deny` 获胜。
- AC14：权限规则只接受实际注册工具名、合法模式以及 `allow` 或 `deny`；非法规则产生清晰配置错误，且相关工具不会在策略不确定时执行。
- AC15：权限文件均不存在时，系统按空规则集运行；单独缺少某一层文件不会影响其他有效层。
- AC16：严格模式遇到持久化 `allow` 时仍进行首次确认；选择本会话放行后，相同规范化调用在当前会话不再询问，新会话中再次首次询问。
- AC17：严格模式遇到解析所得 `deny` 时直接拒绝，不提供放行确认。
- AC18：默认模式分别对命中 `allow`、命中 `deny` 和未命中规则的调用执行直接放行、直接拒绝和人工确认；该行为同样适用于只读工具。
- AC19：放行模式自动允许没有命中规则或命中 `allow` 的调用，但仍拒绝解析所得 `deny`、黑名单命令和沙箱越界路径。
- AC20：选择“仅本次放行”后当前调用执行成功，相同调用再次出现时仍重新进入权限决策，且没有新增会话或持久化规则。
- AC21：选择“本会话放行”后，相同工具与规范化目标在当前会话直接执行；参数目标不同的调用仍独立判断，重新启动后临时放行消失。
- AC22：选择“永久放行”后当前调用获得执行权限、当前会话中的相同调用不再询问，并在项目本地权限文件中新增一条不重复的精确 `allow`。
- AC23：永久放行不会修改用户全局或项目共享规则，也不会丢失项目本地文件中的其他有效规则；项目本地权限文件默认被版本控制忽略。
- AC24：严格模式重新启动后仍对永久规则进行首次确认；默认模式重新启动后可以直接采用该项目本地规则。
- AC25：用户拒绝、取消、输入结束或在非交互环境中触发确认时，调用以拒绝结束，且工具没有启动。
- AC26：同一批次有多个调用需要确认时，提示逐个显示，每个用户选择只作用于对应调用。
- AC27：权限拒绝以结构化工具失败结果回写模型，结果包含黑名单、沙箱、规则或用户拒绝类别及简短原因。
- AC28：模型收到权限拒绝结果后，Agent Loop 继续下一迭代，并能通过修改参数、选择其他工具或给出最终回答完成任务。
- AC29：同批次一个工具被拒绝时，其他通过权限检查的工具仍按现有调度规则执行，回写顺序继续符合原始工具调用顺序。
- AC30：终端能区分权限确认、允许、黑名单拒绝、沙箱拒绝、规则拒绝和用户拒绝，且不显示文件内容、替换文本、API Key 或完整配置。
- AC31：确认期间按下取消键时，尚未获准的工具不启动，Agent 取消流程仍能返回可继续使用的 REPL。
- AC32：损坏权限 YAML、无法安全完成永久规则写入或权限组件异常时，系统给出可理解错误、拒绝相关调用，并且 REPL 与进程不崩溃。
- AC33：全部权限测试可在无网络、无真实模型 API、无真实危险命令且不访问测试工作区外真实用户文件的环境中完成。
- AC34：现有六个内置工具、双 Provider、Agent Loop、Plan Mode、流式事件、取消和工具调度测试均保持通过。
- AC35：项目在 Python 3.11 及以上受支持环境中通过构建和完整测试，且本阶段没有新增网络限制、资源配额或审计日志行为。

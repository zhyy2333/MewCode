# MewCode Plan Mode Finalization Fix Spec

## 背景

当前 Plan Mode 能正确进入只读工具循环，但在兼容接口默认开启思考模式时，配置中的 `thinking: false` 只会导致请求省略思考参数，而不一定真正关闭思考。模型可能把整个输出额度消耗在不可见思考内容上，没有生成最终计划正文；系统又只依据“没有工具调用”判断完成，因而会显示任务完成并保存空计划。

同时，系统没有区分自然结束、工具调用结束和输出额度耗尽，也没有在启用思考并调用工具时保存供应商要求回传的内部延续信息。这会造成重复调查、错误完成和计划丢失。

## 目标

- 让思考配置准确表达自动、开启和关闭三种语义，并兼容现有布尔配置。
- 识别输出额度耗尽和空响应，禁止将其误判为正常完成。
- 在启用思考的工具循环中保留协议要求的内部延续信息，但不向用户展示隐藏思考。
- 将 Plan Mode 分为有界只读调查和无工具最终输出两个阶段，确保成功运行一定产生可见、可保存的计划。
- 保持普通任务、计划执行和现有终端输出层级行为兼容。

## 功能需求

- F1：思考配置支持 `auto`、`enabled`、`disabled` 三种状态。旧值 `true` 等价于 `enabled`，旧值 `false` 等价于 `disabled`，未填写等价于 `auto`。
- F2：请求必须按照所选状态表达思考意图；`auto` 使用供应商默认行为，`enabled` 明确开启，`disabled` 明确关闭。供应商不支持所选状态时必须返回明确错误，不得静默改变用户选择。
- F3：模型响应必须携带归一化结束原因，至少区分自然结束、工具调用、输出额度耗尽和供应商异常。
- F4：输出额度耗尽不得标记为正常完成；普通任务和计划执行应以明确停止原因结束，且不得提交当前不完整响应。
- F5：思考模式产生工具调用时，系统必须把供应商要求的内部延续信息原样回传到同一轮后续请求，同时不得把该信息作为文本事件、终端输出或普通会话正文暴露。
- F6：Plan Mode 最多执行 6 轮只读调查。调查提前结束或达到上限后，都必须进入一次不开放任何工具的最终计划输出阶段。
- F7：最终计划输出阶段使用独立的 8192 Token 上限，只允许输出计划正文，不允许继续调用工具。
- F8：只有非空且自然结束的最终计划才能保存。空正文、输出额度耗尽、流错误或取消都不得创建或覆盖待执行计划，并必须给出可观察的停止原因。
- F9：Plan Mode 的只读工具边界保持不变；调查阶段仍只允许读文件、查找文件和搜索代码。

## 非功能需求

- N1：原生 Anthropic、DeepSeek Anthropic 兼容接口和 OpenAI 接口使用同一套上层完成语义。
- N2：隐藏思考内容不得出现在 Agent 公共文本事件、REPL、错误信息或普通日志中。
- N3：现有未提交的 REPL 输出层级改动必须保留，修复不得覆盖或回滚它们。
- N4：测试不得访问真实网络、读取真实 API Key 或执行危险命令。
- N5：普通无工具对话和现有多轮工具 Agent 行为不得退化。

## 不做的事

- 不增加权限系统、交互式工具确认或上下文压缩。
- 不在本次修复中开放用户自定义调查轮数和最终输出 Token 上限。
- 不在终端显示或持久化可读的模型思维链。
- 不修改 `/do` 的计划审批交互模型。
- 不重构与本缺陷无关的 REPL 视觉层级功能。

## 验收标准

- AC1：旧布尔值和新三态值均能加载，并准确映射为自动、开启或关闭；未填写配置保持供应商默认行为。
- AC2：DeepSeek 兼容接口在 `disabled` 状态下收到明确关闭参数，而不是省略参数。
- AC3：达到输出 Token 上限且没有正文的响应不会显示 `completed`，也不会保存空计划。
- AC4：启用思考的工具循环能在后续请求中收到完整内部延续信息，但终端和公共文本事件中不存在隐藏思考内容。
- AC5：Plan Mode 调查最多执行 6 轮，随后恰好执行一次无工具最终输出调用。
- AC6：模型提前结束调查时仍进入无工具最终输出调用，并输出、保存非空计划。
- AC7：最终输出使用 8192 Token 上限；若仍为空、截断、出错或取消，待执行计划保持原状并显示对应停止原因。
- AC8：Plan Mode 调查阶段只暴露三个只读工具，最终输出阶段不暴露任何工具。
- AC9：Anthropic、DeepSeek 兼容接口和 OpenAI 的自然结束、工具结束及输出上限脚本得到等价的 Agent 停止语义。
- AC10：现有测试与新增端到端 Plan Mode 场景全部通过，且没有真实网络请求和异步任务泄漏。

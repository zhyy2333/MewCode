# 子 Agent Worktree 隔离 Spec

## 背景

MewCode 已支持定义式与 Fork 式子 Agent 并行运行，并隔离各任务的消息、权限、缓存和运行状态，但所有任务仍共享主 Agent 的工作目录。多个具有写入能力的子 Agent 同时修改文件时，可能覆盖彼此或主 Agent 的未完成改动，也无法清楚识别每个任务独立产生的文件和提交。

本阶段为选择 Worktree 隔离的定义式子 Agent 提供独立工作目录和独立临时分支。各目录共享同一 Git 版本库，但文件状态互不影响。未选择隔离的角色保持现有共享目录行为，Fork 式子 Agent 也继续共享主工作目录。

## 目标

- 角色可通过可选隔离声明请求 Worktree；未声明时保持共享目录，兼容现有角色。
- 每个隔离任务独占一个基于任务创建时已提交版本建立的工作目录和临时分支。
- 提供安全、可恢复的创建、进入、退出和删除生命周期，不依赖进程级工作目录切换。
- 在隔离目录中初始化运行所需的本地配置、Git Hooks、大型依赖链接及明确声明的忽略文件。
- 所有文件与进程操作显式使用任务工作目录；路径相关缓存按规范化绝对路径隔离。
- 隔离任务从自身工作目录重新加载项目级指令、配置和记忆，同时继续共享用户级指令与长期记忆。
- 任务结束时自动清理无风险目录；存在未提交修改或未远端保存提交时保留现场并拒绝删除。
- 定期清理已过期的托管目录，同时通过多层校验避免误删非托管目录、活动目录或包含未保存工作的目录。

## 功能需求

### 隔离声明与任务分配

- F1: 定义式角色可声明 `shared` 或 `worktree` 隔离；未声明时默认为 `shared`。未知值使该角色定义无效，现有未声明角色保持兼容。
- F2: Worktree 隔离只适用于定义式子 Agent。Fork 式子 Agent 始终使用主工作目录，委派工具的参数结构不因本功能发生变化。
- F3: 每个 Worktree 隔离任务独占一个工作目录和一个临时分支，不与其他活动任务复用；系统根据不可预测的任务身份生成逻辑名称。
- F4: 新 Worktree 以任务创建时主工作目录的当前提交为基线，不复制主工作目录中的未提交修改。
- F5: 所有 Worktree 都位于主仓库内部的专用托管区域；该区域必须被 Git 忽略，不能进入正常版本控制。

### 名称与路径安全

- F6: Worktree 逻辑名称只允许小写 ASCII 字母、数字、点、下划线、连字符和正斜杠；正斜杠用于有限嵌套。
- F7: 名称总长度为 1–96 个字符，每段长度为 1–32 个字符；每段必须以字母或数字开头，拒绝空段、`.`、`..`、绝对路径、反斜杠、盘符、UNC 前缀、控制字符及其他字符。
- F8: 名称转换成路径后必须仍严格位于托管区域内。解析过程不得跟随把路径引向托管区域之外的符号链接、目录联接或其他重解析点。
- F9: 所有名称和目标路径必须在创建目录、调用 Git 或删除资源之前完成验证；验证失败不得产生部分目录、分支或管理记录。
- F10: 并发请求不得通过大小写差异、路径别名或同名竞争占用同一位置。

### Worktree 生命周期

- F11: 创建新环境时，系统从规定基线建立临时分支和 Worktree，并在环境初始化全部成功后才将其标记为可进入状态。
- F12: 创建过程中任一步骤失败时，只回滚本次调用新建且仍能证明归属的资源，不修改调用前已经存在的目录或分支。
- F13: 当目标目录已经存在时，创建操作进入快速恢复路径：只读取文件系统，不调用 Git、不修改目录，也不重新执行初始化。
- F14: 快速恢复必须验证管理标记、Worktree 指针、仓库身份、逻辑名称、临时分支和就绪状态相互一致；任何缺失、损坏或不匹配都必须拒绝复用。
- F15: 进入操作产生绑定到该 Worktree 的任务执行上下文，并返回规范化绝对路径、临时分支和隔离身份；不得改变进程级当前目录。
- F16: 退出操作结束任务对该 Worktree 的活动占用，并检查文件变更、提交和远端可达状态；任务成功、失败或取消都执行相同的保护检查。
- F17: 没有未提交修改，且所有相对创建基线新增的提交都能从至少一个本地远端跟踪引用到达时，正常退出可以自动删除 Worktree 和临时分支。
- F18: 存在已跟踪修改、未跟踪且未忽略的文件或远端不可达的新提交时，正常退出必须保留 Worktree，并报告路径、分支和保留原因。没有配置远端时，任何新增提交都视为尚未推送。
- F19: 显式删除默认执行与退出相同的变更保护。调用方可明确要求强制删除，但任务退出和后台清理永远不得使用强制删除。
- F20: 强制删除前仍须通过完整的名称、路径、仓库归属和管理标记校验；强制只覆盖变更保护，不能覆盖目标归属保护。
- F21: 重复退出、重复清理以及删除已不存在的已知资源必须返回确定结果，不得误操作名称相近的其他 Worktree 或分支。
- F22: Worktree 正被任务使用、正在创建、恢复、退出或删除时，其他冲突生命周期操作必须等待或安全失败，不能破坏状态。

### 环境初始化

- F23: 项目可通过声明式规则配置初始化操作，并获得一组安全默认规则。配置只允许声明复制本地文件、建立大型依赖目录链接、配置 Git Hooks，以及补齐明确列出的忽略文件或目录。
- F24: 系统不得扫描并自动复制所有被 Git 忽略的内容；密钥、缓存、构建产物或其他未声明内容不得因被忽略而自动进入 Worktree。
- F25: 每条初始化规则都明确标记为必需或可选。必需规则失败会使新建流程失败并触发安全回滚；可选规则失败只产生有界诊断。
- F26: 初始化源和目标必须经过规范路径、仓库边界、链接目标及冲突检查。复制或链接不得覆盖 Worktree 中已有的不同内容。
- F27: 本地配置和明确声明的忽略内容从主工作目录复制到 Worktree 中对应位置，并保持运行所需的相对目录结构。
- F28: 大型依赖目录从主工作目录链接到 Worktree；类 Unix 系统使用符号链接，Windows 使用安全可用的目录链接机制。链接失败时不得静默退化为完整复制，而是按该规则的必需性处理。
- F29: Worktree 使用项目规定的 Git Hooks，但配置不得改变主工作目录、其他 Worktree、仓库共享配置或用户全局 Git 配置。
- F30: 就绪标记只能在 Worktree 创建、全部必需初始化和隔离配置均成功后写入；缺少完整就绪标记的既有目录不能快速恢复。
- F31: 快速恢复不重新复制、修复或覆盖环境内容；需要修复的环境必须先由上层明确处置，不能在恢复路径中隐式改变现场。

### 子 Agent 运行时接入

- F32: 选择 Worktree 隔离的任务只能在其环境进入就绪状态后启动模型或工具；创建失败必须在首次模型请求前收敛为明确任务失败。
- F33: 隔离任务的工作区文件工具、命令、Hook、Skill 及其他工作区相关操作都必须接收该 Worktree 的显式绝对工作目录，不得通过切换进程级当前目录实现隔离。
- F34: 隔离上下文必须向子 Agent 明确说明当前 Worktree 的绝对路径、临时分支和操作边界，避免其把主工作目录当成任务目录。
- F35: 文件内容观察、系统提示词、项目指令、项目配置和记忆等路径相关缓存必须使用规范化绝对来源路径作为键。进入或退出 Worktree 时不依赖全局清缓存来维持正确性。
- F36: 相同相对路径位于主工作目录和不同 Worktree 时必须形成不同缓存项；相同用户级文件的相同绝对路径可以安全共享缓存项。
- F37: 隔离任务从 Worktree 重新加载项目级指令、项目配置和项目记忆；用户级指令与用户级长期记忆继续使用共享来源。
- F38: 任务记录和最终结果必须包含安全、有界的 Worktree 状态摘要。目录被保留时，用户和上层协调逻辑能够获得其路径、分支及保留原因。

### 后台过期清理

- F39: 应用启动时执行一次过期扫描，之后在进程存活期间每小时扫描一次；扫描不得阻塞无关的 Agent 请求。
- F40: 只有已结束、没有活动占用且至少连续 24 小时未使用的托管 Worktree 才能进入删除候选集。
- F41: 后台清理必须依次通过三层过滤：
  1. 目标位于托管区域内，名称合法，管理标记与 Worktree 指针共同证明其属于当前仓库；
  2. 目标不属于活动任务或进行中的生命周期操作，并且已达到过期时间；
  3. 目标没有未提交修改，且全部新增提交均可从至少一个远端跟踪引用到达。
- F42: 任一过滤无法确认、状态读取失败或检查结果矛盾时，后台清理必须保留目录并记录有界诊断。
- F43: 后台清理不得跟随候选路径中的符号链接或目录联接，不得使用强制删除，也不得删除无法证明与候选 Worktree 精确对应的分支。
- F44: 单个候选清理失败不得中止本轮其他候选的检查，也不得影响主 Agent 或正在运行的子 Agent。

### 本地 Worktree 管理

- F45: 系统提供 `/worktrees` 本地命令，列出当前仓库中可安全识别的托管 Worktree，并显示有界的逻辑名称、状态、绝对路径、临时分支、最后使用时间和保护原因；不得把任务内部消息或敏感配置暴露给模型或终端。
- F46: 系统提供 `/worktree delete <逻辑名称> [--force]` 本地命令。默认删除遵守完整变更保护，只有用户在本次命令中显式给出 `--force` 时才覆盖变更保护；未知名称、非法名称、归属校验失败及重复删除均返回确定结果。该命令不注册为模型工具。

## 非功能需求

### 隔离与并发

- N1: 任何生命周期或子 Agent 操作都不得改变进程级当前目录；主 Agent、多个子 Agent 和后台清理并发运行时，进程当前目录始终保持不变。
- N2: 不同 Worktree 的工作区对象、工具实例、项目上下文和路径缓存不得共享可变的目录状态。
- N3: 同一仓库内冲突的创建、进入、退出、删除和清理操作必须串行化；互不冲突的 Worktree 以及不同仓库之间不应被全局锁无谓阻塞。
- N4: 生命周期状态必须单向且确定。一个环境不能同时被标记为活动和可清理，也不能在一次操作中被重复删除或重复回滚。
- N5: 主工作目录中的未提交文件、当前分支、暂存区和运行中工具不得因 Worktree 的创建、使用或清理而改变。

### 性能与资源边界

- N6: 快速恢复路径必须执行零次 Git 命令和零次文件系统写入，其工作量只与固定数量的管理元数据有关，不扫描整个 Worktree。
- N7: 创建、状态检查和清理不得自动执行网络访问或远端抓取；提交是否已推送只依据本地现有的远端跟踪引用判断。不确定时保留目录。
- N8: 不得通过复制大型依赖目录实现隔离；依赖链接应使新 Worktree 的额外磁盘开销主要来自实际检出文件和任务自身变更。
- N9: 初始化配置最多包含 256 条规则；单次复制最多处理 4,096 个文件、单个文件不超过 16 MiB、复制总量不超过 64 MiB。超过限制按必需或可选规则的失败语义处理。
- N10: 单轮后台扫描最多检查 256 个候选；更多候选留待后续轮次，避免长时间占用文件系统和 Git。
- N11: 后台扫描和非冲突生命周期操作不得阻塞主 Agent 的模型请求或无关工具调用；单个候选卡住或失败不能延迟整轮退出。
- N12: 路径缓存不得因进入或退出 Worktree 整体失效；同一绝对来源的不可变内容可以复用，不同绝对来源不得因相对路径相同而误命中。

### 安全

- N13: 所有 Git 和辅助进程都使用结构化参数启动，不经过 shell 拼接，并显式接收工作目录、超时和受控环境。
- N14: 来自模型、角色、项目配置、管理标记和文件系统的名称与路径均视为不可信输入；规范化、边界验证和归属验证不能被任何单一来源绕过。
- N15: 管理标记本身不足以授权复用或删除；必须同时验证规范路径、Worktree 指针、仓库身份和预期分支。
- N16: 删除操作不得使用通配符、未解析环境变量、相对根路径或递归扫描结果直接构造目标；最终删除目标必须是已重新验证的单个绝对路径。
- N17: 在实际删除前必须重新检查占用锁、管理归属和变更保护，降低检查后被替换、链接重定向或任务重新进入造成的竞态风险。
- N18: 复制规则不得跟随源路径中的符号链接逃出主工作目录；依赖链接的源必须是主工作目录内已存在且类型匹配的目标。
- N19: 初始化目标、托管区域及其父级如果出现非预期符号链接、目录联接或重解析点，相关操作必须安全失败。
- N20: 强制删除必须由调用方逐次明确提出，不能成为会话默认值、项目配置默认值或失败重试策略，也不能被后台清理继承。
- N21: Git 凭据、环境变量、文件内容、Hook 内容和未经处理的命令输出不得写入管理标记或用户可见诊断。错误信息只保留定位问题所需的有界摘要。
- N22: 远端跟踪信息缺失、陈旧、损坏或读取失败只能导致保守保留，不能被解释为已经推送。

### 可靠性与故障恢复

- N23: 进程中断可能留下未完成目录，但未写入完整就绪状态的目录永远不能被快速恢复或交给子 Agent 使用。
- N24: 创建失败、初始化失败、Git 失败、链接失败、任务取消和应用退出不得损坏主仓库，也不得删除调用前已存在的资源。
- N25: 生命周期操作必须可重复调用；超时或调用方失去响应后，重试能够获得确定状态，而不是产生第二个分支或第二个 Worktree。
- N26: 清理时遇到占用文件、Git 锁、只读权限或平台链接限制，应保留现场并输出诊断，不进行权限放宽、强制解锁或破坏性重试。
- N27: 应用正常退出时不必等待保留中的 Worktree 被处理完；活动任务按现有子 Agent 关闭规则收敛，Worktree 再按变更保护决定清理或保留。
- N28: 被保留目录必须在后续任务状态查询和诊断中可定位；应用重启后即使进程内任务记录消失，托管标记仍足以让安全扫描识别候选，但不足以绕过其他过滤。

### 兼容性

- N29: 未声明隔离的现有角色、共享目录子 Agent、Fork 式子 Agent、主 Agent 和普通单任务工作流保持现有行为。
- N30: Worktree 功能不得改变 Agent 委派工具的名称、说明、参数结构或 Fork 请求的缓存前缀。
- N31: 非 Git 工作区、Git 不可用、仓库状态不支持 Worktree 或创建基线不可解析时，只有请求 Worktree 隔离的任务在首次模型调用前明确失败；共享模式仍可使用。
- N32: 功能应在 MewCode 支持的 Windows、macOS 和 Linux 环境保持一致的安全语义；平台不支持某种链接能力时按初始化规则失败处理，而不是降低隔离或保护要求。
- N33: 现有权限、Hook、Skill、上下文压缩、自动记忆、MCP、任务通知和 Token 统计行为保持兼容；工作目录变化只能影响明确依赖项目路径的内容。
- N34: 本功能不要求用户修改现有角色；只有选择 Worktree 隔离的角色才承担 Git 仓库和初始化配置前置条件。

### 可测试性与可观测性

- N35: 时钟、Git 执行、文件系统边界、链接创建、任务占用和后台扫描均应支持可控测试替身；自动清理测试不得真实等待 24 小时或一小时。
- N36: 自动化测试必须使用临时仓库和本地远端，不依赖网络、用户全局 Git 配置或开发机已有 Worktree。
- N37: 必须能注入创建、初始化、进入、退出和删除各阶段的失败，验证只回滚本次拥有的资源并保留无法确认安全的现场。
- N38: 并发测试必须覆盖同名创建、任务退出与清理竞争、删除前路径替换、活动任务与过期扫描并行，以及不同 Worktree 同相对路径的缓存隔离。
- N39: 可观测状态至少区分新建、就绪、活动、已保留、正在删除和已删除，并提供有界、无敏感信息的失败原因。
- N40: 现有完整回归测试在共享模式下必须保持通过；新增端到端测试必须证明主 Agent 与两个隔离子 Agent 可以同时修改各自目录而互不覆盖。

## 不做的事

- 不实现 Worktree 之间或 Worktree 与主分支之间的自动合并、变基、拣选、冲突解决或变更回放；上层仍通过 Git 合并策略决定如何接收成果。
- 不自动提交、暂存、推送或抓取代码，也不自动创建远端分支、Pull Request 或其他远端对象。
- 不把主工作目录中的未提交修改复制、暂存或重放到新 Worktree；隔离任务只从已提交基线开始。
- 不实现跨 Worktree 的实时文件同步、代码广播、共享补丁或写入一致性协议。
- 不实现多 Agent 团队编排、任务依赖图、负载调度、Agent 间通信、结果投票或并行任务的自动汇总。
- 不为 Fork 式子 Agent、主 Agent 或未声明隔离的定义式子 Agent 创建 Worktree。
- 不改变 Agent 委派工具协议，也不允许模型指定目录名、分支名、基线提交、清理期限或强制删除选项。
- 不把 Worktree 当作操作系统安全沙箱。它隔离 Git 工作目录和按任务绑定的工作区操作，但不阻止获得相应命令权限的进程故意使用绝对路径访问工作区之外的文件。
- 不引入容器、虚拟机、挂载命名空间、文件系统快照或复制整个仓库的隔离方式。
- 不自动扫描、复制或备份全部 Git 忽略内容；未在初始化规则中声明的密钥、缓存、依赖和构建产物不参与初始化。
- 不在依赖链接失败时自动完整复制大型目录，也不自动运行包管理器安装依赖、构建项目或执行迁移。
- 不对 Git Submodule、Git LFS、稀疏检出或第三方工作区管理器增加专用同步逻辑；它们只遵循 Git 和项目现有行为。
- 不清理托管区域之外的 Worktree、普通目录、用户手工创建的分支或无法证明由 MewCode 管理的资源。
- 不让后台清理执行强制删除、权限放宽、锁文件强拆、自动提交或自动推送。
- 不保证强制删除后的未提交修改或未推送提交可以恢复；调用方明确强制后承担数据丢失后果。
- 不把初始化生成的忽略文件、依赖链接或运行缓存视为需要自动提交的项目变更。
- 不实现跨仓库共享同一个任务 Worktree，也不把一个 Worktree 同时分配给多个子 Agent。
- 不在本阶段新增面向模型的 Worktree 管理工具；创建、进入、退出和清理由子 Agent 运行时及上层生命周期调用。

## 验收标准

### 隔离声明、名称与分配

- AC1: 分别加载未声明隔离、声明 `shared`、声明 `worktree` 和声明未知值的角色；前三者按预期生效，未声明角色保持共享目录，未知值角色被拒绝。（覆盖 F1、N29、N34）
- AC2: 分别发起共享定义式、Worktree 定义式和 Fork 式任务；只有 Worktree 定义式任务创建隔离目录，Agent 工具 schema 和 Fork 首次请求缓存前缀保持不变。（覆盖 F2、N30）
- AC3: 同时启动两个 Worktree 任务，观察它们获得不同的不可预测任务身份、不同目录和不同临时分支；主工作目录中的未提交修改没有出现在任一 Worktree。（覆盖 F3–F4、N5）
- AC4: 创建 Worktree 后运行 Git 状态检查，观察托管区域位于主仓库内部但不作为未跟踪或可提交内容出现。（覆盖 F5）
- AC5: 对合法单段名称、含正斜杠的合法嵌套名称及长度边界执行验证，观察其被接受；对大写字母、空段、`.`、`..`、前导斜杠、反斜杠、盘符、UNC、控制字符、超长段和超长总名称逐一验证，观察全部被拒绝。（覆盖 F6–F7）
- AC6: 使用路径别名、大小写碰撞、指向区域外的链接父级和并发同名请求，观察它们在目录或 Git 状态改变前被拒绝或安全串行，最终最多存在一个合法目标。（覆盖 F8–F10、N14、N19）

### 生命周期与变更保护

- AC7: 从一个已提交基线创建环境，观察临时分支、Worktree、必需初始化和就绪状态按顺序完成；在各阶段注入失败，观察只移除本次创建的资源，调用前资源保持不变。（覆盖 F11–F12、N24、N37）
- AC8: 对一个完整的既有环境再次执行创建，记录到零次 Git 调用和零次文件系统变更；分别损坏管理标记、Worktree 指针、仓库身份、名称、分支和就绪状态，观察每种情况均拒绝恢复且不尝试修复。（覆盖 F13–F14、N6）
- AC9: 进入 Worktree 前后及两个任务并发运行期间检查进程当前目录，观察其始终不变；进入结果包含规范化绝对路径、临时分支和隔离身份。（覆盖 F15、N1）
- AC10: 让任务分别成功、失败和取消，观察三种终态都释放活动占用并执行同样的变更与提交保护检查。（覆盖 F16）
- AC11: 分别退出无变更任务和只有已推送新提交的任务，观察 Worktree 与精确对应的临时分支被删除；整个过程不执行网络访问或远端抓取。（覆盖 F17、N7）
- AC12: 分别制造已跟踪修改、未跟踪且未忽略的文件、未推送提交、无远端的新提交和远端状态读取失败，观察 Worktree 均被保留，并报告路径、分支和准确原因。（覆盖 F18、N22）
- AC13: 对受保护 Worktree 执行普通删除时观察拒绝；逐次明确强制后允许删除。随后伪造路径或管理标记再次强制，观察仍被拒绝。自动退出与后台清理从不强制删除。（覆盖 F19–F20、N16、N20）
- AC14: 对同一环境重复退出、重复删除以及删除已经不存在的已知资源，观察结果确定且不影响名称相近的目录或分支。（覆盖 F21、N25）
- AC15: 让创建、进入、退出、显式删除和后台清理竞争同一目标，观察冲突操作被安全等待或拒绝，环境状态始终唯一；同时操作不同 Worktree 时可以独立推进。（覆盖 F22、N3–N4）

### 环境初始化

- AC16: 使用安全默认配置创建环境，观察本地配置和 Git Hooks 得到处理；增加显式复制、链接和忽略内容规则后对应内容出现。仅新增一个未声明的忽略文件时，该文件不会被自动复制。（覆盖 F23–F24）
- AC17: 分别让必需规则和可选规则的源缺失或操作失败；前者使新建失败并安全回滚，后者保留可用环境并产生有界诊断。（覆盖 F25）
- AC18: 使用区域外源路径、区域外目标、源链接逃逸、类型不匹配、目标冲突、超过规则数、文件数、单文件大小和复制总量的配置，观察系统拒绝覆盖或越界，并按规则必需性处理。（覆盖 F26、N9、N18）
- AC19: 声明本地配置和被忽略的运行必需内容后创建环境，观察内容按原相对结构出现在 Worktree，且主工作目录内容未被修改。（覆盖 F27）
- AC20: 在类 Unix 和 Windows 测试环境分别初始化大型依赖目录，观察生成平台适用的目录链接而不是完整副本；让链接能力不可用时，观察系统按规则失败且不回退复制。（覆盖 F28、N8、N32）
- AC21: 在 Worktree 中运行 Git Hook，观察项目规定的 Hook 生效；检查主工作目录、另一 Worktree、仓库共享设置和用户全局设置，观察均未被该任务改写。（覆盖 F29）
- AC22: 在每个初始化阶段中断创建，观察不完整环境没有就绪状态且无法快速恢复；对完整环境走快速恢复，观察既有配置、链接和忽略内容没有被修复、覆盖或重建。（覆盖 F30–F31、N23）

### 子 Agent 运行时与缓存

- AC23: 分别让 Worktree 创建成功和失败，记录 Provider 调用；成功任务只在环境就绪后开始请求，失败任务在零次模型请求时进入明确失败终态。（覆盖 F32、N31）
- AC24: 捕获隔离任务的文件工具、命令、Hook、Skill 和其他工作区相关执行，观察每次都显式接收同一个 Worktree 绝对路径；并发任务得到各自路径，进程当前目录不变。（覆盖 F33、N1–N2）
- AC25: 捕获隔离子 Agent 的系统上下文，观察其中明确给出当前 Worktree 绝对路径、临时分支和操作边界，不把主工作目录描述为当前工作区。（覆盖 F34）
- AC26: 在主工作目录和两个 Worktree 的相同相对路径写入不同内容，依次读取项目指令、系统提示来源、项目记忆和普通文件，观察各自命中不同的绝对路径缓存；相同用户级来源可以复用。（覆盖 F35–F36、N12）
- AC27: 让 Worktree 中的项目指令、项目配置或项目记忆与主工作目录版本不同，观察隔离任务读取 Worktree 版本；用户级指令和用户级长期记忆仍与主 Agent 一致。（覆盖 F37）
- AC28: 让任务分别自动清理和因多种保护原因被保留，观察任务查询和最终结果显示有界状态摘要；保留时包含可定位路径、分支和原因，且状态能区分就绪、活动、保留、删除中和已删除。（覆盖 F38、N28、N39）

### 后台清理与安全

- AC29: 使用可控时钟启动应用并推进多个扫描周期，观察启动时扫描一次、每小时扫描一次；单轮最多检查 256 个候选，额外候选留到后续轮次，主 Agent 请求不被扫描阻塞。（覆盖 F39、N10–N11、N35）
- AC30: 构造活动、已结束未满 24 小时、已结束恰好 24 小时和超过 24 小时的环境，观察只有无占用且达到期限的环境进入删除候选。（覆盖 F40）
- AC31: 对路径归属、活动状态、过期时间、工作区变更和提交远端可达性组合测试，观察候选只有在三层过滤全部通过时才被删除。（覆盖 F41）
- AC32: 让标记读取、Git 状态、远端跟踪引用、占用状态和时间信息分别失败或互相矛盾，观察系统保留目录并记录有界诊断。（覆盖 F42、N22、N26）
- AC33: 使用包含链接或目录联接的候选、指向错误分支的 Worktree、被其他 Worktree 使用的分支和需要强制才能删除的目录，观察后台清理全部保留且不跟随链接。（覆盖 F43、N15–N20）
- AC34: 让首个候选检查超时或删除失败，观察其被保留，后续候选仍继续检查；运行中的主 Agent 和其他子 Agent 不受影响。（覆盖 F44、N11、N26）

### 可靠性、兼容性与安全输出

- AC35: 记录所有 Git 与辅助进程启动，观察参数未经 shell 拼接、工作目录明确、环境受控、超时有效，并且生命周期未执行隐式网络操作。（覆盖 N7、N13）
- AC36: 超过初始化规则和后台候选的各项资源限制，观察处理在边界处停止或延期，不产生失控复制、长时间全盘扫描或部分就绪环境。（覆盖 N9–N10）
- AC37: 在路径、标记、配置、Git、Hook 和命令错误中放入模拟密钥及超长内容，观察管理标记和用户诊断不包含密钥或原始内容，只显示有界摘要。（覆盖 N21）
- AC38: 在创建和删除的每个阶段模拟进程中断后重试，观察不完整环境不被使用、不产生第二套资源、不删除已有现场，并能由后续安全扫描保守处理。（覆盖 N23–N28）
- AC39: 使用可控时钟、临时仓库、本地裸远端和故障注入器运行并发与竞态测试，全程不依赖网络、用户 Git 配置或真实等待。（覆盖 N35–N38）
- AC40: 在非 Git 工作区、Git 不可用和不支持 Worktree 的仓库运行共享任务与隔离任务，观察共享任务行为不变、隔离任务独立失败；现有 Agent、权限、Hook、Skill、上下文、记忆、MCP、通知和用量回归测试保持通过。（覆盖 N29–N34、N40）

### 端到端场景

- AC41: 主 Agent 保持一份未提交修改，同时启动两个 Worktree 子 Agent；两个子 Agent 修改相同相对路径并各自产生不同结果。观察主目录和两个 Worktree 的三个文件状态互不覆盖，工具和缓存均绑定到各自绝对路径。
- AC42: 一个隔离任务无变更结束后自动清理；另一个产生未提交修改后结束并被保留。用户根据任务状态找到保留目录，提交并推送到本地测试远端后再次删除，观察保护解除且只清理目标资源。
- AC43: 应用异常中断留下一个完整但过期的托管 Worktree 和一个伪造目录；重启扫描时，前者只有在闲置、无变更且提交远端可达后被清理，伪造目录始终保留并产生安全诊断。

### 本地 Worktree 管理

- AC44: 创建可清理、受保护、活动和伪造环境后执行 `/worktrees`，观察只列出可证明归属的托管环境，状态与保护原因准确且输出有界；模型工具列表保持不变。（覆盖 F45）
- AC45: 对干净、含修改、含未推送提交、未知、非法和伪造环境执行本地删除命令，观察默认只删除干净目标；逐次显式 `--force` 只能覆盖真实托管目标的变更保护，不能覆盖归属或活动保护。（覆盖 F46）

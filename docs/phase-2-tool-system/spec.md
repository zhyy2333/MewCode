# MewCode 工具系统 Spec

## 背景
MewCode 当前已经具备终端 REPL、多轮对话、Anthropic Claude 与 OpenAI 双 provider、流式文本输出和 YAML 配置能力，但仍是纯聊天机器人：模型只能生成文字，不能观察或改变工作区，也不能执行命令。

本阶段要把 MewCode 从纯对话升级为具备一次工具执行能力的 Agent。用户提问后，模型可以基于供应商 tool-calling 能力选择一个工具并生成参数；MewCode 负责解析流式工具调用、执行本地工具、把结构化结果回灌进对话历史，再让模型基于结果生成最终回复。

本阶段仍不实现自动循环 Agent Loop。每轮用户提问最多执行一次工具调用；工具结果回灌后允许模型生成一次最终回答。如果最终回答阶段再次请求工具，系统不再执行，而是给出清晰提示并结束本轮。

## 目标
- 提供统一工具抽象，让每个工具都有名称、描述、参数 Schema 和执行行为。
- 提供工具注册中心，集中登记工具、按名称查找工具，并能转换成 Anthropic 与 OpenAI API 可识别的工具定义。
- 首批内置六个核心工具：读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容。
- 所有文件工具只允许访问当前工作区内路径；越界路径返回结构化错误。
- 命令工具只在当前工作区内执行，并带默认超时、最大超时和危险命令拦截。
- Provider 层支持解析 Anthropic 与 OpenAI 的流式工具调用，包括 JSON 参数碎片拼接。
- 工具执行失败时返回结构化结果给模型，而不是让 MewCode 崩溃。
- 终端只显示简短工具状态，不显示工具调用 JSON 参数碎片。
- 工具结果回灌后，模型生成一次最终回答；本章不做多工具连环调用或自动循环。

## 功能需求
- F1: 系统提供统一 Tool 抽象；每个工具都能声明名称、描述、参数 Schema，并接收结构化参数执行后返回结构化结果。
- F2: 系统提供工具注册中心；注册中心能集中登记内置工具、按名称查找工具，并导出 Anthropic 与 OpenAI API 可识别的工具定义列表。
- F3: 系统内置 `read_file(path)` 工具，用于读取工作区内文本文件内容。
- F4: 系统内置 `write_file(path, content)` 工具，用于在工作区内写入文本文件；目标路径越界时失败。
- F5: 系统内置 `edit_file(path, old_text, new_text)` 工具，用于在工作区内对文本文件做原文唯一匹配替换；匹配不到或匹配多次时失败，并返回可重试的错误说明。
- F6: 系统内置 `run_command(command, timeout_seconds?)` 工具，用于在工作区内执行命令；命令带默认超时、最大超时和危险命令拦截。
- F7: 系统内置 `find_files(pattern)` 工具，用于按 glob 模式查找工作区内文件，并返回相对路径列表。
- F8: 系统内置 `search_code(query, path?)` 工具，用于在工作区内搜索文件内容，并返回匹配文件、行号和片段。
- F9: 所有文件路径参数都必须解析到当前工作区内；绝对路径越界、`..` 越界、符号链接越界都失败并返回结构化错误。
- F10: 用户每轮提问时，系统把当前可用工具定义传给当前 provider，使模型可以选择是否调用工具。
- F11: Provider 层能从 Anthropic 流式响应中解析工具调用名称与 JSON 参数碎片，并拼接成一次完整工具调用请求。
- F12: Provider 层能从 OpenAI Responses API 流式响应中解析工具调用名称与 JSON 参数碎片，并拼接成一次完整工具调用请求。
- F13: 当模型请求调用已注册工具时，系统执行该工具，并把结构化工具结果作为后续模型输入回灌进对话历史。
- F14: 当模型请求未知工具、参数 JSON 无法解析、参数不符合 Schema、工具执行超时或工具内部失败时，系统把失败信息包装成结构化工具结果回灌给模型。
- F15: 工具结果回灌后，系统再调用模型一次生成最终回复，并把最终回复流式打印到终端。
- F16: 如果最终回复阶段模型再次请求工具，系统不执行第二个工具调用，并向用户显示本轮已达到一次工具调用上限的提示。
- F17: 如果模型没有请求工具，系统保持当前纯对话行为，直接流式打印最终文本并保存多轮历史。
- F18: 终端在工具执行前后显示简短状态信息，包括工具名称、成功或失败结果摘要；终端不显示工具调用 JSON 参数碎片。

## 非功能需求
- N1: 工具系统默认安全边界为当前工作区；任何越界文件访问或越界命令工作目录都必须被拒绝。
- N2: 工具执行错误不能导致 REPL 或进程崩溃；错误必须以结构化结果返回给模型，并以简短状态展示给用户。
- N3: 命令执行必须有默认超时和最大超时；超时后终止命令并返回结构化超时结果。
- N4: 命令工具必须拦截明显危险命令，避免删除工作区、格式化磁盘、修改系统权限或执行无限制破坏性操作。
- N5: 工具返回内容需要有大小上限；文件读取、搜索结果和命令输出过大时应截断，并明确标记已截断。
- N6: 终端输出应保持可读；工具调用过程只显示短状态，不输出完整参数 JSON、完整大文件内容或完整命令输出。
- N7: Provider 抽象应隐藏 Anthropic 与 OpenAI 工具调用协议差异；会话层只处理统一的工具调用请求和工具结果。
- N8: 没有工具调用时，原有纯对话、多轮记忆和流式文本输出行为不能退化。
- N9: 默认测试不得调用真实 LLM API 或执行真实危险命令；工具、provider 事件和命令执行都应可用 fake/mock 验证。
- N10: 本阶段实现应为后续 Agent Loop 留出扩展点，但不得在本章自动执行多轮工具循环。

## 不做的事
- 不做自动循环 Agent Loop；每轮用户提问最多执行一次工具调用。
- 不做同一轮多个工具调用的并行或串行执行。
- 不做跨轮任务规划、任务队列、后台执行或长任务恢复。
- 不做用户逐次审批工具调用的交互机制；本阶段采用固定工作区安全边界和危险命令拦截。
- 不做高级沙箱、容器隔离、权限配置文件或 per-tool 权限策略。
- 不做二进制文件解析、图片/PDF/Office 文档读取或富媒体处理。
- 不做语义代码索引、AST 级搜索、语言服务器集成或 embeddings 检索。
- 不做 patch/diff 格式编辑；`edit_file` 只做原文唯一匹配替换。
- 不做 shell 会话保持；`run_command` 每次都是独立命令执行。
- 不做工具结果持久化或跨进程恢复。

## 验收标准
- AC1: 工具注册中心能列出六个内置工具，并能按名称查找每个工具。
- AC2: 导出的工具定义能分别被转换为 Anthropic 和 OpenAI API 所需的工具列表格式。
- AC3: `read_file` 读取工作区内文本文件时返回成功结果和文件内容；读取越界路径时返回失败结果。
- AC4: `write_file` 能在工作区内写入文本内容；越界路径写入失败且不创建文件。
- AC5: `edit_file` 在原文恰好出现一次时完成替换；原文出现 0 次或多次时失败并说明原因。
- AC6: `run_command` 能在工作区内执行安全命令并返回 stdout、stderr 和退出码；命令超时时返回超时结果。
- AC7: `run_command` 对明显危险命令返回失败结果，且不执行该命令。
- AC8: `find_files` 能按 glob 模式返回工作区内相对路径列表，不返回越界路径。
- AC9: `search_code` 能返回匹配内容的文件、行号和片段；可选路径限制只搜索指定工作区子目录。
- AC10: 工具输出超过大小上限时会截断，并在结构化结果中标记已截断。
- AC11: Anthropic provider 能从流式事件中解析完整工具调用名称和 JSON 参数，并生成统一工具调用请求。
- AC12: OpenAI provider 能从 Responses API 流式事件中解析完整工具调用名称和 JSON 参数，并生成统一工具调用请求。
- AC13: 当模型请求一个已注册工具时，系统执行工具、把结果回灌给模型，并再生成一次最终回复。
- AC14: 当模型请求未知工具、坏 JSON、缺少参数、工具超时或工具失败时，系统把失败结果回灌给模型，而不是崩溃。
- AC15: 每轮用户提问最多执行一次工具调用；如果最终回复阶段再次请求工具，系统不执行第二次调用并显示上限提示。
- AC16: 没有工具调用时，原有纯聊天流式输出和多轮历史仍然可用。
- AC17: 终端显示简短工具状态，包括工具名称和成功/失败摘要；不显示 JSON 参数碎片。
- AC18: 默认测试不需要真实 Anthropic/OpenAI API key，也不会执行危险命令。

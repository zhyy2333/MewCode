## 集成与架构

- [x] **I01 — Lead 仍是唯一状态提交者。** 宿主和成员工作进程只能提交已验证事件/结果；过期的 Lead 控制代际、运行 ID 或成员运行代际不能修改成员状态、任务、邮箱或通知。（验证：并行提交有效和过期控制消息，重读团队状态、修订与 outbox。）
- [x] **I02 — 终端成员 provisioning 全成全败。** 在角色、预检、Worktree、会话、邮箱、窗格启动、宿主登记和状态发布逐点失败时，未发布成员不可投递且 journal 能安全恢复；已有成员不受影响。（验证：逐故障点创建成员、销毁服务后重启并检查花名册、注册表、资源目录和 journal。）
- [x] **I03 — 固定 argv 与安全边界生效。** Windows Terminal/tmux 命令由固定 argv 构成，不经过 shell；成员名、消息、任务、路径和秘密不能修改命令、标题或控制协议。（验证：输入 shell 元字符和秘密哨兵，捕获进程执行器参数、窗格摘要和持久文件。）
- [x] **I04 — 控制 broker 身份与重连收敛。** 每个成员同时只接受一个有效宿主；重复登记、旧连接、旧结果和控制面重启后的遗留连接被拒绝或替换，不产生双运行。（验证：用连接 fake 并发登记/断线/重连，统计有效连接和工作进程数。）
- [x] **I05 — 持久邮箱与唤醒结果独立。** 邮箱已追加并标记已投递后，即使唤醒异常或重复 flush，也不会复制消息或撤销投递；回执准确区分 `running`、`queued`、`failed`、`not_applicable`。（验证：在 append、标记投递、唤醒前后注入异常并重放相同 message ID。）
- [x] **I06 — 统一容量不泄漏。** 独立成员实际运行期间由 Lead 持有 14A 容量租约；空闲宿主不占用名额，普通子 Agent与所有成员总数始终不超过限制。（验证：用容量为 1 的 fake 同时运行普通子 Agent、终端成员和进程内成员，记录获得/释放顺序。）
- [x] **I07 — 停止、移除、审批和任务语义保留。** 对终端成员停止会取消在途工作，移除会回收宿主但保留 Worktree 成果保护；审批、任务状态和邮箱协议继续使用原有规则。（验证：运行审批成员的任务、停止、移除与恢复流程并比较 Git、审批、任务、邮箱和窗格状态。）
- [x] **I08 — CLI 隐藏模式隔离。** 宿主和成员工作模式不创建普通主会话、不取得 Lead 租约、不开放 REPL；普通 CLI、未使用团队、进程内团队启动行为不变。（验证：运行三种模式的解析/装配测试并比较会话、租约、工具和终端入口。）
- [x] **I09 — 时间和外部边界可替换。** 终端命令、子进程、连接、时钟、等待、容量、Git 和锁均由 fake 驱动；测试没有网络调用或真实长等待。（验证：运行专项测试并审查 fake 使用、总时限和网络禁用设置。）

# 上下文管理与两层压缩 Spec

## 背景

MewCode 当前在单次进程内持续累积完整对话历史，并在 Agent Loop 的每次模型请求中携带这些消息。工具结果通常占据主要 Token 空间；随着对话和工具调用增加，活动上下文会逐渐逼近模型窗口上限，最终可能导致请求失败，使长时间任务无法继续。

系统已经能够获得 Provider 返回的 Token usage，但尚未管理历史长度，也未定义模型上下文窗口。需要引入两层压缩机制：先以确定性的轻量处理限制工具结果体积，再在整体历史接近窗口上限时由 LLM 生成结构化摘要。同时保留必要原文和可重新读取的存盘记录，避免模型根据摘要臆测代码或文件细节。

## 目标

- 让 MewCode 能在有限上下文窗口内持续执行长时间、多轮、工具密集型任务。
- 优先压缩工具结果，最大程度保留用户原始意图和仍有效的原文约束。
- 通过轻量预防和重量兜底，使每次模型请求都在调用前完成上下文容量检查。
- 让被移出活动上下文的工具结果和早期对话在当前会话内仍可追溯、可重新读取。
- 支持用户主动压缩，并通过连续失败熔断避免自动摘要死循环和无效 Token 消耗。
- 在本阶段采用基于最近一次 API usage 与增量字符量的近似 Token 估算，不依赖精确 tokenizer。

## 功能需求

- F1：每个模型 Profile 支持可选的上下文窗口配置；未配置时统一按 128000 Token 处理。非法或不足以容纳正常请求的值必须在使用前给出明确错误。

- F2：系统维护当前活动上下文的近似 Token 数。获得有效 API input usage 后，以该值作为新锚点；在下一次获得实际 usage 前，只根据请求内容的增量字符量修正估算。尚无可用 usage 时，对完整请求进行字符量估算。

- F3：每次 API 请求前必须依次执行轻量预防和整体容量检查。轻量预防完成后，才判断是否需要重量压缩；摘要请求本身不得递归触发新的重量压缩。

- F4：单个工具结果超过约 8K Token 时，完整结果必须存盘，活动上下文仅保留工具标识、原始估算大小、首尾预览和可重新读取的文件路径。

- F5：同一轮模型响应产生的工具结果，在轻量处理后的活动内容合计超过约 12K Token 时，必须从尚未存盘的最大结果开始依次存盘，直到该轮保留内容不超过 12K。每个存盘结果的首尾预览合计最多约 1K Token。

- F6：存盘内容必须与原始工具结果一致；占位内容必须明确说明结果已存盘而非被删除或截断。存盘失败时不得静默丢失内容，也不得继续发起可能溢出的模型请求。

- F7：工具结果和早期对话记录存放在工作区私有且默认不参与版本控制的会话目录中。文件在当前会话期间可读取；正常退出时删除，并在下次启动时清理崩溃遗留的旧会话目录。

- F8：普通请求的自动重量压缩边界为：
  `context_window - 本次最大输出 Token - 13K`。
  轻量预防完成后，若活动请求估算达到或超过该边界，必须在调用主模型前执行重量压缩。

- F9：REPL 提供 `/compact` 命令。该命令不写入对话历史，先执行轻量预防，再强制尝试一次重量压缩，不受自动触发阈值限制。摘要请求的容量边界为：
  `context_window - 8192 - 3K`。
  没有可压缩的早期消息时，命令返回“无需压缩”，且不调用摘要模型。

- F10：重量压缩从历史尾部向前选取近期保留区，直到同时满足约 10K Token 和至少 5 条消息。切分不得拆开工具调用与对应结果等协议上必须保持完整的消息组；为保持消息组完整，可以超过近期保留目标。

- F11：近期保留区保持原文。更早的完整消息在摘要前存盘；正式摘要必须逐字保留仍然有效的用户约束，已完成、失效或被替代的早期要求可以概括，并提供早期完整记录的读取路径。

- F12：正式摘要固定包含以下章节，顺序不可变，空章节也必须写明“无”：
  1. 当前目标
  2. 仍有效的用户原始约束
  3. 关键决策及理由
  4. 已完成工作
  5. 当前代码与文件状态
  6. 未解决问题与风险
  7. 下一步行动
  8. 存盘记录索引

- F13：重量摘要复用当前活动 Profile 和 Provider，关闭全部工具，最大输出为 8192 Token。摘要 Prompt 必须明确禁止调用工具，并要求模型先输出带明确边界的分析草稿，再输出正式摘要。系统只提取并保留通过结构校验的正式摘要；分析草稿、截断响应和无效响应全部丢弃。

- F14：重量压缩成功后，以一份新的滚动摘要替换被压缩的早期活动消息；原有滚动摘要必须参与下一次摘要并被新摘要替换，活动历史中不得无限累积多份旧摘要。

- F15：每次重量压缩成功后，必须在摘要与近期原文之间加入边界消息，明确告知后续模型：摘要不等同于文件原文；需要代码、工具结果或文件细节时，应从存盘路径或原工作区重新读取，不得根据摘要补全或臆测。

- F16：摘要失败时，原活动历史和已有滚动摘要保持不变，失败计数增加。任意一次成功摘要将连续失败计数清零。

- F17：连续 3 次摘要失败后，本会话熔断自动重量压缩。熔断期间，若普通请求存在上下文溢出风险，必须在调用主模型前明确报错，不得反复自动重试。

- F18：熔断后，用户仍可执行 `/compact` 发起一次显式摘要尝试。显式尝试成功后清零失败计数并恢复自动摘要；失败则维持熔断状态。

- F19：工具结果存盘、重量压缩开始、压缩成功、无需压缩、压缩失败和熔断状态都必须向用户提供简洁、可观察的状态反馈，但分析草稿和完整存盘内容不得作为状态输出。

## 非功能需求

- N1：可靠性——任何压缩都必须是原子操作。只有存盘成功、摘要响应完整且结构校验通过后，才能替换活动历史；中途失败或取消不得留下部分压缩状态。

- N2：容量安全——系统不得仅依赖近似估算的理想准确度。所有自动和手动边界都必须保留约定的输出预算与安全余量；预计无法安全发起的请求必须在 Provider 调用前停止。

- N3：数据完整性——存盘的工具结果和早期消息必须保持原始内容及原始顺序。预览、摘要和状态提示不得覆盖或冒充完整原文。

- N4：协议完整性——压缩前后的消息序列必须继续满足各 Provider 对角色顺序、工具调用和工具结果配对的要求，不得产生孤立工具结果或缺失对应调用的历史。

- N5：确定性——给定相同历史、相同 usage 锚点和相同配置，轻量预防必须选择相同的存盘对象、预览边界和处理顺序；大小相同时使用稳定顺序决策。

- N6：向后兼容——未配置上下文窗口的现有 Profile 无需迁移即可继续工作；未触发压缩时，普通对话、Plan/Execute 模式、权限系统、内置工具、MCP 工具和 Provider 行为保持不变。

- N7：Provider 兼容——OpenAI 与 Anthropic 路径必须具有等价的容量判断、存盘、摘要、历史替换和熔断行为；Provider 未返回有效 usage 时仍可使用完整字符估算继续保护上下文。

- N8：资源控制——轻量预防不得调用 LLM。每次触发重量压缩只允许一次摘要请求，不在同一请求前置处理中循环重试；摘要请求不得携带任何工具定义。

- N9：取消安全——用户取消摘要或主流程时，进行中的 Provider 请求应被停止；未完成的摘要不得写入历史，临时文件不得被当作有效存盘记录引用。

- N10：隐私与安全——会话存盘目录不得进入版本控制；生成的文件名和路径不得受工具输出内容控制；状态和错误信息不得回显完整工具结果、完整早期历史或 Provider 内部分析草稿。

- N11：清理有界——正常退出与启动时的遗留清理不得无限等待；单个文件或目录清理失败不得阻止其余清理，并应提供不包含存盘内容的简洁警告。

- N12：可观察性——用户能够区分轻量存盘、自动重量压缩、手动重量压缩、无需压缩、压缩失败、自动熔断和恢复成功；反馈不得与模型正式回答混淆。

- N13：可测试性——自动化测试不得依赖真实 LLM、真实网络或精确 tokenizer。Token usage、摘要成功与失败、输出截断、取消、存盘错误和清理失败都必须可由本地 fake 或 mock 稳定复现。

- N14：性能——未接近阈值时，预检成本应主要与新增消息及新增工具结果大小相关；获得 usage 锚点后，不应在每次请求前重复对全部历史进行精确分词。

- N15：可维护性——轻量存盘、Token 估算、重量摘要、历史替换和熔断职责应保持清晰边界；Provider 特有消息格式不得扩散到通用压缩策略中。

## 不做的事情

- 不引入精确 tokenizer，也不承诺近似估算与任一 Provider 的计费 Token 完全一致。
- 不使用机器学习、强化学习或历史效果评分来动态选择摘要策略、阈值或保留内容。
- 不自动发现模型的真实上下文窗口，也不维护随模型版本更新的上下文窗口映射表。
- 不新增独立摘要 Profile，不自动选择更便宜或更强的摘要模型。
- 不允许 `/compact` 接受自定义摘要 Prompt 或临时改变固定摘要章节。
- 不实现跨进程对话恢复、长期记忆、历史搜索、会话同步或摘要文件导入。
- 不长期保留存盘工具结果和早期对话，也不提供归档浏览器、管理界面或手动保留策略。
- 不压缩或改写用户配置的系统指令、Skill、工具定义和当前结构化系统提示；它们只参与请求容量估算。
- 不自动把存盘文件内容重新注入上下文；模型需要细节时必须按边界消息提示显式重新读取。
- 不摘要或删除近期保留区中的原始消息，即使其使保留区超过约 10K Token。
- 不实现多轮自动摘要重试、退避重试、定时半开或后台压缩任务。
- 不改变 Provider 的缓存策略、计费统计、思考模式或普通回答的输出预算。
- 不扩展现有工具结果的数据类型能力，不新增二进制、多模态或远程对象存储归档。
- 不承诺对本地存盘内容进行加密或不可恢复的安全擦除；本阶段只提供会话隔离、版本控制排除和生命周期清理。

## 验收标准

### 配置与 Token 估算

- AC1（F1）：使用未配置上下文窗口的现有 Profile 启动并发起请求，容量计算采用 128000 Token；配置自定义窗口后采用自定义值；非法值在 Provider 调用前产生明确错误。

- AC2（F2）：首次请求没有 usage 时，对完整请求作字符量估算；Provider 随后返回已知 input usage 后，下一次预检以该值为锚，只加入新增消息、提示和工具内容的字符估算量，而不是继续累加旧估算误差。

- AC3（F3）：构造同时包含超大工具结果且整体接近窗口边界的请求，观察到系统先完成工具结果存盘，再使用轻量处理后的历史决定是否进行重量压缩，最后才调用主模型。

### 轻量预防与存盘

- AC4（F4、F6）：产生一个估算超过 8K Token 的工具结果，下一次模型请求中只出现工具标识、原始大小、最多 1K Token 的首尾预览和读取路径；路径中的文件包含完整原始结果，且占位内容明确说明结果已存盘。

- AC5（F5）：同一轮产生多个均不超过 8K、但合计超过 12K 的结果，系统按原始估算大小从大到小依次存盘，直到保留内容不超过 12K；相同大小的结果每次运行都以相同顺序处理。

- AC6（F4-F6、N4）：对包含多个工具调用及结果的消息组执行轻量处理后，消息顺序、工具调用标识和结果配对仍合法，OpenAI 与 Anthropic fake 均能接受下一次请求。

- AC7（F6、N1）：模拟工具结果存盘失败，系统不调用模型、不用截断内容替代完整结果，并返回明确错误；活动历史仍保持失败前状态。

- AC8（F7）：存盘结果在会话中可由现有读取工具取得；正常退出后会话目录被删除。模拟进程异常遗留目录后重新启动，遗留目录被清理；单个清理失败不会阻止其余目录清理。

### 重量压缩触发与保留区

- AC9（F8）：给定已知上下文窗口和普通请求最大输出预算，当估算值低于 `context_window - max_output_tokens - 13K` 时不自动摘要；达到边界时先摘要，且主模型只接收压缩后的历史。

- AC10（F9、F13）：执行 `/compact` 时，摘要请求复用当前活动 Profile，最大输出为 8192 Token，不携带任何工具定义，并按 `context_window - 8192 - 3K` 校验其容量安全。

- AC11（F9）：在尚未达到自动阈值但存在可压缩早期消息时执行 `/compact`，系统仍发起一次摘要；命令文本不出现在历史中。只有近期保留区时执行该命令，显示“无需压缩”且不调用 Provider。

- AC12（F10）：构造超过 5 条消息且近期内容不足 10K 的历史，保留区继续向前扩展至约 10K；构造超过 10K 但不足 5 条的历史，至少保留 5 条。切分点遇到工具调用组时，完整保留该组，即使因此超过目标。

- AC13（F11）：重量压缩成功后，近期保留区中的用户、助手和工具消息与压缩前逐项一致；被压缩早期区的完整原始消息可从摘要给出的存盘路径读取，顺序和内容均未改变。

### 摘要生成与历史替换

- AC14（F11-F13）：检查摘要请求，Prompt 明确包含禁止调用工具、先写有边界的分析草稿、再写正式摘要、逐字保留仍有效用户约束和不得臆测文件细节的要求；请求中包含待压缩早期消息及其存盘索引。

- AC15（F12-F13）：返回包含分析草稿和八个固定章节的响应后，活动历史只保留正式摘要，分析草稿不可在历史、状态输出或后续请求中找到；缺少章节、章节乱序、空章节未标“无”、正式摘要边界缺失或响应截断时，压缩失败。

- AC16（F11）：给定包含仍有效约束、已完成要求和已被替代要求的早期历史，合格摘要中的“仍有效的用户原始约束”保留有效约束原文，其他两类要求可在对应章节概括，并能通过存盘路径查到原文。

- AC17（F14）：完成两次重量压缩后，活动历史中只有一份最新滚动摘要；第二份摘要已吸收第一份摘要和新压缩区的信息，第一份摘要不再单独占用活动上下文。

- AC18（F15）：压缩后的历史在滚动摘要与近期原文之间包含一条边界消息，明确要求重新读取文件或存盘结果获得细节，并禁止根据摘要补全代码；后续模型请求始终携带该边界。

### 失败、熔断与恢复

- AC19（F16、N1、N9）：分别模拟 Provider 错误、输出截断、空响应、结构错误和用户取消。每种情况都不替换历史、不保留草稿、不产生有效摘要引用；除用户主动取消外，失败会增加连续失败计数。

- AC20（F17）：连续三次自动摘要失败后，第四个需要摘要的普通请求不再调用摘要模型或主模型，而是在请求前报告自动压缩已熔断及上下文风险；不需要摘要的请求仍可正常运行。

- AC21（F18）：熔断后执行 `/compact` 只发起一次显式尝试；失败时继续熔断，成功时替换历史、清零失败计数，下一次达到阈值的普通请求恢复自动摘要能力。

### 兼容性、反馈与端到端

- AC22（F19、N12）：分别触发轻量存盘、自动压缩、手动压缩、无需压缩、压缩失败、熔断和恢复，终端均显示可区分的简洁状态，且不输出完整存盘内容或分析草稿。

- AC23（N6-N7）：对等的 OpenAI 与 Anthropic fake 场景得到相同的阈值判断、存盘选择、近期保留区、摘要替换和熔断结果；未触发压缩的既有对话、Plan/Execute、权限和工具测试保持通过。

- AC24（F2、N7）：Provider 连续不返回 usage 时，系统仍能通过字符估算触发轻量和重量保护；之后重新获得有效 usage，新的实际值替换旧估算成为锚点。

- AC25（N8）：仅触发轻量预防时没有额外 LLM 请求；一次重量触发只有一次摘要请求，失败后不会在同一次预检中自动重试，且摘要请求的工具集合为空。

- AC26（N1、N4-N5）：在并发完成多个只读工具、取消发生于存盘或摘要期间、以及 Provider 返回不同消息格式的场景中，不出现部分历史替换、孤立工具结果、重复存盘引用或不稳定选择顺序。

- AC27（N10）：使用包含路径分隔符、控制字符和疑似秘密文本的工具名称及结果进行存盘，生成路径仍限制在当前会话目录内；终端状态、异常文本和文件名中不出现完整结果或疑似秘密内容。

- AC28（N11）：模拟删除拒绝、文件占用和单个遗留目录损坏，退出或启动清理在有限时间内结束，继续处理其他目录并只输出非敏感警告。

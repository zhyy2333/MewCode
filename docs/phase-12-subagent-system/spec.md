# 子 Agent 系统 Spec

## 背景

MewCode 已具备可循环调用工具的 Agent、模型 Profile、权限控制、Hook 生命周期、工具裁剪和进程内 Token 用量统计，也有独立 Skill 临时运行的基础能力。但主 Agent 目前没有一种稳定、通用的方式，把工作委派给具有独立上下文和独立运行状态的子 Agent；Hook 中的 Agent 动作也仍是占位行为。复杂任务只能继续占用主对话，容易把调查过程、工具结果和权限状态带入主上下文。

本阶段引入独立的子 Agent 系统。它与现有 Skill 系统并存，复用已经验收的 Agent Loop、Profile、权限、Hook、文件系统和模型基础设施，但不改变现有 Skill 的公开语义。

## 目标

- 主 Agent 通过一个始终可见且结构稳定的 Agent 工具委派任务，并由类型参数选择定义式或 Fork 式运行。
- 定义式子 Agent 从空白消息历史和固定角色提示开始；Fork 式子 Agent 从触发委派的父模型请求快照开始，以保留缓存前缀并继承当次可用工具能力。
- 每个子 Agent 隔离消息、会话级权限状态、文件读取缓存、运行计数和 Token 用量，同时共享模型客户端、Hook 引擎、文件系统及其他无会话状态的基础设施。
- 子 Agent 采用非交互式“跑到底”执行：模型不再请求工具时完成；权限需要人工确认时自动拒绝该次调用，并允许模型继续寻找替代方案。
- 子 Agent 可在前台短暂执行或进入后台；Fork 式始终进入后台。后台任务可被追踪，并在完成后把有界结果异步通知主 Agent，而不把子 Agent 的内部对话写入主历史。
- 工具能力经过全局禁止、角色限制和后台能力限制的多层交集，且所有子 Agent 均不得再次委派子 Agent。
- 角色定义支持项目级、用户级、内置和注入式插件来源，并按项目级高于用户级、高于内置、高于插件的顺序覆盖同名角色。

## 功能需求

### 统一委派入口

- F1: 系统只向主 Agent 注册一个用于委派的 Agent 工具；无论发现了多少角色、角色是否更新或调用哪种子 Agent，该工具的名称、说明和参数结构都保持不变。
- F2: 每次委派必须提供非空任务，并通过类型参数明确选择“定义式”或“Fork 式”。定义式还必须指定已加载的角色；Fork 式不接受角色名。
- F3: 类型、任务、角色或后台参数组合无效时，调用必须在创建任务前失败，并返回可理解的参数错误。
- F4: Agent 工具只负责创建子 Agent，不承担任务查询、结果读取或取消操作；这些能力由本地任务命令提供。
- F5: 主对话所处模式构成子 Agent 的安全上限。只读或计划模式下发起的子 Agent 不得获得写入或命令等有副作用能力，即使角色声明或权限模式允许也不例外。
- F6: 定义式子 Agent 的工具 schema 不包含 Agent 工具及其他能够再次启动模型代理的控制工具。Fork 式为保持父请求缓存前缀而保留父工具 schema，但执行层必须硬拒绝这些控制工具；任何子 Agent 都不能真正继续委派或通过间接入口形成嵌套代理。

### 角色定义与加载

- F7: 角色使用 UTF-8 Markdown 文件定义；文件由一个严格的 YAML frontmatter 和一个非空正文组成，未知字段、错误类型和无法识别的枚举值均视为定义无效。
- F8: frontmatter 必须完整声明角色名、用途说明、工具白名单、工具黑名单、模型、最大轮次和权限模式。角色名使用小写 kebab-case，用途说明为非空单行文本，两个工具列表均为无重复名称的列表。
- F9: `model` 只能是 `inherit` 或现有 Profile 名称。`inherit` 使用调用主 Agent 当前采用的 Profile；指定名称复用该 Profile 的协议、模型、地址、凭据和上下文窗口，不直接接受供应商模型 ID。
- F10: 最大轮次必须是 1 到 100 的整数。权限模式只能是现有的 `strict`、`default` 或 `allow`，并只影响该角色启动的子 Agent。
- F11: Markdown 正文作为角色的固定系统指令，在该子 Agent 的每次模型请求中持续生效，不进行任务模板替换；本次任务作为独立用户消息提供。
- F12: 系统按项目级、用户级、内置、插件级的优先顺序选择同名角色。插件级来源由启动装配注入，本阶段不负责发现或安装插件。
- F13: 高优先级定义无效时，系统记录安全诊断并回退到下一层有效的同名定义；所有层都无有效定义时，该角色不可调用。同一层出现多个有效同名定义属于目录冲突，必须拒绝该次目录装配，不能依赖扫描顺序静默选择。
- F14: 角色加载时校验白名单和黑名单中的工具名称。不存在、尚未注册或属于全局禁止集合的白名单工具会使定义无效；黑名单可包含当前存在的工具，但不能把白名单扩大。
- F15: 定义式子 Agent 的初始工具集为“当前模式允许的已注册工具、角色白名单、启动时注入的后台能力白名单”的交集，再依次移除角色黑名单和全局禁止工具。黑名单与白名单冲突时黑名单优先；空白名单产生无工具角色。
- F16: 角色目录在应用启动时形成只读快照。本阶段不监视文件变化，也不在运行中热重载角色。

### 上下文与运行时隔离

- F17: 定义式子 Agent 从空白消息历史启动。它获得 MewCode 的稳定基础规则、当前环境、项目与用户人工指令、长期记忆和角色正文，但不继承父消息、父 Hook 临时提示、父计划状态或父对话中已激活的 Skill。
- F18: Fork 式子 Agent 复用触发该委派调用的父模型请求快照，包括相同 Profile、系统提示缓存前缀、输入消息和当次工具 schema；系统在这个完整前缀之后追加新的子任务，不复制产生委派调用的尚未配对工具调用消息。
- F19: Fork 式子 Agent 的首次请求保持父工具 schema 及顺序不变，同时冻结一份实际执行策略。该策略把可执行能力限制为父请求实际工具、启动时注入的后台能力白名单和父模式安全上限的交集，并硬拒绝全局禁止工具。被策略拒绝的已展示工具调用只返回确定失败，不执行工具，也不创建嵌套任务。
- F20: 每个子 Agent 分别维护消息列表、上下文压缩状态、文件读取缓存、会话级权限授权、权限决策记录、轮次计数、取消状态和任务级 Token 用量；一个任务的变化不得被另一个任务或主 Agent 直接观察到。
- F21: 子 Agent 共享只读或并发安全的模型客户端、Profile 目录、Hook 引擎、文件系统访问层、持久权限规则快照及进程级用量账本。共享基础设施不得导致任务消息、临时 Hook 提示、文件缓存或权限授权串线。
- F22: 子 Agent 的消息和工具链不写入主对话历史、会话存储或其他子 Agent 历史。前台完成时只有有界最终结果成为 Agent 工具结果；后台完成时只通过任务记录和一次性通知返回。
- F23: 定义式子 Agent 使用角色指定的最大轮次。Fork 式使用调用者本次 Agent Run 的轮次上限作为自己的独立上限，不继承调用者已经消耗的轮次数。
- F24: 子 Agent 在模型自然结束且不再请求工具时成功完成。达到轮次或输出上限、Provider 失败、上下文失败、取消和内部错误均产生明确的非成功终态；若最后一次响应仍要求工具，不执行该批工具。
- F25: 子 Agent 使用独立权限控制状态，并读取任务创建时的用户级和项目级持久规则快照；不继承父会话临时授权。权限判断为 `ASK` 时自动拒绝该次工具调用，把拒绝原因反馈模型，并继续剩余执行；显式拒绝规则和硬安全门禁保持不可绕过。
- F26: 每个子 Agent 的模型、工具和 Hook 活动都携带任务身份及父运行关联。共享 Hook 引擎必须把匹配产生的临时提示和结果限制在来源任务内，不得由并发的主 Agent、维护请求或其他子 Agent 消费。
- F27: 每个任务独立累计输入、输出、缓存读取和缓存写入用量；相同调用同时计入现有进程级账本，但不得重复计费。Provider 未报告的字段保持未知，不以估算值伪造。

### 前台、后台与任务管理

- F28: 定义式委派默认先以前台任务运行，也可在调用时显式要求立即进入后台。Fork 式委派始终立即进入后台，调用者不能要求 Fork 式前台运行。
- F29: 显式后台任务和 Fork 任务注册成功后立即向调用者返回唯一任务 ID 与初始状态，主 Agent 无须等待子 Agent 的首次模型响应。
- F30: 默认前台的定义式任务若在 10 秒内完成，Agent 工具直接返回其有界最终结果、终态和任务级用量；主历史不包含子 Agent 的中间消息或工具结果。
- F31: 默认前台的定义式任务运行满 10 秒仍未完成时自动转入后台，立即向调用者返回任务 ID 和当前状态；转换不取消、不重启任务，也不重置上下文、权限或用量。
- F32: 用户可在定义式前台任务运行期间按 `Ctrl+B` 立即将其转入后台。`Ctrl+B` 不改变 `Ctrl+C` 的取消语义；当前没有可转换任务时必须给出简短且无副作用的提示。
- F33: 启动装配为所有子 Agent 提供固定的后台能力白名单。由于本阶段的每个子 Agent 都可能或必然进入后台，该白名单从任务启动前即限制实际可执行能力：定义式直接据此裁剪工具 schema，Fork 式通过不改变父 schema 的执行策略拒绝越界调用。前后台转换不得扩大能力或遗留后台不允许的可执行工具。
- F34: 后台任务管理器至少区分已注册、运行中、已完成、失败和已取消终态，并记录任务 ID、类型、定义式角色、父运行关联、前后台位置、创建与结束时间、有界结果或错误以及任务级用量。
- F35: `/tasks` 显示当前会话进程内任务的安全摘要，并明确区分活动任务和终态任务；列表不得输出完整内部消息、工具参数或凭据。
- F36: `/task <id>` 显示单个任务的状态、最终结果或错误及用量；任务尚未完成时只显示当前可安全观察的进度，不阻塞等待。
- F37: `/task cancel <id>` 请求取消指定的非终态任务，并在清理完成后把它标记为已取消。取消终态任务、未知任务或重复取消必须返回确定且无副作用的结果。
- F38: 后台任务完成、失败或被取消时，终端立即显示包含任务 ID 和终态的单行摘要，并把有界最终结果、错误和用量加入主 Agent 的一次性通知队列。
- F39: 一次性通知只在主 Agent 下一次真实模型请求边界注入：若主 Agent 仍在运行，则在后续迭代注入；若主 Agent 已空闲，则在下一次用户任务触发的请求中注入。通知不得被子 Agent、上下文压缩、自动记忆或其他维护请求消费。
- F40: 每条完成通知最多注入一次，不写入主对话历史或会话存储。多条待处理通知按任务完成顺序组成有界批次；未能放入当前批次的通知保留到后续主请求。
- F41: `/reset` 取消当前进程内所有非终态子 Agent，清空任务表和待注入通知，防止旧会话结果进入重置后的上下文。正常退出执行有界等待，随后取消仍未结束的任务；崩溃后不恢复任务或通知。
- F42: 后台任务达到系统并发上限时，新委派在创建模型请求前失败并说明容量已满；已经运行的任务不受影响，终态任务不占用活动并发名额。

## 非功能需求

### 缓存与性能

- N1: Agent 工具的 schema 不包含动态角色枚举、运行中任务 ID 或其他目录派生内容；同一进程内角色数量和任务状态变化不得改变主 Agent 的工具列表或该工具 schema。
- N2: Fork 首次请求必须保持父请求的 Profile、工具顺序、稳定系统提示和消息前缀逐字节一致，只在缓存前缀之后增加子任务内容。系统应创造缓存命中条件，但不得把供应商是否实际命中缓存作为正确性前提。
- N3: 定义式角色正文、任务状态和完成通知只能出现在动态上下文边界之后，不得改变 MewCode 的稳定系统提示前缀。
- N4: 产品默认最多同时运行 8 个子 Agent；容量检查和任务注册必须原子化，并发委派不能突破上限。测试可下调该上限，但产品默认值只有一个来源。
- N5: 前台转后台计时使用单调时钟，从任务成功注册后开始计算；事件循环延迟不得导致任务被取消或重复启动。
- N6: 子 Agent、任务通知和本地任务命令不得阻塞无关的主 Agent 请求。共享模型客户端或 Hook 引擎出现单任务故障时，其他任务仍可继续运行。

### 资源限制

- N7: 单个角色定义文件最大 64 KiB，每个来源最多发现 256 个候选角色，所有已选角色正文合计最大 1 MiB；超限候选按无效定义处理并产生有界诊断。
- N8: 单次委派任务文本最大 64 KiB；Agent 工具返回、任务详情和一次性通知中的单个最终结果最多保留 20,000 个字符，并明确标记截断。
- N9: 单次主请求最多注入 16 条完成通知且编码后合计不超过 64 KiB；超过任一上限时保留剩余通知，等待后续主请求，不能静默丢弃。
- N10: 任务管理器最多保留最近 128 条已经通知完毕的终态任务；超限时只淘汰最早的已完成记录。活动任务和尚未完成通知投递的终态任务不得被淘汰。
- N11: 正常关闭和 `/reset` 最多等待 5 秒让取消清理完成，随后强制结束仍未收敛的任务并记录安全诊断；关闭不能无限等待 Provider、工具或 Hook。
- N12: 角色诊断、任务错误、终端摘要和 Hook 元数据均须有长度上限。异常堆栈、完整工具参数、模型内部内容、API Key、认证头和未经处理的 Provider 响应不得进入用户可见任务记录或通知。

### 安全与隔离

- N13: 工具能力过滤采用只会收窄的交集语义，顺序变化不能使实际可执行集合扩大。Fork 为缓存保留 schema 不等于获得执行能力；全局禁止、后台能力名单与父模式安全上限是不可绕过的硬策略，角色 `allow` 权限模式也不能恢复被裁剪、策略拒绝或硬门禁拒绝的工具。
- N14: 子 Agent 创建时冻结 Profile、持久权限规则、工具视图、角色定义和后台能力名单；运行途中父权限模式、角色文件或注册表变化不得悄然改变既有任务能力。
- N15: 文件系统仍使用主进程现有的规范路径和硬安全检查。共享文件系统意味着并发任务可以观察其他任务已经提交的文件变化；本阶段不承诺事务、快照或写冲突消解。
- N16: 任务 ID 必须在当前进程内唯一且不可由简单递增序列猜测；本地命令只允许操作当前会话进程所拥有的任务。
- N17: 后台通知使用系统语义并带明确的不可信结果边界，要求主 Agent 把子 Agent 输出视为任务结果而非更高优先级指令。通知不得覆盖基础规则、人工指令或安全模式。
- N18: Hook 事件和临时提示必须按任务作用域隔离；并发完成顺序可以不同，但同一任务内的事件顺序、权限决策和工具结果顺序保持确定。

### 可靠性、兼容性与可测试性

- N19: 单个角色解析失败、子 Agent 失败、结果截断、通知延后或任务取消不得损坏主历史、会话文件、其他任务状态或进程级用量账本。
- N20: 任务必须恰好进入一个终态，完成通知最多入队一次，取消和完成竞争时由首先提交的终态获胜；后续回调不得改写结果或重复计量。
- N21: 现有普通对话、PLAN、权限、Hook、上下文压缩、自动记忆、MCP 和 Skill 的公开行为保持兼容。没有角色来源或没有运行任务时，除稳定出现的 Agent 工具和新增本地命令外，不增加模型请求、后台线程、日志文件或会话写入。
- N22: 子 Agent 内部消息、任务表和通知队列仅驻留当前进程内，不写入会话 JSONL；应用重启后不得显示或注入上次进程的任务结果。
- N23: 所有时间、并发、Provider、Hook、权限、工具和终端输入边界都应支持替换为测试实现；自动转后台、完成/取消竞争和通知消费测试不得依赖真实网络或实际等待 10 秒。
- N24: 新增公开错误和状态输出使用稳定、简洁的用户语义；内部异常在最外层收敛为任务失败或安全诊断，不把普通异常传播到 REPL 主循环。

## 不做的事情

- 不为子 Agent 创建 Git Worktree、临时仓库、文件系统快照、容器或独立工作目录；所有任务继续访问同一个工作区。
- 不实现多 Agent 团队、任务依赖图、角色间通信、投票、协商、共享黑板、自动合并或写冲突解决。
- 不允许子 Agent 再启动子 Agent，也不设计可配置嵌套深度。
- 不持久化后台任务、内部消息、权限状态、结果或通知；不支持崩溃恢复、跨进程接管或跨会话继续。
- 不实现插件安装、插件扫描、插件更新或插件生命周期；只接受启动装配显式提供的插件角色来源。
- 不热重载角色定义，不保留角色版本历史，也不为角色提供目录包、脚本或专属工具声明。
- 不新增 `haiku`、`sonnet`、`opus` 等内置模型别名或模型档位映射；需要这些名称时由用户创建同名 Profile。
- 不为子 Agent 提供交互式权限审批、异步提权队列或父 Agent 代批；所有 `ASK` 都按已确认规则自动拒绝。
- 不实现后台任务暂停、恢复、重试、优先级、定时执行、任务依赖或跨任务资源配额。
- 不把任务查询、取消或结果读取暴露为新的模型工具；主 Agent 只接收一次性完成通知，用户通过本地命令管理任务。
- 不保证供应商一定命中 Prompt Cache，也不根据缓存未命中自动重试或改变请求内容。
- 不改变现有 isolated Skill 的实现或公开行为，不把 Skill 自动迁移为角色。
- 不在本阶段启用 Hook 配置中的 Agent 动作；该动作继续保持已校验但不执行的占位语义。
- 不新增用户可编辑的后台工具白名单、并发上限或自动转后台时长配置；首期使用本 Spec 规定的产品默认值。

## 验收标准

### 委派入口与角色目录

- AC1: 分别在无角色、单角色、多角色和已有后台任务的状态下读取主 Agent 工具列表，始终只看到一个 Agent 委派工具，且其名称、说明、参数结构和工具顺序完全一致。（覆盖 F1、N1）
- AC2: 分别提交空任务、未知类型、定义式缺少角色、定义式未知角色、Fork 式携带角色和非法后台参数组合；每次都在创建任务和调用模型前得到明确参数错误，任务列表保持不变。（覆盖 F2–F4）
- AC3: 在插件、内置、用户和项目来源放置同名有效角色，观察项目版本生效；依次移除高层版本后，观察用户、内置、插件版本按顺序生效。（覆盖 F12）
- AC4: 让高优先级同名角色格式无效，观察安全诊断且低层有效版本生效；让同一层出现两个有效同名角色，观察目录装配被拒绝且不按扫描顺序选择。（覆盖 F13）
- AC5: 对未知字段、错误字段类型、非法名称、重复工具名、空正文、未知 Profile、最大轮次 0/101 和未知权限模式逐一加载，观察对应候选无效；边界值 1/100 能成功加载。（覆盖 F7–F11）
- AC6: 通过启动装配注入插件角色来源时可以发现并调用角色；未注入来源时系统不扫描任何约定插件目录，也不影响其他来源。（覆盖 F12、N21）
- AC7: 启动后修改、增加或删除角色文件，再次调用时仍使用启动快照；重启应用后才采用新目录内容。（覆盖 F16）
- AC8: 角色白名单引用未知、未注册或全局禁止工具时角色无效；黑名单包含白名单中的工具时角色仍有效，但实际运行看不到该工具；空白名单角色能够无工具运行。（覆盖 F14–F15）
- AC9: 让同一角色分别使用 `inherit` 和另一个现有 Profile，观察前者采用调用主 Agent 的 Profile，后者完整采用指定 Profile；直接填写供应商模型 ID 且无同名 Profile 时加载失败。（覆盖 F9）

### 上下文、工具和权限隔离

- AC10: 向父历史放入仅父对话可见的标记，并激活一个共享 Skill 和一次性 Hook 提示；启动定义式子 Agent 后，模型请求包含基础规则、环境、人工指令、长期记忆、角色正文和独立任务，但不包含父消息标记、父 Hook 提示、父计划状态或激活 Skill。（覆盖 F11、F17）
- AC11: 让定义式子 Agent 连续运行多轮，观察角色正文每轮持续存在、任务只作为独立用户消息出现，子 Agent 的消息与工具链没有写入主历史或会话存储。（覆盖 F11、F22）
- AC12: 组合父模式安全上限、角色白名单、角色黑名单、后台能力白名单和全局禁止名单，观察定义式最终 schema 严格等于这些限制的交集与差集；Fork schema 保持父请求不变，但对交集之外的每个调用均返回确定策略拒绝。改变过滤应用顺序不能扩大任一路径的实际可执行集合。（覆盖 F5–F6、F15、F19、F33、N13）
- AC13: 在 DEFAULT 与 PLAN 中调用同一个包含读写工具的定义式角色，观察 DEFAULT 只获得全部过滤后允许的能力，PLAN 只能获得只读能力；`allow` 权限模式也不能恢复被移除能力。（覆盖 F5、N13）
- AC14: 在定义式子 Agent 中观察 Agent 工具、`load_skill` 和其他模型代理控制入口不在 schema；在 Fork 式中这些父 schema 项仍可见，但调用只得到确定的执行策略拒绝。两条路径都不能形成第二层代理。（覆盖 F6、F19）
- AC15: 捕获产生 Fork 委派的父模型请求与 Fork 首次请求，观察两者使用相同 Profile，且系统提示、工具顺序和输入消息在追加子任务之前逐字节一致；产生委派调用的未配对助手工具消息没有进入 Fork 历史。（覆盖 F18、N2）
- AC16: 从工具受限的父运行发起 Fork，观察 Fork 首次请求逐项保留父请求中实际可见的工具 schema 与顺序；分别调用全局禁止项、非后台能力项和父模式不允许项时均得到确定策略拒绝，而交集内工具仍可正常执行。（覆盖 F19、N2、N13）
- AC17: 使用报告缓存读写量的 Provider 执行 Fork，观察系统保留了可缓存前缀并如实记录 Provider 返回值；让 Provider 报告缓存未命中，Fork 仍能正常完成且不重试。（覆盖 F18、N2）
- AC18: 并发运行两个子 Agent，分别修改消息、触发上下文压缩、读取同一文件、产生权限决策、消耗轮次并取消其中一个；观察消息、压缩档案、文件读取缓存、会话授权、决策、轮次和取消状态互不串线。（覆盖 F20）
- AC19: 让一个子 Agent 写入共享工作区并成功完成，再让另一个任务重新读取，后者能看到已提交文件变化；同时两个任务仍使用各自文件读取缓存，系统不承诺快照或冲突合并。（覆盖 F21、N15）
- AC20: 父会话存在临时允许、用户/项目持久允许和显式拒绝规则时启动子 Agent，观察它只继承持久规则快照而没有父会话允许；产生 `ASK` 时该调用自动拒绝、拒绝结果回到模型且 Agent 继续，硬拒绝始终不可绕过。（覆盖 F25）
- AC21: 并发触发主 Agent、两个子 Agent 和维护请求的 Hook，观察每个事件带正确任务与父运行关联，临时 Hook 提示只被来源运行消费，同一任务内事件顺序稳定。（覆盖 F21、F26、N18）
- AC22: 对两个任务返回不同的完整/缺失 usage 字段，观察每个任务独立显示自己的用量、进程账本只累计一次，缺失字段显示未知而非估算值。（覆盖 F20、F27）
- AC23: 分别制造自然结束、达到角色轮次上限、Fork 轮次上限、输出上限、Provider 错误、上下文错误、取消和内部异常，观察每个任务进入对应明确终态；上限轮次仍请求的最后一批工具没有执行。（覆盖 F23–F24）

### 前后台转换与任务命令

- AC24: 定义式任务在 10 秒内完成时，Agent 工具直接返回有界最终结果、成功状态和任务用量；主历史只增加正常的委派工具调用与结果，不包含子 Agent 中间过程。（覆盖 F28、F30）
- AC25: 使用可控时钟让定义式前台任务到达 10 秒，观察 Agent 工具返回任务 ID、任务原地转为后台且继续运行；模型调用次数、消息、权限状态和用量没有归零或重复。（覆盖 F31、N5）
- AC26: 显式要求定义式后台运行以及发起 Fork，观察两者在等待首次模型响应前就返回唯一任务 ID；Fork 始终标记为后台，不能改为前台。（覆盖 F28–F29）
- AC27: 定义式前台任务运行时按 `Ctrl+B`，观察它立即原地转后台并返回任务 ID；无前台子任务时按键只显示提示。按 `Ctrl+C` 仍取消当前前台运行而不是转后台。（覆盖 F32）
- AC28: 创建、运行、完成、失败和取消任务，观察管理器记录任务类型、角色、父运行、前后台位置、时间、状态、有界结果或错误及用量，并且每个任务 ID 在进程内唯一且不可简单预测。（覆盖 F34、N16）
- AC29: 同时保持 8 个活动子 Agent 后并发提交更多委派，观察所有超额调用在模型请求前明确失败，活动数从未超过 8；任一任务进入终态后可再成功创建一个任务。（覆盖 F42、N4）
- AC30: 执行 `/tasks`，观察活动与终态任务清楚分组，只显示安全摘要；执行 `/task <id>`，完成任务显示有界结果和用量，活动任务立即显示非阻塞进度；未知 ID 返回确定错误。（覆盖 F35–F36）
- AC31: 对活动、终态、未知和已经请求取消的任务执行 `/task cancel <id>`，观察只有活动任务发生一次取消；让完成与取消同时竞争，任务只进入一个终态且结果、通知和用量不重复。（覆盖 F37、N20）
- AC32: 完成超过 128 个已投递通知的终态任务，观察只保留最近 128 条；活动任务和尚未投递通知的终态任务始终可查，淘汰不影响待通知结果。（覆盖 N10）

### 通知、生命周期与边界

- AC33: 后台任务完成、失败和取消时，终端各显示一条含任务 ID 与终态的摘要；对应有界结果、错误和用量各自只进入通知队列一次。（覆盖 F38、N20）
- AC34: 后台任务在主 Agent 仍运行时完成，观察通知进入其下一次模型迭代；主 Agent 已空闲时完成，观察通知进入下一次用户任务的首个请求。（覆盖 F39）
- AC35: 在待通知期间先运行子 Agent、上下文压缩、自动记忆和其他维护模型请求，观察它们均未消费通知；只有主 Agent 的真实任务请求能够消费。（覆盖 F39）
- AC36: 同时完成 20 个任务并让结果总量超过 64 KiB，观察首个主请求最多按完成顺序收到 16 条且不超过 64 KiB，其余通知保留并在后续请求继续投递；每条最多投递一次。（覆盖 F40、N9）
- AC37: 检查投递前后主消息历史和会话 JSONL，观察通知没有被写入；重启应用后任务表与通知队列为空，旧结果不再显示或注入。（覆盖 F40、N22）
- AC38: 在有活动任务和待通知结果时执行 `/reset`，观察任务被取消、任务表和队列清空，重置后的主请求收不到旧结果；正常退出时清理在 5 秒内结束，失去响应的任务被强制收敛。（覆盖 F41、N11）
- AC39: 分别超过角色文件大小、每来源候选数、角色正文总量、任务输入大小和单结果大小，观察系统按规定拒绝或截断并明确标记，且诊断和错误不泄漏凭据、完整参数、内部模型内容或原始 Provider 响应。（覆盖 N7–N8、N12）
- AC40: 把包含伪系统指令的子 Agent 结果送入通知，观察通知具有明确的不可信任务结果边界，不能覆盖基础规则、人工指令、权限模式或工具上限。（覆盖 N17）
- AC41: 让单个子 Agent 的 Provider、Hook、工具和通知处理分别失败，观察该任务安全失败或延后通知，主 REPL、主历史、会话文件、其他任务和用量账本仍可继续使用。（覆盖 N6、N19、N24）
- AC42: 在没有角色、没有任务且没有通知的状态运行现有普通对话、PLAN、权限、Hook、上下文、记忆、MCP 和 Skill 回归套件，观察既有行为保持不变，也没有额外模型请求、后台线程、日志或会话写入。（覆盖 N21）

### 端到端场景

- AC43: 定义一个只读审查角色，让主 Agent 委派一个 10 秒内完成的任务；观察角色从空白历史按限定工具执行，主 Agent 只收到最终工具结果并据此继续回答。（覆盖 F1–F17、F20–F30）
- AC44: 定义一个长时任务，让其自动或通过 `Ctrl+B` 转入后台；主 Agent 先完成当前回复，子 Agent 随后结束并通知，下一次主请求收到一次结果，用户能够通过任务命令查看状态、用量并取消另一活动任务。（覆盖 F28–F42）
- AC45: 从包含较长历史和稳定工具集的主 Agent 发起 Fork；观察调用立即返回后台任务 ID，Fork 首次请求保留父缓存前缀但拥有独立运行状态，完成结果只通过一次性通知回到主 Agent，且不能再次委派。（覆盖 F6、F18–F27、F38–F40）

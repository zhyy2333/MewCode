# MewCode 结构化系统提示与提示缓存 Spec

## 背景

MewCode 已具备双 Provider、Agent Loop、工具调用和 Plan Mode，但模型请求目前缺少统一的系统指令层：任务模式指令以普通用户消息注入，工具说明较简略，环境上下文没有独立语义边界，Token 用量也没有反映缓存写入与命中情况。

这使固定规则、动态上下文和真实用户输入混在一起，既削弱指令遵守率，也破坏稳定前缀，无法可靠利用或验证供应商的提示缓存能力。

本阶段建立统一的提示组织规则，再由 Anthropic 与 OpenAI 分别映射到各自协议。范围聚焦于系统提示、动态补充指令、模式注入、工具规则与缓存观测；不提前实现项目指令发现、Skill 激活、长期记忆生成、真实 MCP 或自动化评估。

## 目标

- 建立按优先级拼装的模块化系统提示，固定顺序为：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出、环境信息。
- 在固定模块之后依次支持自定义指令、已激活 Skill 和长期记忆等可选内容。
- 将稳定指令与工具定义放入可复用的缓存前缀，将环境信息、对话历史和轮次动态指令放在缓存边界之后。
- 通过系统提示与具体工具描述双重表达关键工具规则，提高“优先使用专用工具”和“编辑前先读取目标内容”等规则的遵守率。
- 使用带明确特殊标签的系统级补充指令承载运行时规则，使其不作为用户请求进入历史或诱导模型直接回复。
- 对会话模式指令按 Agent 模型调用次数注入：第 1、5、9、13、17 次使用完整版本，其余调用使用精简版本。
- 统一采集两种 Provider 的缓存创建、缓存命中和常规 Token 用量，并向现有事件及终端统计层提供可观察结果。
- 准备一组典型人工对比场景，用于定性评估改造前后的指令遵守、工具选择和输出质量。
- 保持现有双 Provider、Agent Loop、Plan Mode、工具安全边界和普通多轮对话兼容。

## 功能需求

- F1：每次模型请求都必须包含统一组织的系统提示，其固定模块严格按以下优先级排列：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出、环境信息。
- F2：系统支持自定义指令、已激活 Skill 和长期记忆三个可选模块；存在内容时依次排在环境信息之后，缺失或空白时完全省略，不留下空标题或占位文本。
- F3：各模块之间使用一个空行分隔；相同输入必须生成内容与顺序完全一致的提示前缀，避免无意义变化造成缓存失效。
- F4：身份至文本输出七个固定模块属于稳定指令；环境信息、可选模块、模式补充指令和对话历史属于动态内容，必须位于稳定缓存边界之后。
- F5：环境信息至少包含当前工作区、操作系统、当前日期和运行所用 Shell；不得包含环境变量值、API Key 或其他凭据。
- F6：Anthropic 与 OpenAI 必须接收语义等价的系统指令、动态补充和工具规则，同时使用符合各自协议的系统级表示与缓存能力。
- F7：运行时补充指令统一包裹在 `<system-reminder>...</system-reminder>` 标签中，以系统级语义传递；不得伪装成用户请求，不得进入持久化的用户对话历史，也不得诱导模型单独回复该提醒。
- F8：动态补充指令必须追加在稳定缓存边界之后；环境、模式或可选模块变化时，不得改变此前稳定指令和工具定义的内容与顺序。
- F9：启用需要动态提示的会话模式时，同一次 Agent Run 的第 1、5、9、13、17 次模型调用注入完整模式指令，其余调用注入精简提醒；每次新的 Agent Run 从第 1 次重新计数。
- F10：完整模式指令必须说明当前模式的目标、允许动作、禁止动作、完成条件和输出要求；精简提醒只保留模式名称、关键边界与当前应继续执行的目标。
- F11：Plan Mode 的完整与精简提示都必须明确禁止修改工作区；其实际可用工具集合仍只包含只读工具，不能仅依赖提示约束。
- F12：全局工具规则必须要求优先使用已有专用工具；只有专用工具无法完成任务时，才使用通用命令执行能力替代文件读取、搜索或编辑操作。
- F13：任何对已有文件的编辑都必须先读取相关内容；新建文件不要求执行无意义的预读取。该规则同时出现在全局工具规则和相关文件工具描述中。
- F14：工具定义必须采用确定性顺序和稳定描述；相关工具描述必须重复表达“优先使用专用工具”和“编辑已有文件前先读取”的关键约束。
- F15：在工具集合与稳定指令未变化时，连续模型调用和后续用户轮次必须保持相同的可缓存前缀；动态环境、历史和运行时提醒只能追加在该前缀之后。
- F16：系统必须解析并统一报告每次模型响应的常规输入、输出、总 Token，以及供应商提供的缓存读取和缓存写入 Token；缺失字段明确标记为不可用，不得伪造为零。
- F17：缓存用量既要支持单次模型调用观察，也要支持同一次 Agent Run 内累计，并沿用现有 Token 事件与终端统计路径展示。
- F18：系统必须能通过模拟响应验证两种 Provider 的缓存字段映射；同时提供真实 API 手工验证说明，用重复请求确认稳定前缀是否产生缓存写入或命中。
- F19：项目必须准备固定的人工对比场景，至少覆盖：先读后改、专用搜索工具优先于 Shell、Plan Mode 不执行写操作、动态环境变化不破坏稳定前缀、普通问答不把系统提醒当成用户问题回复。
- F20：调用方可以直接提供三个可选模块的内容并参与排序与渲染；本阶段不负责发现、加载、激活、生成或持久化这些内容。
- F21：普通多轮对话、直接执行、Plan Mode、计划执行和多轮工具循环必须继续工作；系统补充消息不得作为普通用户消息出现在对话历史或待执行计划正文中。

## 非功能需求

- N1：系统提示的模块定义、优先级和启用条件必须集中管理；新增模块时不应复制整套拼装逻辑或分别修改两个 Provider。
- N2：Provider 适配层只处理协议格式、缓存标记和用量字段差异，不得各自维护不同版本的业务指令。
- N3：在输入不变时，稳定提示与工具定义必须保持字节级确定性，包括模块顺序、工具顺序、空行和换行格式。
- N4：动态内容变化不得移动、改写或重新排序稳定前缀；不能通过把全部内容都标记为缓存内容来伪装满足缓存要求。
- N5：不得为了达到供应商的最小缓存长度而向正常提示填充无意义文本。真实缓存验证可以使用足够长的测试内容，并必须记录模型、请求条件和实际返回字段。
- N6：缓存命中属于供应商实际结果，系统不得承诺每次请求必然命中。模型不支持缓存、内容不足最低长度或供应商未返回相关字段时，应显示“不可用”或零实际命中，而不是报告成功。
- N7：缓存统计扩展不得改变现有输入、输出和总 Token 的含义；未知值在累计过程中继续保持未知语义，不得因累加而变成虚构数据。
- N8：提示拼装和统计解析不得阻塞流式文本展示；收到文本增量后仍应立即向事件消费者转发。
- N9：系统提示、工具描述、运行时提醒、事件和终端输出均不得泄露 API Key、环境变量值、隐藏推理内容或供应商内部对象。
- N10：动态内容中的标签、换行或类似指令文本不得破坏外层系统提醒边界，也不得改变固定模块的排序。
- N11：工具规则应简洁、明确且避免无意义重复；双重强化只用于关键约束，不在每个模块中反复堆叠相同文本。
- N12：Anthropic 与 OpenAI 在相同上层输入下应产生语义等价的指令层级和统一缓存统计；供应商特有字段必须封装在 Provider 边界内。
- N13：现有配置文件无需增加必填项；未提供三个可选模块时，程序应以默认系统提示正常运行。
- N14：保持 Python 3.11 及以上兼容，并保证现有 Agent Loop、Plan Mode、工具调度、流式事件和 REPL 测试不退化。
- N15：自动测试不得访问真实网络、读取真实 API Key 或产生真实缓存费用；真实 API 缓存验证作为有明确步骤的人工检查单独执行。
- N16：人工对比场景必须固定输入、记录所用 Provider 与模型，并同时观察工具调用轨迹和最终回答，避免只凭主观印象下结论。
- N17：本阶段形成的提示组织能力必须允许未来接入项目指令、Skill、长期记忆和 MCP 工具，而无需改变现有固定模块的优先级语义。

## 不做的事

- 不扫描或加载 `AGENTS.md`、项目配置、用户目录配置等项目级或用户级指令文件。
- 不发现、安装、选择或激活 Skill；只接受调用方已经提供的 Skill 内容。
- 不生成、检索、更新、压缩或持久化长期记忆；只接受调用方已经提供的记忆内容。
- 不接入真实 MCP Server，不发现远程工具，也不改变现有六个内置工具的执行能力。
- 不建立自动化质量评估、打分模型、回归基准平台或统计显著性分析；本阶段只准备固定的人工对比场景。
- 不实现会话历史压缩、摘要、裁剪、上下文窗口管理或跨进程会话持久化。
- 不新增权限系统、工具调用确认、沙箱机制或副作用回滚能力。
- 不改变 Plan Mode 现有的只读工具集合、调查轮数、最终输出阶段和 `/plan`、`/do` 交互方式。
- 不改变 Agent Loop 的迭代上限、工具调度、取消、错误停止或未知工具处理规则。
- 不新增会话模式，也不提供模式提醒间隔的用户配置；本阶段固定采用第 1、5、9、13、17 次完整注入。
- 不实现缓存预热、缓存保活、TTL 配置、缓存清除或供应商缓存状态管理。
- 不计算实际费用、折扣金额或节省比例；只报告 API 明确返回的 Token 分类。
- 不保证不支持提示缓存的模型或兼容接口产生缓存命中，也不通过自动切换模型或 Provider 来获得命中。
- 不持久化或上传缓存统计、人工评估结果和提示内容。
- 不新增 GUI、Web 控制台或遥测后台；缓存信息沿用现有事件与终端展示渠道。
- 不重写工具执行实现；除关键规则强化所需的工具描述调整外，工具参数、结果格式和安全分类保持不变。

## 验收标准

- AC1：给定全部固定模块，生成结果中的标题严格按“身份→系统约束→任务模式→动作执行→工具使用→语气风格→文本输出→环境信息”出现，模块之间恰好保留一个空行。
- AC2：分别不给可选内容、只提供一个可选模块和同时提供三个可选模块时，输出只包含实际提供的内容；三个模块同时存在时严格按“自定义指令→已激活 Skill→长期记忆”排列在环境信息之后。
- AC3：使用完全相同的输入重复生成提示和工具定义，得到字节完全一致的结果；工具注册来源顺序变化时，对外缓存前缀仍保持确定性顺序。
- AC4：捕获两次模型请求并只改变工作区、日期、历史或运行时提醒时，身份至文本输出七个固定模块及工具定义保持不变，变化内容只出现在缓存边界之后。
- AC5：环境信息能够观察到工作区、操作系统、日期和 Shell；使用包含敏感环境变量的测试进程运行时，提示、事件和终端输出中均不存在该变量值或 API Key。
- AC6：对同一组模块、环境、模式和工具分别生成 Anthropic 与 OpenAI 请求时，两者包含等价的稳定指令、动态补充和工具规则，并使用各自支持的系统级表示。
- AC7：运行时补充内容只出现于 `<system-reminder>...</system-reminder>` 中；模型请求历史检查显示它不具有用户消息语义，会话保存结果中也不存在一条对应的用户消息。
- AC8：补充内容中含换行、相似标签或指令文本时，外层提醒边界仍然完整，固定模块顺序和缓存边界不受影响。
- AC9：一次达到 20 次模型调用的 Agent Run 中，第 1、5、9、13、17 次收到完整模式指令，其余次数收到精简提醒；启动新的 Agent Run 后计数重新从第 1 次开始。
- AC10：检查完整模式提醒时，可以观察到模式目标、允许动作、禁止动作、完成条件和输出要求；精简提醒只保留模式名称、关键边界和继续执行目标。
- AC11：在 Plan Mode 的完整提醒和精简提醒中都能观察到只读边界；该模式下模型请求只公开读取、查找和搜索工具，写入、编辑和命令工具不可调用。
- AC12：面对“查找文件后修改已有内容”的固定场景，模型首先使用专用查找、搜索和读取工具，而不是通过通用命令完成等价操作；只有模拟专用工具无法完成时才允许回退到命令工具。
- AC13：面对修改已有文件的场景，第一次编辑调用之前存在针对相关内容的读取调用；面对新建文件场景，不要求对不存在的目标执行预读取。
- AC14：检查全局工具规则和相关工具描述，两处都明确包含专用工具优先与编辑前读取约束；工具参数、结果格式和安全分类保持不变。
- AC15：同一对话的连续模型调用与后续用户轮次在固定模块和工具集合不变时共享完全相同的稳定前缀，新增历史只追加在该前缀之后。
- AC16：模拟 Anthropic 返回缓存创建与缓存读取字段时，统一 Token 统计准确反映两类数值；模拟 OpenAI 返回缓存读取以及可用的缓存写入字段时，得到相同上层语义。
- AC17：供应商缺少某项缓存字段时，该项显示为不可用；供应商明确返回零时保留为零，两种情况不会混淆。
- AC18：连续两次模型响应包含不同缓存统计时，每次 Token 事件显示本次值，Agent 停止事件和终端统计显示正确累计值，同时原有输入、输出和总 Token 数保持正确。
- AC19：使用 fake/mock 捕获请求时，Anthropic 与 OpenAI 的缓存标记或缓存前缀位置符合各自协议，并且全部自动测试不发起真实网络请求。
- AC20：按照人工验证说明，使用支持缓存且稳定前缀达到最低长度的真实模型连续发送相同前缀请求，可以从 API usage 中观察到实际缓存写入或后续缓存读取；若条件不满足，记录为不具备验证条件，不得伪报命中。
- AC21：真实缓存验证中只改变稳定边界之后的用户消息或动态补充，再次请求仍能观察到稳定前缀的缓存读取；改变固定指令或工具定义后，统计能够反映前缀失效或重新写入。
- AC22：人工对比文档至少提供五个固定场景：先读后改、专用搜索优先、Plan Mode 禁止写入、动态内容不破坏稳定前缀、系统提醒不被当作用户问题回复；每个场景都包含固定输入、观察点和通过条件。
- AC23：调用方分别传入自定义指令、Skill 内容和长期记忆时，它们参与正确排序与渲染；不传入时程序不会自行扫描项目文件、激活 Skill 或创建记忆。
- AC24：普通问答仍能流式输出并进入多轮历史；直接执行、Plan Mode、`/do` 和多轮工具调用仍按原有停止及安全规则工作。
- AC25：文本增量到达后立即产生现有文本事件，提示拼装和缓存统计解析不会等待整个 Agent Run 结束后才展示文本。
- AC26：模拟缓存字段、动态提醒、标签边界或 Provider 错误时，REPL 不崩溃，不泄露供应商内部对象、隐藏推理或测试凭据。
- AC27：项目现有测试与本阶段新增测试全部通过，并能在 Python 3.11 及以上环境中运行。
- AC28：代码库检查未出现项目指令加载、自动 Skill 激活、长期记忆持久化、真实 MCP 接入、缓存预热、费用计算或自动评分系统。

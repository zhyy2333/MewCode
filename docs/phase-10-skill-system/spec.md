# Skill 系统 Spec

## 背景

MewCode 已具备结构化系统提示、动态环境上下文、工具注册与权限控制、Agent Loop、会话持久化、上下文压缩，以及统一的斜杠命令系统，但可复用的 AI 工作流仍主要依赖用户重复输入提示词或硬编码命令。

本阶段引入 Skill 系统：将可复用操作封装为带严格元信息的 Markdown 能力包。系统启动时只向 Agent 展示 Skill 名称和一句说明，需要使用时再加载完整 SOP 和专属工具，以减少常驻上下文并提高工具选择准确率。

Skill 支持项目级、用户级和内置三级来源，支持共享当前对话与临时独立对话两种执行方式，并与现有提示构建、模式限制、权限、命令、会话及热更新机制协同工作。

## 目标

- 让用户和 Agent 能复用标准化 AI 操作，避免重复编写同类提示词。
- 启动时仅披露 Skill 目录信息，按需加载完整 SOP 和专属工具。
- 通过 Skill 工具白名单收窄模型可见能力，同时不削弱既有系统安全限制。
- 支持多个共享 Skill 同时激活，并在每轮提示重建时稳定保留其完整指令。
- 支持一次性临时独立运行，只向主对话回流最终结果，不污染主历史。
- 让有效 Skill 自动成为斜杠命令，并在输入边界自动应用文件变更。
- 支持可恢复的激活状态，以及原子清空对话和 Skill 状态的 `/reset`。
- 提供 `commit`、`review`、`test` 三个内置参考 Skill，为用户自定义能力提供可运行样板。
- 为后续市场分发与版本管理保留清晰边界，但本阶段不实现这些能力。

## 功能需求

### 定义、发现与覆盖

- F1：Skill 必须由 YAML frontmatter 和 Markdown 正文组成；frontmatter 描述元信息，正文作为完整 SOP。
- F2：系统必须依次发现项目级 `<workspace>/.mewcode/skills/`、用户级 `~/.mewcode/skills/` 和随包提供的内置 Skill。同名定义按“项目＞用户＞内置”覆盖，只暴露最高优先级的有效版本。
- F3：每层同时支持 `<name>.md` 与 `<name>/SKILL.md`；入口基名必须与 frontmatter 的 `name` 完全一致。
- F4：单个定义解析失败时必须跳过并给出简洁警告，不得阻断其他 Skill；较高层定义无效时，允许回退到较低层有效版本。
- F5：同一层存在同名有效定义时必须拒绝启动并列出所有冲突来源，层级优先级不得用于解决同层歧义。
- F6：`name` 必须符合小写 kebab-case 格式 `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`；斜杠命令匹配继续保持大小写不敏感。
- F7：`name`、`description`、`tools`、`mode` 必填，未知 frontmatter 字段使该定义无效。
- F8：`mode` 只允许 `shared` 或 `isolated`。独立模式必须声明非负整数 `history`，共享模式禁止声明 `history`；`model` 只允许独立模式使用。
- F9：Skill 命令名不得与系统命令、系统命令别名或其他有效 Skill 命令冲突；发生冲突时必须在进入交互前报出名称与来源。

### 两阶段加载与参数

- F10：启动时只把各有效 Skill 的名称和一句说明加入 Agent 上下文，不加载正文，不注册专属工具，也不向模型暴露工具 schema。
- F11：系统必须提供一个不受 Skill 白名单约束的系统级工具，用于统一完成 Skill 的加载和运行。
- F12：Agent 调用该工具选择共享 Skill 时，系统必须加载完整 SOP 和专属工具，使当前 Agent Run 在同一轮继续执行。
- F13：Agent 调用该工具选择独立 Skill 时，系统必须启动临时独立运行，并把其最终回复作为该工具的结果返回主 Agent。
- F14：正文只识别 `{{input}}` 参数占位符，并使用调用时的完整原始参数替换；没有使用占位符时，参数仍作为本次任务内容提供给 Agent。
- F15：同一个共享 Skill 只保留一个激活实例；再次调用时使用新参数重新渲染并替换旧 SOP，但不改变它在多个激活 Skill 中的原有顺序。

### 斜杠命令

- F16：所有启动扫描得到的有效 Skill 必须立即注册为 `/<skill-name> [input]`，并自动进入帮助与 Tab 补全；命令调用复用系统加载工具的同一执行链路。
- F17：用户直接调用共享 Skill 时，主历史必须原样保存斜杠输入，并正常保存该轮 Agent 回复和工具链；完整 SOP 不得复制为用户消息。
- F18：用户直接调用独立 Skill 时，主历史只保存原始斜杠调用和独立运行的最终回复，不保存独立内部消息或工具调用。

### 共享模式与工具收窄

- F19：共享 Skill 激活后，其完整渲染 SOP 必须常驻主对话最显眼的 `Active Skills` 系统区域，并在每次提示重建时保持存在。
- F20：多个共享 Skill 可以同时激活；主对话可见工具为所有已激活共享 Skill 白名单的并集，再与当前系统模式限制取交集。
- F21：没有共享 Skill 激活时，主对话继续获得当前模式允许的全部已注册工具。
- F22：系统级 Skill 加载工具始终可见，不受 Skill 白名单、共享并集或独立 Skill 白名单限制。
- F23：PLAN 等只读限制必须继续作为安全上限；Skill 白名单不得重新开放被当前系统模式禁止的工具。
- F24：共享 Skill 始终使用当前对话 Profile；共享定义声明 `model` 时，该定义必须作为解析失败跳过。

### 独立模式

- F25：每次独立 Skill 调用必须创建一次新的临时对话；运行结束后销毁内部历史，不在不同调用间延续。
- F26：独立运行只能从主历史复制最近 `history` 个完整对话轮次；用户消息、助手回复及其工具调用链必须作为整体保留，不得截断。
- F27：独立运行必须继承环境、项目与用户人工指令、长期记忆和已激活共享 Skill 的 SOP，再追加当前独立 Skill 的 SOP；不得继承其他独立 Skill 的 SOP。
- F28：独立运行可见工具为“已激活共享 Skill 白名单并集＋当前独立 Skill 白名单”，再与当前系统模式限制取交集；独立 Skill 的白名单不得收窄主对话。
- F29：独立 Skill 的 SOP 只在本次临时独立上下文中保持显著，不得注入主对话的 `Active Skills` 区。
- F30：独立运行的最终回复直接作为回流摘要，不得再发起额外模型调用生成摘要。
- F31：主 Agent 自主调用独立 Skill 时，主历史必须保留普通用户消息、系统加载工具调用、包含独立最终回复的工具结果，以及主 Agent 最终回复；独立内部链路不得写入主历史。
- F32：独立 Skill 可选通过 `model` 指定现有 Profile；未指定时沿用当前 Profile。所有被引用 Profile 必须在启动时完成全部配置与凭据解析，任一无效都必须拒绝启动。

### 专属工具包

- F33：目录型 Skill 可以包含专属工具声明与实现脚本；专属工具声明位于 `<skill>/tools/*.json`，每个 JSON 文件声明一个工具，且 `tools/` 中全部 JSON 文件都必须是合法工具声明。实现脚本通常位于 `<skill>/scripts/`，但命令可以引用包内任意普通文件。单文件 Skill 不具有包内专属工具。
- F34：每个专属工具必须在 schema 中声明局部名称，并以 `<skill-name>__<tool-name>` 作为稳定公开名；Skill 白名单必须使用该完整名称。
- F35：启动时必须验证专属工具 schema、公开名、命令参数数组、包路径边界、脚本存在性、安全类别和超时配置，但不得创建运行时工具、启动进程或向模型公开 schema。
- F36：专属工具只在所属 Skill 激活时注册；每次实际调用才启动其实现脚本。
- F37：工具 schema 必须声明 `safety: read_only|side_effect`；专属工具使用完整公开名进入既有工具级权限判断，首期不支持自定义参数级权限目标。
- F38：脚本命令必须以 argv 字符串数组声明，且不经过 shell；包内相对可执行文件或脚本路径必须先安全解析，解释器由 Skill 作者显式指定。
- F39：脚本子进程必须以当前工作区为工作目录，并通过环境变量获得 Skill 包目录。
- F40：调用时必须向 stdin 写入一个 JSON 参数对象；stdout 必须且只能返回一个 JSON 对象，包含 `ok` 与 `content`，失败时可包含 `error`，并可包含 `metadata`。
- F41：非零退出、超时、非法 JSON 或结果字段错误必须转成结构化工具失败；stderr 只能作为有界诊断保存，不得直接显示给用户。
- F42：schema 可选声明 1–600 秒的超时，缺省为 60 秒；超时后必须终止该子进程。
- F43：有效 Skill 白名单中的每个工具必须在启动时真实存在。未配置或启动失败的 MCP 工具视为不存在，并使启动失败，错误必须指出 Skill、工具名和 MCP 状态。

### 热更新与恢复

- F44：系统必须在每次处理新用户输入或斜杠命令前检查 Skill 文件快照；无变化时不得重新加载，有变化时在该次输入前刷新。
- F45：热更新后，已激活 Skill 必须按名称绑定到当前最高优先级有效版本，并使用最后一次原始参数重新渲染。
- F46：已激活 Skill 不再存在任何有效版本时，必须自动失活并警告。
- F47：热更新快照若产生命令冲突、同层重复、缺失白名单工具或无效 Profile 等全局错误，必须整批拒绝并继续使用上一份完整有效快照。
- F48：会话必须持久化已激活 Skill 的名称、激活顺序和最后一次原始参数；恢复时按当前有效定义重新绑定和渲染，不保存或恢复旧 SOP 副本。
- F49：恢复时缺失的 Skill 必须忽略并警告，不得阻止其余会话内容恢复。

### `/reset`

- F50：新增 `/reset`，现有 `/clear` 继续只清除终端显示。
- F51：`/reset` 必须原子清空当前会话的消息、待执行计划和全部 Skill 激活状态，并切回 `[DEFAULT]`。
- F52：重置结果必须持久化到同一会话 ID，重启后不得恢复重置前的历史或 Skill 状态。
- F53：`/reset` 不得清除人工指令、长期记忆、权限模式或改变会话 ID；失败时不得留下部分重置状态。

### 内置样板

- F54：内置 `commit` 必须使用共享模式和最小工具白名单；它检查 Git 改动、运行相称验证、仅暂存与任务相关且安全的文件、生成提交信息并创建一次提交。`input` 作为额外提交意图或提交信息约束；无改动、验证失败或无法判断范围时不得提交。
- F55：内置 `review` 必须替代现有硬编码 `/review`，使用独立模式、携带 0 轮主历史和只读最小工具集，只依据当前工作区审查未提交改动。
- F56：内置 `test` 必须使用共享模式和最小工具白名单；有参数时优先运行与描述或相关改动匹配的最小测试集，无参数时优先验证当前未提交改动，并在合理时扩大验证。它只运行和报告测试，不修改产品代码。
- F57：三个内置 Skill 默认沿用当前 Profile，不声明专用 Profile。

## 非功能需求

- N1 确定性：相同目录快照、配置和会话状态必须得到相同的有效 Skill 集、覆盖结果、激活顺序、斜杠命令和工具可见集合；不得依赖文件系统枚举顺序。
- N2 原子性：启动快照、热更新快照和 `/reset` 必须以完整状态切换；失败时继续使用上一份有效状态，不得暴露新旧定义混合、部分重置或部分工具注册状态。
- N3 故障隔离：单个 Skill 的 frontmatter、正文或专属工具声明解析失败时，只跳过该定义并报告来源；只有命令冲突、同层重复、白名单缺失工具、被引用 Profile 无效等全局一致性错误才能阻止启动或拒绝热更新。
- N4 安全边界：Skill 白名单只能减少模型能力，不能扩大模式、权限系统、危险命令防护、路径约束或其他系统安全上限；系统加载工具的白名单豁免不得使它绕过自身固定职责。
- N5 进程隔离：专属工具实现不得导入 MewCode 主进程；必须无 shell 启动，限制运行时间，并在超时后终止子进程。包内路径解析不得逃逸 Skill 包目录。
- N6 权限透明：专属工具调用必须沿用现有权限决策和用户确认体验，并显示稳定的公开工具名；不得用脚本路径、解释器或局部名称绕过工具级权限规则。
- N7 隐私：启动目录、帮助、补全、状态和普通诊断只允许暴露 Skill 名称、说明及必要来源信息；不得泄露完整 SOP、工具 schema、脚本参数、凭据、独立运行内部历史或未经请求的 stderr。
- N8 凭据安全：Profile 校验不得把 API Key 值写入错误、日志、会话、工具结果或模型上下文；专属工具环境不得自动继承或注入不属于其显式运行环境的模型凭据。
- N9 上下文效率：未激活 Skill 的正文和专属工具定义不得进入模型请求；热更新无文件变化时不得重读全部文件。共享 Skill 的完整 SOP 只保留在动态系统区，不复制进对话消息。
- N10 可预期延迟：本地发现、快照比较、命令注册、白名单计算和共享 Skill 激活不得调用 Provider 或启动专属工具进程；只有 Agent 执行和实际工具调用可以产生相应外部延迟。
- N11 历史完整性：任何主历史都必须保持 Provider 所需的助手工具调用与工具结果配对；独立历史截取不得拆开轮次或工具调用链；独立内部记录不得意外进入主历史。
- N12 持久化可靠性：激活名称、顺序和原始参数必须与会话历史保持一致恢复；写入失败时不得声称 `/reset` 或状态更新成功，也不得留下只能部分恢复的状态。
- N13 兼容性：现有普通对话、PLAN 模式、权限、MCP、上下文压缩、长期记忆、会话恢复、帮助、补全和 `/clear` 行为除本 Spec 明确修改处外必须保持兼容；硬编码 `/review` 的迁移不得改变用户可见命令名。
- N14 跨平台：Skill 发现、路径校验、无 shell 子进程、stdin/stdout JSON 协议、超时终止及 cwd 行为必须在 Windows、Linux 和 macOS 上等价；路径比较遵循各平台安全语义。
- N15 可观察性：用户必须能区分单文件解析警告、全局快照拒绝、Profile 无效、工具缺失、脚本退出、超时、输出协议错误、自动失活及 `/reset` 失败；面向用户的信息应简洁且不以原始堆栈代替说明。
- N16 可测试性：发现与覆盖、严格解析、命令注册、提示注入、工具筛选、独立历史截取、父子运行回流、热更新回滚、恢复、重置和脚本协议必须能在不连接真实模型、网络、MCP 服务或用户目录的情况下自动测试。
- N17 可维护性：单文件和目录型 Skill 必须共享同一元数据与执行语义；斜杠入口和系统加载工具必须复用同一编排路径；帮助和补全必须由有效 Skill 快照生成，不维护第二份手工列表。
- N18 资源有界：stderr 诊断、stdout 解析、工具结果、Skill 正文和目录扫描必须使用明确的有界处理，避免异常文件或脚本无限占用内存、上下文或进程槽。

## 不做的事情

- 不实现 Skill 市场、远程仓库、安装、卸载、发布、搜索、评分或同步。
- 不实现 Skill 语义版本、依赖解析、锁文件、更新通道、迁移或兼容性协商。
- 不实现签名、来源认证、信任等级或包完整性验证；项目级与用户级 Skill 仍视为本地受信任配置。
- 不实现通用操作系统沙箱、容器隔离或资源配额；专属脚本仍以 MewCode 进程可用的操作系统身份运行，只受无 shell、cwd、超时和既有权限机制约束。
- 不支持远程 Skill URL、压缩包、符号链接入口或发现目录之外的入口文件。
- 不支持除 `<name>.md` 和 `<name>/SKILL.md` 之外的入口约定。
- 不支持 frontmatter 扩展字段、默认字段、字段别名或未知字段透传。
- 不支持 `{{input}}` 之外的位置参数、命名参数、条件、循环、过滤器或模板表达式。
- 不支持一个 Skill 同时声明共享与独立两种模式，也不支持调用时覆盖其执行模式、历史轮数或 Profile。
- 不支持共享 Skill 切换 Profile；Profile 选择只属于独立 Skill。
- 不持久化渲染后的 SOP、工具实例、独立内部历史或旧版本 Skill 快照。
- 不让独立 Skill 的 SOP 或白名单污染主对话，也不让不同独立 Skill 共享隐藏历史。
- 不支持用户逐个停用 Skill；本阶段通过 `/reset` 一次清除全部激活状态，或由热更新在定义消失时自动失活。
- 不支持手动热更新命令、后台文件监听器或运行中强制中断当前 Agent Run；变更只在下一次输入边界应用。
- 不自动纠正 Skill 名、路径名、工具名、命令冲突或无效 Profile。
- 不支持单文件 Skill 携带专属脚本，也不支持把脚本模块导入主进程。
- 不支持 shell 命令字符串、后缀推断解释器、脚本守护进程、交互式 stdin、多请求复用或流式 stdout。
- 不支持专属工具自定义参数级权限目标；只沿用完整公开名的工具级权限判断。
- 不支持 Skill 自行扩大 PLAN、只读模式、危险命令防护、路径沙箱或权限规则。
- 不改变 `/clear` 的“只清终端显示”语义。
- 不改变长期记忆、人工指令、权限模式或会话 ID 的 `/reset` 外延。
- 不让 `test` 自动修复产品代码，也不让 `review` 修改工作区。
- 不保证 `commit` 在范围不明、验证失败或工作区不安全时一定创建提交。

## 验收标准

### 定义、发现与命令

- AC1（F1、F3、F6–F8）：分别加载合法的单文件和目录型 Skill，确认 YAML 元信息、Markdown SOP 和严格字段规则均被识别；名称不匹配、非法 kebab-case、字段缺失、模式字段冲突或未知字段的定义被单独跳过并显示来源警告。
- AC2（F2、F4）：在三个层级放置同名 Skill，确认项目级覆盖用户级和内置；使高层定义无效后，确认自动回退到下一层有效版本，其他 Skill 不受影响。
- AC3（F5、F9）：分别构造同层重名、Skill 间命令重名、与系统命令或别名冲突，确认程序在显示交互提示前失败，并列出冲突名称及全部相关来源。
- AC4（F16）：正常启动后执行 `/help` 并使用 Tab 补全，确认全部有效 Skill 已注册为 `/<skill-name> [input]`，隐藏或无效定义未进入命令列表。

### 两阶段加载与共享执行

- AC5（F10）：启动后检查首个模型请求，确认只包含有效 Skill 的名称和一句说明，不包含未激活 SOP、专属工具 schema 或工具定义。
- AC6（F11–F14）：让 Agent 自主选择共享 Skill，确认系统加载工具始终可见，并在同一 Agent Run 中加载 SOP 和专属工具后继续执行；分别验证 `{{input}}` 完整替换及无占位符时参数仍作为任务内容提供。
- AC7（F15、F17）：连续使用不同参数调用同一共享 Skill，确认主历史原样保存两次斜杠输入，常驻 SOP 只保留最新参数渲染版本，Skill 的激活顺序不变，完整 SOP 未被复制成用户消息。
- AC8（F19）：激活多个共享 Skill 并触发多次模型迭代、上下文检查和新用户轮次，确认各 SOP 始终按激活顺序出现在显著的 `Active Skills` 系统区域。

### 工具白名单与系统限制

- AC9（F20–F24）：无共享 Skill 时确认当前模式允许的全部工具可见；依次激活两个共享 Skill 后，确认主对话工具为两份白名单并集；切入 PLAN 后只读交集生效；系统加载工具始终保留；共享 Skill 声明 `model` 时该定义被跳过。
- AC10（F23、F37）：把副作用专属工具加入白名单后在 DEFAULT 和 PLAN 中分别运行，确认 DEFAULT 仍经过现有工具级权限判断，PLAN 中该工具不可见且无法通过 Skill 重新开放。

### 独立执行与历史隔离

- AC11（F18、F25、F26、F30）：直接调用独立 Skill 两次，确认每次都新建临时上下文，只复制配置数量的最近完整轮次且不拆开工具链；主历史每次只增加原始斜杠调用和独立最终回复，不产生第二次摘要调用。
- AC12（F27–F29）：在存在人工指令、长期记忆、两个共享 Skill 和其他已激活独立 Skill 时运行一个独立 Skill，确认它只继承环境、人工指令、长期记忆、共享 SOP 和本次独立 SOP；工具集采用共享白名单并集加本次独立白名单，并且主对话的 SOP 与工具集不被该独立 Skill 改变。
- AC13（F31）：让主 Agent 自主调用独立 Skill，确认主历史保留普通用户消息、系统加载工具调用、携带独立最终回复的工具结果和主 Agent 最终回复，且 Provider 所需的工具调用配对完整；独立内部消息和工具链未写入主历史。
- AC14（F32）：分别让独立 Skill 使用当前 Profile、有效指定 Profile、缺失 Profile、配置无效 Profile 和缺少 API Key 环境变量的 Profile，确认前两者按预期运行，后三者在启动时明确失败且不泄露凭据。

### 目录包与专属工具

- AC15（F33–F36）：加载包含 `SKILL.md`、`tools/*.json` 和实现脚本的目录包，确认每个 JSON 只声明一个工具并获得 `<skill-name>__<tool-name>` 公开名；启动期完成静态验证但模型看不到定义，激活前工具未注册，激活后才可见，实际调用前没有脚本进程。
- AC16（F35、F38、F39）：分别构造非数组命令、缺失脚本、逃逸包目录的相对路径和合法显式解释器命令，确认前三者验证失败；合法调用不经过 shell，以工作区为 cwd，包内路径已解析，并能从环境变量读取 Skill 包目录。
- AC17（F37）：调用只读与副作用专属工具，确认二者按声明参与模式筛选，并以完整公开名进入现有工具级权限提示；schema 无法声明参数级权限目标。
- AC18（F40–F42）：使用脚本分别返回合法成功、合法失败、非零退出、非法 JSON、缺失字段、超量 stderr 和超时，确认合法结果正确转换，其余均成为有界、可区分的工具失败；stderr 不直接展示，默认超时为 60 秒，自定义值只接受 1–600 秒，超时进程被终止。
- AC19（F43）：让白名单引用不存在的内置工具、未注册专属工具及启动失败的 MCP 工具，确认均在交互开始前失败，并指出 Skill、公开工具名以及适用的 MCP 状态。

### 热更新与恢复

- AC20（F44、F45）：在文件未变化时连续提交输入，确认不重读完整 Skill 集；随后修改已激活 Skill 的 SOP、白名单和参数模板，确认下一次输入前应用新快照，并以最后参数重新渲染、按名称重绑且保持激活顺序。
- AC21（F46）：依次删除已激活 Skill 的高层版本和所有有效版本，确认前者回退并重绑低层版本，后者自动失活并显示一次清晰警告。
- AC22（F47）：热更新中分别制造命令冲突、同层重复、白名单工具缺失及 Profile 无效，确认整个新快照被拒绝，当前输入继续使用上一份完整有效快照，不出现新旧定义混合。
- AC23（F48、F49）：激活多个 Skill、重复传入参数后正常退出并恢复，确认名称、顺序和最后原始参数被恢复，并用当前文件重新渲染；删除其中一个定义后再次恢复，缺失项被忽略并警告，其余会话和 Skill 正常恢复。

### `/reset` 与兼容性

- AC24（F50–F53）：在 PLAN 模式、存在消息、待执行计划和多个激活 Skill 时执行 `/reset`，确认消息、计划和激活状态一次性清空，模式恢复 `[DEFAULT]`，会话 ID、人工指令、长期记忆和权限模式不变；重启后旧历史不再出现。
- AC25（F51–F53）：模拟 `/reset` 持久化失败，确认用户看到明确失败，内存与磁盘仍保持重置前的一致状态，没有部分清空。
- AC26（F50）：执行 `/clear`，确认仍只清终端显示，不改变历史、模式、计划、Skill、记忆或持久化数据。

### 内置样板

- AC27（F54、F57）：运行 `/commit [input]`，确认它使用共享模式和最小工具集，检查相关改动、执行相称验证、只暂存安全且相关的文件并生成一次提交；无改动、验证失败或范围不明时不产生提交。
- AC28（F55、F57）：运行 `/review`，确认硬编码命令已由内置 Skill 替代，命令名保持不变；执行采用独立模式、0 轮历史和只读最小工具集，只审查当前工作区且不修改文件。
- AC29（F56、F57）：分别以有参数和无参数运行 `/test`，确认它识别项目测试方式并优先运行最小相关测试，在合理时扩大验证，只报告结果而不修改产品代码。
- AC30（F54–F57）：项目级或用户级定义覆盖三个内置样板后，确认同名斜杠命令执行最高优先级有效版本；删除覆盖版本后恢复内置行为。

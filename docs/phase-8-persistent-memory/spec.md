# 项目知识、会话恢复与长期记忆 Spec

## 背景

MewCode 当前能够在单次进程内维护多轮对话，并通过上下文压缩延长会话寿命，但进程退出后不会保留可恢复的对话历史。结构化系统提示虽然预留了自定义指令和长期记忆位置，启动流程却不会主动发现项目规则、用户偏好或既有知识。用户每次重新启动后，都需要重复提供背景与约束。

本阶段需要补齐三层连续性：

- 通过分层项目指令恢复显式、人工维护的规则。
- 通过持久化会话恢复尚在有效期内的工作上下文。
- 通过自动笔记积累跨会话的用户偏好、纠正反馈、项目知识和参考资料。

三类信息由独立组件管理，并在启动、请求处理、Agent Loop 自然结束和程序关闭等生命周期边界协同工作。恢复过程必须容忍局部文件损坏、进程中断和模型调用失败，且不能因为辅助记忆不可用而阻止正常对话。

## 目标

- 启动时自动加载用户级和项目级知识，使模型在处理首条请求前已经获得有效指令与记忆索引。
- 默认恢复本项目 30 天内最近一次会话，同时支持强制新建和按 ID 恢复指定会话。
- 以可追加、可局部恢复的格式保存完整会话，不维护需要额外同步的元数据文件。
- 在恢复时修复或隔离坏行、未配对工具调用、超出上下文容量以及长时间中断等异常。
- 按明确优先级加载三层人工指令，并安全支持有限深度的文件引用。
- 在每轮 Agent Loop 自然结束后异步更新四类长期笔记，让新知识从下一轮开始可用。
- 分离用户级和项目级笔记，在有限上下文预算内优先注入项目相关记忆。
- 确保指令、会话和记忆更新失败时保留上一份有效状态，并向用户提供简洁、非敏感的诊断。
- 保持现有直接对话、Plan/Execute、工具调用、权限系统、MCP、Prompt 缓存和上下文压缩行为兼容。

## 功能需求

### 分层项目指令

- F1：启动时加载三层可选的手写指令：项目本地指令、项目根指令和用户级指令；文件不存在时正常继续。
- F2：指令按“项目本地 → 项目根 → 用户级”排列，高优先级内容先注入，并保留清晰的来源边界。
- F3：指令支持 `@include`。引用路径相对当前文件解析，内容在指令出现的位置展开，最大嵌套深度为 5。
- F4：每次加载维护已访问集合；重复引用或循环引用不得造成重复展开或无限递归。
- F5：项目级引用解析后的真实路径必须位于项目根内；用户级引用必须位于用户配置目录内。路径跳转、符号链接越界、缺失文件、循环和深度超限均跳过相关引用并显示简洁警告，不阻止其余有效指令加载。
- F6：指令在启动时形成当前进程的只读快照；运行期间的磁盘修改从下次启动开始生效。

### 会话持久化与恢复

- F7：每个新会话获得格式为 `YYYYMMDD-HHMMSS-xxxx` 的唯一 ID；同秒创建时必须避免冲突。
- F8：每个会话使用一个 JSONL 文件，按发生顺序追加已提交的用户消息、助手消息、工具调用、工具结果及必要的生命周期记录。每条记录独占一行并带时间信息。
- F9：系统不得维护独立会话元数据文件。会话 ID、标题、消息数、最后活动时间和恢复候选状态均通过扫描 JSONL 中的有效记录获得。
- F10：默认启动时自动恢复本项目 30 天内最近的可恢复会话；不存在候选会话时创建新会话。`--new` 强制创建新会话，`--resume <ID>` 恢复指定会话；两个参数不得同时使用。
- F11：默认恢复遇到不可恢复的最新候选时，显示警告并继续尝试下一个有效候选；显式指定的会话不存在、已过期、正在被其他进程使用或不可恢复时，必须明确报错，不得悄悄改为其他会话。
- F12：追加写必须保证此前完整行保持有效；进程崩溃或写入中断最多影响正在写入的最后一行。
- F13：恢复时逐行解析记录。语法损坏、结构非法或版本未知的行应被跳过并计入诊断，其余有效记录继续参与恢复。
- F14：恢复后的工具调用和工具结果必须保持协议配对。如果发现未完成、孤立或顺序不合法的工具交互，从最早的不完整交互处截断后续历史，只保留此前完整前缀。
- F15：恢复历史在首个正常模型请求前执行容量检查。超限时只自动尝试一次现有上下文压缩；压缩失败或压缩后仍超限时停止恢复并给出可操作错误，不得反复调用模型。
- F16：最后有效活动时间距恢复时间超过 24 小时时，在活动历史中插入一条系统生成的时间跨度提醒，明确写出上次活动时间和本次恢复时间，且不得伪装成用户消息。
- F17：会话文件之间相互隔离；同一会话同一时间只能由一个进程追加。正在使用的会话不得被恢复到另一进程或被过期清理。
- F18：定期清理最后有效活动时间超过 30 天的会话。清理失败不影响其他会话，并只输出不包含历史内容的警告。
- F19：会话列表或恢复扫描不得把整段消息内容输出到终端；标题应从有效记录中确定性获得，并限制为适合列表展示的长度。

### 自动笔记与记忆索引

- F20：自动笔记分为用户偏好、纠正反馈、项目知识和参考资料四类；每条笔记单独保存为带元信息头的 Markdown。
- F21：用户级笔记与项目级笔记分开存储。模型负责根据内容影响范围选择作用域，并可将重复、过期或被纠正的内容合并、更新或删除。
- F22：每个作用域维护一份由现有笔记生成的索引。任一索引均不得超过 200 行或 25KB，索引中的每个条目必须能够定位到对应笔记。
- F23：处理每条用户请求前，先等待上一轮尚未完成的笔记更新，再读取当前有效索引并注入上下文。合并后的注入内容同样不得超过 200 行或 25KB，项目级条目优先于用户级条目，且不得从条目中间截断。
- F24：自动笔记和索引属于参考知识，优先级低于人工项目指令和当前用户要求，不得覆盖更高优先级约束。
- F25：仅当 Agent Loop 以无工具调用的自然最终回复结束时，异步发起一次笔记更新。取消、错误、输出截断、迭代上限或仍要求工具调用的停止不得触发更新。
- F26：笔记更新以刚完成的有效回合、现有索引和必要的既有笔记为依据；更新请求不得携带工具，也不得再次触发 Agent Loop 或新的笔记更新。
- F27：是否值得记录、所属类别与作用域、是否与旧笔记重复或冲突，均由笔记更新模型判断；没有稳定长期价值时必须允许无操作结束。
- F28：最终回复应立即展示，不等待笔记更新。下一条请求和正常退出必须等待上一轮更新完成，确保成功生成的记忆从紧接着的下一轮开始可用。
- F29：笔记文件与索引作为一个逻辑更新原子提交。只有全部新内容通过格式、引用和大小校验后才能替换旧状态；失败或取消时保留上一份有效笔记和索引。
- F30：笔记更新失败后显示简洁警告，不自动重试，也不阻止下一轮使用旧索引继续工作。
- F31：索引超限时必须在条目边界内压缩或淘汰内容，优先保留仍有效、具体、近期且与当前作用域相关的信息；不得通过破坏 Markdown 或留下悬空引用来满足大小限制。
- F32：自动笔记不得保存凭据、疑似秘密、完整大体积工具输出、内部分析草稿或纯临时运行状态。

## 非功能需求

- N1：可靠性——指令加载、会话恢复和记忆更新的局部失败必须相互隔离；除明确无法安全恢复指定会话外，不得阻止 MewCode 启动或继续正常对话。
- N2：崩溃一致性——会话追加中断不得损坏此前完整记录；笔记或索引更新中断不得替换上一份有效状态，也不得留下被索引引用的半成品。
- N3：数据完整性——恢复、截断和压缩不得改变保留消息的内容与顺序；所有有意跳过、截断、压缩或清理的数据都必须有可观察诊断。
- N4：协议完整性——恢复后的消息序列必须继续满足各 Provider 对角色顺序、工具调用及工具结果配对的要求。
- N5：确定性——给定相同文件、时间和配置，指令展开顺序、会话候选排序、有效前缀、标题、消息数、索引合并和超限淘汰结果必须一致。
- N6：路径安全——所有路径均须使用规范化后的真实路径进行边界判断；父目录跳转、绝对路径绕过、大小写差异和符号链接不得突破对应作用域。
- N7：隐私——终端状态、异常信息、会话标题和自动笔记不得泄露完整历史、工具结果、凭据、疑似秘密或模型内部分析。
- N8：容量安全——首个恢复请求和后续请求的容量计算必须包含人工指令、记忆索引、恢复历史、工具定义及其他系统提示；预计无法安全调用时必须在 Provider 调用前停止。
- N9：资源控制——启动扫描应采用流式处理，不因会话总量线性占用内存；除被恢复的会话外，不得为计算列表信息把所有历史同时保存在内存中。
- N10：异步有界——同一会话最多存在一个笔记更新任务；每个自然结束的 Agent Loop 最多产生一次无工具的更新请求，不并发修改同一记忆作用域。
- N11：并发安全——会话锁、笔记更新和索引替换必须避免多个进程交错写入；无法安全取得写入权时应保留旧状态并明确报告。
- N12：清理有界——单个过期文件损坏、被占用或删除失败不得阻塞其余清理；清理不得跟随越界符号链接，也不得误删未过期或活动会话。
- N13：向后兼容——现有配置无需迁移；没有指令、会话或记忆文件时，系统行为应等价于当前版本的新会话。
- N14：功能兼容——未发生恢复或记忆更新时，直接对话、Plan/Execute、权限系统、内置工具、MCP、Prompt 缓存和上下文压缩行为保持不变。
- N15：Provider 兼容——OpenAI 与 Anthropic 路径应具有等价的会话恢复、容量保护和记忆更新语义；Provider 不返回 Token usage 时仍须使用现有近似估算保护请求。
- N16：可观察性——用户能够区分新建会话、自动恢复、指定恢复、坏行跳过、工具历史截断、恢复压缩、时间跨度提醒、过期清理和笔记更新失败。
- N17：可测试性——自动化测试不得依赖真实网络、真实模型、真实用户目录或实际等待 24 小时、30 天；时间、ID、文件错误、锁竞争和模型响应均应可控。
- N18：可维护性——指令加载、会话仓库和记忆管理保持独立职责，通过明确的生命周期接口协作；存储格式解析不得散落在 CLI、Prompt 构建和 Agent Loop 中。
- N19：可演进性——持久化记录和笔记元信息应具备格式版本；未知版本不得按已知格式猜测解释。
- N20：跨平台——路径边界、锁定、原子替换和清理行为在 Windows、Linux 与 macOS 上保持等价语义。
- N21：性能——没有待恢复历史或待完成笔记任务时，新增功能不得产生额外 LLM 请求；常规请求只读取有界索引，不扫描全部原始笔记或全部会话。

## 不做的事情

- 不引入向量数据库、Embedding、语义搜索、RAG 或按当前问题动态检索原始笔记。
- 不实现团队记忆、组织级记忆、多人合并、权限共享、云端同步或跨设备同步。
- 不恢复其他项目的会话，也不把一个项目的自动笔记隐式注入另一个项目。
- 不提供图形化会话管理器、启动时交互选择器、全文历史搜索、会话重命名、导入导出或云端备份。
- 不维护独立的会话元数据、数据库索引或需要与 JSONL 同步的旁路状态文件。
- 不自动恢复或重新执行中断的工具调用；不完整工具交互只会被截断。
- 不把过期会话自动转换成长久归档；超过保留期后直接进入清理流程。
- 不加密会话或记忆文件，不承诺安全擦除；本阶段只提供路径隔离、最小输出和版本控制排除。
- 不在进程运行期间热重载人工指令；修改从下次启动开始生效。
- 不支持条件引用、网络引用、命令生成引用或超过固定深度的复杂指令规则。
- 不让自动笔记取代人工指令，也不把笔记内容视为可直接执行的命令。
- 不为自动笔记配置独立模型、独立 Provider、工具调用或多轮 Agent Loop。
- 不在笔记更新失败后自动重试、退避或阻止后续正常请求。
- 不实现常驻后台守护进程；会话清理和笔记更新只在 MewCode 生命周期内运行。
- 不修改现有上下文压缩策略、Provider 缓存策略、权限判定或工具调度语义，除非为接入恢复历史所必需。
- 不承诺精确 Token 计数；继续使用现有 Provider usage 与近似估算机制。
- 不自动保存完整工具输出到长期笔记，也不把会话 JSONL 当作长期知识库直接注入模型。

## 验收标准

### 分层项目指令

- AC1（F1、F2、F6）：同时提供三层指令后启动，首个模型请求按“项目本地 → 项目根 → 用户级”顺序包含全部内容及来源边界；删除任一可选文件仍可启动；运行中修改文件不影响当前进程，重新启动后生效。
- AC2（F3-F5）：构造相对引用、重复引用、直接与间接环路、超过 5 层、父目录跳转、绝对路径、符号链接越界和缺失文件场景；有效内容只展开一次，无限递归和越界读取均未发生，其他有效指令仍被加载，并显示不泄露文件内容的警告。
- AC3（F3-F5）：项目级引用只能读取项目根内文件，用户级引用只能读取用户配置目录内文件；相同引用文本在两个作用域中按各自边界独立解析。

### 会话写入与元信息

- AC4（F7）：在固定到同一秒的时钟下连续创建多个会话，每个 ID 均符合 `YYYYMMDD-HHMMSS-xxxx` 且互不冲突。
- AC5（F8、F12）：完成包含普通回答和工具调用的多轮对话后，JSONL 按发生顺序保存可重建的完整记录，每条记录独占一行。模拟最后一次写入中断后，此前完整行仍可恢复，最多丢失或跳过最后一条不完整记录。
- AC6（F9、F19）：在不存在任何独立元数据文件的情况下，通过流式扫描得到稳定一致的会话 ID、标题、消息数和最后活动时间；列表输出不包含完整消息或工具结果。
- AC7（F8、N3）：模拟一次追加失败，既有完整记录保持逐字不变，不出现半条有效记录，并向用户报告当前回合未成功持久化。

### 启动恢复与修复

- AC8（F10）：存在 30 天内多个会话时，普通启动恢复最后活动时间最近的可恢复会话；没有候选时创建新会话；`--new` 始终新建；`--resume <ID>` 只恢复指定会话；同时提供两个参数时在启动模型前报错。
- AC9（F11）：最新候选损坏到无法恢复时，默认启动显示警告并尝试下一个候选；显式指定不存在、过期、被占用或不可恢复的 ID 时明确失败，不自动切换会话。
- AC10（F13）：在 JSONL 的开头、中间和末尾分别插入坏 JSON、非法结构和未知版本记录，恢复结果跳过坏行并保留其余有效记录，同时报告跳过数量。
- AC11（F14、N4）：分别构造缺失工具结果、孤立工具结果、调用与结果 ID 不一致以及多工具批次只完成一部分的历史；恢复只保留最早异常点之前的完整前缀，后续 OpenAI 与 Anthropic fake 均接受恢复后的消息序列。
- AC12（F15）：恢复历史超过安全容量时只发起一次压缩请求；成功后首个主请求使用压缩历史。压缩失败或压缩后仍超限时不调用主模型，并给出使用新会话等可操作提示。
- AC13（F16）：中断 24 小时以内恢复时不增加提醒；超过 24 小时时增加一条系统提醒，其中包含可核对的上次活动时间和恢复时间，且角色不为用户。
- AC14（F17、N11）：一个进程持有会话写锁时，另一进程无法恢复或追加同一会话；原进程释放后可正常恢复，期间文件没有交错写入。
- AC15（F18、N12）：启动时以及进程持续运行超过一个清理周期后，最后有效活动超过 30 天且未被占用的会话被清理；未过期和活动会话保留。模拟删除失败时继续处理其他候选并输出非敏感警告。

### 自动笔记与索引

- AC16（F20）：一次更新分别产生四类笔记，所有笔记均为独立 Markdown，带有效类别、作用域、创建时间、更新时间和稳定标识等元信息。
- AC17（F21、F27）：向更新模型提供重复偏好、被用户纠正的旧结论、项目专属知识和跨项目偏好；结果分别执行合并、替换、项目级存储和用户级存储，不保留互相冲突的有效索引项。
- AC18（F27）：完成一个没有长期价值的寒暄回合，更新模型可以返回无操作，磁盘上的笔记与索引均保持不变。
- AC19（F22）：分别构造接近和超过限制的用户级、项目级记忆；更新后每份索引均不超过 200 行和 25KB，且每个条目都能定位到实际存在的笔记。
- AC20（F23）：两份索引合计超限时，注入内容不超过 200 行和 25KB，先保留项目级完整条目，再在剩余预算内加入用户级完整条目；不存在半条 Markdown 记录。
- AC21（F23、F28）：让上一轮笔记更新阻塞，观察到最终回复和输入提示已经显示，但下一轮模型请求尚未发出；释放更新后，下一轮请求包含刚生成的索引。
- AC22（F24）：同时提供互相冲突的项目本地指令、项目根指令、用户指令和自动笔记，发送给模型的内容具有清晰层级，自动笔记明确标记为不可覆盖人工指令与当前用户要求的参考信息。
- AC23（F25）：自然最终回复恰好触发一次更新；工具循环最终自然停止仍只在整个 Loop 结束后触发一次。取消、Provider 错误、输出截断、空回复、迭代上限和未执行的最终工具调用均不触发更新。
- AC24（F26、N10）：检查更新请求，确认其只包含允许的回合与记忆材料、不带工具，且最多调用模型一次；更新请求本身不会产生新的会话消息或递归笔记任务。
- AC25（F29）：分别在写入笔记、删除旧笔记、校验索引和替换索引时注入错误；每种情况恢复后均只能看到更新前的完整状态或更新后的完整状态，不出现悬空引用或半次更新。
- AC26（F30）：更新模型失败时显示简洁警告，下一轮使用旧索引正常调用主模型；没有自动重试更新请求。
- AC27（F28）：自然回复后立即正常退出，退出流程等待更新完成并保留新笔记；更新失败时退出仍能完成并保留旧状态。
- AC28（F31）：索引超限时，淘汰结果稳定地优先保留有效、具体、近期且作用域相关的条目；重新执行得到相同结果，Markdown 与笔记引用保持完整。
- AC29（F32、N7）：让回合包含 API key、疑似令牌、内部分析、完整大工具输出和临时路径；自动笔记、索引、标题、状态和错误信息中均不出现这些敏感或临时内容。

### 兼容性、安全与端到端

- AC30（N6）：在 Windows 与类 Unix 路径语义下测试大小写、父目录、绝对路径、目录联接和符号链接；所有越界目标均在读取前被拒绝。
- AC31（N8、N15）：恢复后的首个请求同时包含三层指令、两级索引、工具定义和历史时，容量估算覆盖全部内容；OpenAI 与 Anthropic fake 获得等价的压缩或拒绝结果。
- AC32（N9）：扫描大量会话以生成候选信息时，逐文件流式处理，不把全部会话消息同时保存在内存；只有最终选中的恢复历史进入活动上下文。
- AC33（N13、N14）：在全新项目和空用户配置目录中启动，现有直接对话、Plan/Execute、权限、内置工具、MCP、Prompt 和上下文管理测试全部保持通过，无需迁移旧配置。
- AC34（N16）：分别触发新建、自动恢复、指定恢复、坏行跳过、工具历史截断、恢复压缩、时间跨度提醒、过期清理和笔记更新失败，终端反馈可区分且不混入模型最终回答。
- AC35（N17-N21）：完整自动化测试不需要 API key、外部网络、真实时间等待或真实用户目录，并能稳定模拟时钟、ID、崩溃写入、文件错误、锁竞争和模型响应。
- AC36（F1-F32）：端到端执行“启动新项目 → 加载三层指令 → 完成工具型任务 → 异步形成项目与用户记忆 → 退出 → 隔日自动恢复 → 处理下一请求”；恢复后的模型同时获得合法会话历史、时间提醒、项目优先的有界记忆以及正确排序的人工指令。

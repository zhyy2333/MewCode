# MewCode Agent Loop Spec

## 背景

MewCode 已具备多轮对话、流式文本输出、双 Provider 和工作区工具系统，但每轮最多执行一次工具。模型拿到工具结果后不能继续观察、修正和调用后续工具，复杂任务仍需要用户反复催促。

本阶段引入 Agent Loop，使模型能围绕同一任务重复进行推理、工具调用、结果观察和策略调整，直到完成或命中明确停止条件。同时建立统一异步事件流，把 Agent 执行过程与终端等展示界面解耦。

## 目标

- 支持完整 ReAct 循环，让模型自主完成多步骤任务。
- 覆盖正常完成、迭代上限、用户取消、连续未知工具和流错误等停止路径。
- 通过异步事件流暴露文本、工具调用、工具结果、Token 用量和执行进度。
- 流式文本既实时展示，也被完整收集用于后续循环判断和历史记录。
- 安全并发执行同批只读工具，串行执行具有副作用的工具。
- 提供 `/plan` 与 `/do` 两阶段工作方式，规划阶段只允许读取，执行阶段恢复全部工具。
- 保持现有双 Provider、工作区安全边界和纯聊天行为兼容。
- 不在本阶段引入权限系统、上下文压缩或交互式工具确认。

## 功能需求

一次“迭代”指一次完整的模型流式响应，以及该响应请求的工具批次处理。

- F1：收到普通用户任务后，系统进入 Agent Loop，重复调用模型、执行工具并回写结果，直到命中停止条件。
- F2：每次后续迭代都能看到本任务此前已完成的模型响应、工具调用和工具结果，从而调整下一步行动。
- F3：Agent 通过统一异步事件流对外报告执行过程，不依赖终端或其他具体界面。
- F4：模型文本增量必须同时实时发送给事件消费者并累积成完整响应；只有流正常结束后，系统才根据完整响应决定是否调用工具。
- F5：一次模型响应可以包含零个、一个或多个工具调用；所有调用都被完整收集后再统一调度。
- F6：工具调用按原始顺序划分执行批次：相邻的只读调用可并发执行，具有副作用的调用形成串行屏障。回写模型时，工具结果始终保持原始调用顺序。
- F7：每个完整工具调用都产生“调用”和“结果”事件；并发工具可以在完成时立即报告结果，但不会改变回写顺序。
- F8：工具失败、参数错误或执行异常作为结构化结果回写给模型，允许模型在后续迭代中自行修正，而不会导致 Agent 崩溃。
- F9：当模型响应中不再包含工具调用时，本任务正常完成；已收集的完整文本成为最终回答。
- F10：单次 Agent 任务最多进行 20 次模型调用。第 20 次响应如果仍请求工具，该批工具不再执行，任务以“达到迭代上限”停止。
- F11：未知工具调用先作为失败结果回写，允许模型纠正；如果连续 3 次迭代都只请求未知工具且没有任何已知工具可执行，任务停止。
- F12：用户在任务运行期间按 `Ctrl+C` 可取消当前任务。取消后不再启动新的模型调用或工具调用，已完成的副作用不回滚，REPL 返回输入提示符而不退出进程。
- F13：模型流发生错误时，已经展示的文本增量保留在界面上，但未完成的模型响应和不完整工具调用不写入会话历史；此前已完成的迭代仍保留。
- F14：事件流至少包含文本增量、工具调用、工具结果、Token 用量、进度和任务停止事件。
- F15：每次模型响应结束后报告该次及当前任务累计的输入、输出和总 Token 用量。
- F16：进度事件至少报告任务开始、当前迭代、工具批次状态和最终停止原因。
- F17：`/plan <任务>` 启动规划阶段；规划阶段仅向模型开放只读工具，任何写入、编辑或命令执行工具既不公开也不可执行。
- F18：成功完成 `/plan` 后，系统展示并保存最新计划；新的 `/plan` 会替换此前尚未执行的计划。
- F19：`/do` 使用全部工具执行最近一次成功生成的计划；执行成功后清除该计划，执行失败或取消时保留计划以便重试。
- F20：没有可执行计划时输入 `/do`，或 `/plan` 后未提供任务时，系统显示明确提示且不调用模型。
- F21：普通用户消息默认使用全部工具直接进入 Agent Loop，不要求先经过 Plan Mode。
- F22：未调用工具的普通聊天仍保持流式输出、多轮历史和现有双 Provider 行为。

## 非功能需求

- N1：新增 Agent Loop 后，现有配置文件、双 Provider、六个内置工具及普通聊天行为保持兼容。
- N2：Agent 执行逻辑不得依赖终端输入输出；任何界面只需异步消费统一事件流。
- N3：文本增量到达后应立即向事件消费者转发，不得等待完整响应或工具调用解析结束。
- N4：只读工具采用有界并发，同一批最多同时执行 4 个，避免单次模型响应无上限占用资源。
- N5：具有副作用的工具不得与任何其他工具重叠执行。
- N6：收到取消信号后应尽快终止当前流或可取消工具，正常情况下 2 秒内返回 REPL；已完成的写入等副作用不尝试回滚。
- N7：工具安全分类固定为：读文件、找文件和搜代码属于只读工具；写文件、编辑文件和执行命令属于副作用工具。规划阶段的限制由实际可用工具集合强制执行，不能只依赖模型提示词。
- N8：Anthropic 与 OpenAI 的流事件、工具调用和 Token 统计差异必须在 Provider 边界内完成归一化。
- N9：事件必须携带足够的任务、迭代和工具调用标识，使消费者能恢复因果关系；同一执行条件下，事件顺序应可预测。
- N10：并发工具结果可以按实际完成时间实时报告，但写回模型的结果顺序必须稳定。
- N11：工具输出继续遵守现有大小限制和截断规则；终端默认只显示简短工具状态，不打印完整参数、大段结果或供应商原始事件。
- N12：Provider、工具或事件消费者中的单次错误不得造成 REPL 进程崩溃，也不得遗留仍在后台运行的 Agent 任务。
- N13：错误信息和事件不得泄露 API Key 等凭据；供应商异常继续进行脱敏处理。
- N14：任务停止时，会话历史只能包含已经完整结束的模型响应、工具调用和工具结果，不保存半截响应或无法关联的结果。
- N15：Token 数量使用统一字段表示；供应商未提供某项统计时必须明确标记为不可用，不得伪造为零。
- N16：默认测试不得调用真实模型 API，不执行真实危险命令；并发、取消、迭代上限和流错误必须能通过可控的 fake/mock 稳定验证。
- N17：实现继续支持 Python 3.11 及以上版本，并通过项目现有全部测试。

## 不做的事

- 不做权限配置、按用户或按工具授权、动态安全策略及沙箱隔离。
- 不做工具调用前的交互式确认；`/plan` 到 `/do` 的阶段切换不等同于逐次工具审批。
- 不做上下文压缩、摘要、自动裁剪或长期记忆。
- 不做 Token 预算停止条件、费用预算或用量计费；本章只观测和报告 Token 用量。
- 不做模型请求或流错误的自动重试、退避及 Provider 自动切换；流错误直接停止当前任务。
- 不做任务暂停、断点续跑、后台运行、进程重启恢复或跨进程任务持久化。
- 不做已完成副作用的事务回滚；取消或失败前已完成的文件修改及命令影响仍然保留。
- 不做多个命名计划、计划版本管理、计划编辑器、结构化计划 DSL 或任务依赖图；只维护一个最近成功生成的文本计划。
- 不做副作用工具并行执行，即使多个调用看起来彼此独立。
- 不分析命令内容来判断其是否只读；执行命令工具整体按副作用工具处理，并在 Plan Mode 中禁用。
- 不新增内置工具，也不改变现有工具的工作区边界、危险命令拦截和输出截断能力。
- 不新增 GUI、Web 界面或远程控制接口；本章只提供解耦事件流并更新现有终端消费者。
- 不展示或持久化模型的隐藏推理过程；只展示模型主动输出的普通文本、工具状态和进度事件。
- 不保证撤销已经发送到外部进程或系统且无法中断的操作；取消采用尽力而为语义。

## 验收标准

- AC1：模型依次请求至少两轮工具并最终返回无工具调用的文本时，系统自动完成全部迭代，无需用户再次输入。
- AC2：后续模型调用能看到此前完整的工具调用和结果，并能根据失败结果改用正确参数或其他已知工具。
- AC3：模型只返回文本时，文本增量立即显示，完整文本被保存为最终回答，任务以“模型完成”停止。
- AC4：模拟分段文本与分段工具参数流时，界面实时收到文本增量；流结束后系统能恢复完整文本及全部工具调用。
- AC5：一次响应包含多个工具调用时，每个调用都被执行一次，并在下一次模型调用前全部回写。
- AC6：同一响应中的相邻 `read_file`、`find_files` 和 `search_code` 调用可以重叠执行，但并发数不超过 4。
- AC7：`write_file`、`edit_file` 和 `run_command` 不与任何其他工具重叠执行；混合调用仍遵守模型给出的批次顺序。
- AC8：并发工具结果事件可以按完成时间出现，但提供给模型的结果始终与原始工具调用顺序一致。
- AC9：每个工具都产生可关联的调用事件和结果事件；事件包含任务、迭代和工具调用标识。
- AC10：工具参数错误、执行失败或异常不会终止 Agent Loop；失败结果回写后，模型仍可在下一迭代进行修正。
- AC11：第 20 次模型响应仍请求工具时，该批工具不执行，系统发出“达到迭代上限”停止事件。
- AC12：一次未知工具请求会作为失败结果回写；模型在三次限制内改用已知工具时任务可继续。
- AC13：连续 3 次迭代都只请求未知工具时，系统停止任务并报告“连续未知工具”原因。
- AC14：Agent 运行期间按 `Ctrl+C`，不会再启动新的模型或工具调用，正常情况下 2 秒内返回 REPL，进程仍可接受下一条消息。
- AC15：取消前已经完成的文件修改不会被回滚；取消后的未启动工具不会执行。
- AC16：模型流中途失败时，已经收到的文本仍可见，当前不完整响应不进入会话历史，此前完成的迭代仍被保留。
- AC17：流失败后系统不自动重试模型请求，并发出包含脱敏错误信息的停止事件。
- AC18：每次完成的模型响应都产生归一化 Token 用量事件，包含本次和任务累计统计；供应商缺失的数字明确标记为不可用。
- AC19：一次完整任务可观察到任务开始、迭代变化、工具批次状态和最终停止原因等进度事件。
- AC20：`/plan <任务>` 调用模型时只提供 `read_file`、`find_files` 和 `search_code`；即使模型请求写入、编辑或命令工具，这些调用也不会执行。
- AC21：成功完成 `/plan` 后，终端显示并保存计划；再次执行 `/plan` 会用新计划替换旧计划。
- AC22：`/do` 使用全部工具执行最近计划；正常完成后再次输入 `/do` 会提示没有计划。
- AC23：`/do` 执行失败或被取消后，计划仍然存在，可以再次执行。
- AC24：输入空的 `/plan` 或在没有计划时输入 `/do`，系统显示用法提示且不调用模型。
- AC25：普通用户消息无需 `/plan` 即可使用全部工具进入 Agent Loop；未调用工具的多轮聊天行为保持不变。
- AC26：Anthropic 与 OpenAI 在相同脚本事件下产生等价的统一文本、工具调用、Token 和停止事件。
- AC27：终端工具状态不显示完整参数、供应商原始事件或大段工具结果；超限结果继续截断并标记。
- AC28：Provider、工具或事件消费者发生可预期错误后，REPL 不崩溃，任务结束后没有遗留后台 Agent 工作。
- AC29：错误输出及事件中不包含配置的 API Key，模型隐藏推理内容不进入用户事件流或会话历史。
- AC30：全部测试可在无真实 API Key、无网络请求且不执行危险命令的环境中完成。
- AC31：项目原有测试与本阶段新增测试全部通过，Python 3.11 及以上版本能够运行。

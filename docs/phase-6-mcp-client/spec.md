# MewCode MCP 客户端 Spec

## 背景

MewCode 当前拥有统一的工具接口、工具注册中心、Agent 调度流程和权限防御系统，但可用工具仅来自进程内置实现。用户无法通过配置接入外部工具服务，也无法复用 MCP 生态中已有的 Server。

本阶段为 MewCode 增加只面向工具能力的 MCP 客户端。MewCode 在启动时读取用户级与项目级配置，连接多个外部 MCP Server，按 MCP `2025-11-25` 完成初始化和工具发现，并把可用的远端工具纳入现有工具中心。Agent 仍通过统一工具接口发现和调用工具，不需要感知工具来自内置实现还是 MCP Server。

外部 Server 属于独立故障域。某个 Server 的配置、启动、通信或工具调用失败时，MewCode 应提供可理解的失败信息，并保持其他 Server、内置工具和 Agent Loop 可用。

## 目标

- 兼容 MCP `2025-11-25` 的初始化、工具发现和工具调用流程，并明确不兼容已移除初始化会话的 MCP `2026-07-28`。
- 支持通过 stdio 启动本地 MCP Server，以及通过 Streamable HTTP 连接远程 MCP Server。
- 从用户级和项目级配置合并得到启用的 Server 集合，并支持在敏感配置值中引用环境变量。
- 在 MewCode 启动时发现各 Server 提供的工具，以稳定且无冲突的名称注册到现有工具中心。
- 让 MCP 工具沿用现有 Provider 暴露、参数校验、权限决策、调度、状态展示和 Agent Loop 失败恢复行为。
- 在一次 MewCode 进程生命周期内复用每个 Server 的连接，并在退出时释放子进程、网络连接和待处理请求。
- 隔离不同 Server 的启动与运行故障，防止单个 Server 的失败或无响应破坏其他工具的可用性。

## 功能需求

### 配置发现与合并

- F1：MewCode 从用户级 `~/.mewcode/config.yaml` 和当前工作区的项目级 `.mewcode/config.yaml` 读取 `mcp_servers` map；未声明 `mcp_servers` 时按空 map 处理。项目级文件允许只包含 MCP 配置，现有模型 Profile 仍以用户级配置为准。
- F2：缺少项目级配置文件时按空项目配置处理。两个层级中不同名的 Server 合并启用；同名 Server 由项目级整条配置替换用户级配置，不做字段级深合并。
- F3：每个 `mcp_servers` key 必须是非空字符串并作为 Server 名称。Server 条目必须通过 `transport` 明确声明 `stdio` 或 `http`，只能包含该传输允许的字段；混用两种传输的专属字段或包含未知字段时，该 Server 配置无效。
- F4：stdio Server 必须声明非空 `command`，可以声明字符串数组 `args` 和字符串 map `env`；未声明的 `args` 与 `env` 按空值处理。子进程继承 MewCode 的进程环境，再由已配置的 `env` 覆盖同名变量，并以当前工作区为工作目录启动。
- F5：HTTP Server 必须声明使用 `http` 或 `https` 协议的非空 `url`，可以声明字符串 map `headers`；未声明的 `headers` 按空值处理，已配置的请求头随该 Server 的每次 HTTP 请求发送。协议要求的内容类型、响应类型、协议版本和会话请求头由 MewCode 控制，用户配置不得覆盖这些保留请求头。
- F6：stdio 的 `env` 值和 HTTP 的 `headers` 值支持在字符串任意位置展开一个或多个 `${VAR}` 引用。引用的环境变量未定义时，该 Server 配置无效；不对 `command`、`args`、`url` 或其他字段执行环境变量展开。
- F7：任一配置文件无法解析、根结构错误或已声明的 `mcp_servers` 不是 map 时，MewCode 拒绝启动并报告文件级配置错误。单个 Server 条目缺少字段、字段类型错误、传输类型未知或环境变量无法展开时，只跳过该 Server 并显示警告。

### 连接与协议会话

- F8：MewCode 在进入交互会话前并行启动所有有效 Server 的连接流程；每个 Server 独立执行且有时间上限，一个 Server 失败或无响应不得阻止其他 Server 完成启动。
- F9：stdio 传输由 MewCode 启动并持有一个 Server 子进程，使用 UTF-8、换行分隔且单行内无嵌入换行的 JSON-RPC 消息通过标准输入和标准输出通信；标准错误仅作为 Server 日志，不参与协议解析。
- F10：Streamable HTTP 传输向配置的单一端点发送 HTTP POST，能够处理 `application/json` 和请求范围内的 `text/event-stream` 响应，并在协商后携带协议版本头以及 Server 返回的会话标识。首版不开启仅用于 Server 主动推送的长期 HTTP GET 流。
- F11：每个 Server 的首次协议交互必须是 MCP `2025-11-25` 的 `initialize` 请求。MewCode 只声明本阶段实际支持的客户端能力；Server 返回的协议版本不受支持或未声明工具能力时，该 Server 初始化失败。
- F12：初始化成功后，MewCode 先发送 `notifications/initialized`，再发送 `tools/list`；初始化完成前不得执行工具发现或工具调用。
- F13：MewCode 为发出的 JSON-RPC 请求生成会话内唯一 id，并允许同一 Server 存在多个待处理请求。收到响应时必须按 id 关联原请求；乱序响应不得导致配对错误，未知 id、重复响应、非法 JSON-RPC 消息和传输关闭必须以受控错误处理。Server 发起 `ping` 请求时返回空成功结果；Server 发起未协商的其他请求时返回不支持该方法的 JSON-RPC 错误，不执行资源、提示词、采样或其他越界能力。
- F14：所有初始化、工具发现和工具调用请求都有有限等待时间。请求超时后停止等待，并在传输仍可用时发送对应取消通知；超时不得永久占用待处理请求或阻止关闭流程。

### 工具发现与注册

- F15：MewCode 使用 `tools/list` 读取 Server 的全部工具，并持续请求 `nextCursor` 指示的后续页面，直到完成分页；不得只注册第一页结果。
- F16：每个远端工具以 `<server>__<tool>` 作为 MewCode 中公开名称的基础值，但向 MCP Server 发起 `tools/call` 时仍使用 Server 发布的原始工具名。基础值已满足 `^[A-Za-z0-9_-]{1,64}$` 时保持原样；否则确定性替换非法字符、按需截断，并追加由完整基础值生成的短哈希，使最终名称满足该格式且相同输入始终得到相同名称。
- F17：规范化后的公开名称不得与已注册工具或同批其他工具冲突。定义非法、名称重复、规范化后仍冲突或无法适配的单个工具被跳过并显示带 Server 名称的警告，其他有效工具仍可注册。
- F18：注册后的远端工具保留 Server 提供的描述和输入 Schema，并像内置工具一样出现在 Provider 可用工具列表、工具查找和 Agent 调用流程中。
- F19：本阶段的工具集合是启动时快照。MewCode 不订阅或响应 `notifications/tools/list_changed`，运行期间不动态增加、删除或替换已注册工具。

### 权限与调度

- F20：所有 MCP 工具均按可能产生副作用的工具处理，不依据 Server 提供的 `readOnlyHint`、`destructiveHint` 或其他工具注解降低安全级别。
- F21：每次 MCP 工具调用都必须经过 MewCode 现有权限决策，权限单位是公开的命名空间工具。选择“仅本次”只允许当前调用；选择“本会话”或“永久”后，允许该工具后续使用任意参数调用，并沿用现有权限规则的作用域和优先级。
- F22：未经权限允许的调用不得向 MCP Server 发送 `tools/call`；权限拒绝作为普通工具失败返回 Agent，且不终止 Agent Loop。
- F23：MCP 工具沿用副作用工具的独占调度语义，不与其他工具并发执行；同一模型响应中的调用顺序保持不变。

### 工具调用与结果适配

- F24：Agent 调用已注册的 MCP 工具时，MewCode 把参数对象原样作为该原始工具的 `tools/call` 参数发送，并在同一 Server 会话上等待对应响应。
- F25：MCP 结果中的多个文本内容块按原顺序合并；存在 `structuredContent` 时将其序列化为 JSON 文本并保留，若同时存在文本内容则两者都返回给 Agent。
- F26：工具结果中的资源链接和文本型嵌入资源转换为包含 URI、类型和可用文本的可读描述，但不触发任何 MCP 资源读取请求；图片、音频及其他二进制内容只返回类型、MIME 和“内容已省略”标记，不把 Base64 数据传给模型。
- F27：MCP 结果的 `isError: true`、JSON-RPC 错误、HTTP 错误、协议错误、超时和连接中断均转换为包含 Server 与工具上下文的 MewCode 失败结果，不让异常越过工具边界或终止 Agent Loop。
- F28：适配后的工具结果沿用 MewCode 现有内容大小上限；超过上限时截断并明确标记，错误信息和终端状态不得泄露已展开的环境变量、认证请求头或其他配置秘密。

### 缓存、故障隔离与关闭

- F29：一次 MewCode 进程生命周期内，每个 Server 只维护一个缓存客户端：stdio 复用同一子进程和管道，HTTP 复用同一网络客户端及协商得到的会话状态；工具调用不得为每次请求重新初始化 Server。
- F30：Server 在初始化或工具发现阶段失败时，其工具不进入注册中心；Server 在运行阶段退出、会话失效或连接不可用时，所有待处理调用受控失败，后续调用快速返回不可用错误。本阶段不自动重启、重新初始化或重连。
- F31：一个 Server 的失败状态只影响其自身工具；其他 MCP Server、内置工具、Provider、REPL 和 Agent Loop 保持可用。
- F32：MewCode 正常退出、启动流程中止或收到取消时，必须在有限时间内清理所有已创建的 Server 客户端。stdio 先关闭输入并等待子进程退出，必要时再终止；HTTP 在存在会话标识时尝试结束会话，然后关闭网络连接；清理单个 Server 失败不得阻止其他 Server 清理。

## 非功能需求

- N1：可靠性——任何外部进程、网络请求、协议响应或关闭动作都不得让 MewCode 无限等待；超时、取消和传输中断后必须释放对应的等待者与资源。
- N2：故障隔离——每个 MCP Server 拥有独立的连接状态、待处理请求集合和错误边界；单个 Server 的错误不得污染其他 Server 的请求配对或生命周期状态。
- N3：协议兼容性——实现行为以 MCP `2025-11-25` 为唯一协议基线，同时正确遵守 JSON-RPC 2.0 消息结构、stdio 消息分帧和该版本 Streamable HTTP 的请求、SSE 响应、协议版本头与会话标识要求。
- N4：向后兼容——未配置 `mcp_servers` 时，MewCode 的现有配置加载、六个内置工具、Provider、权限系统、REPL 和 Agent Loop 行为保持不变；已有用户配置无需迁移即可继续启动。
- N5：异步安全——请求 id 分配、待处理响应配对、超时取消和连接关闭在并发条件下保持一致；同一请求只能完成一次，不得遗留悬空等待任务或产生未处理的异步异常。
- N6：安全执行——stdio 的 `command` 与 `args` 必须作为程序及参数直接启动，不经 shell 拼接或二次解释；HTTPS 使用系统默认的证书校验，首版不提供关闭证书校验的配置。
- N7：秘密保护——已展开的环境变量、stdio 环境覆盖值、HTTP 认证请求头和会话标识不得出现在 Agent 上下文、正常终端状态、异常文本或测试快照中；可观察错误只指出 Server、阶段和非敏感原因。
- N8：输入不可信——Server 提供的工具描述、Schema、注解、日志和调用结果均按外部输入处理。格式错误的数据只能导致该工具或该 Server 受控失败，不得触发 MewCode 本地代码执行、路径访问或权限绕过。
- N9：资源有界——工具结果沿用现有文本上限；stderr、SSE 和协议读取必须持续消费且不得因缓冲区填满造成死锁，连接关闭后不得残留子进程、网络客户端或读取任务。
- N10：确定性——相同的两层配置和相同的 `tools/list` 结果必须产生相同的合并结果、公开工具名称与注册顺序，使 Provider 工具定义和权限规则保持稳定。
- N11：可移植性——stdio 启动、UTF-8 通信、取消和分级终止必须在项目支持的 Windows 与类 Unix 环境中具有等价的可观察行为。
- N12：可测试性——默认自动化测试不得访问真实 LLM、真实远程 MCP 服务或依赖机器上已安装的第三方 MCP Server；配置、stdio、HTTP JSON、HTTP SSE、乱序响应、超时和进程退出均可由本地 fake 或 mock 重现。
- N13：可维护性——传输差异不得泄露给工具适配和 Agent 调用流程；两种传输共享相同的 JSON-RPC 请求配对、会话语义、错误分类和结果转换规则。

## 不做的事

- 不支持 MCP `2026-07-28`、`2024-11-05` 或其他协议版本，也不自动探测并降级到旧版 HTTP+SSE 传输。
- 不实现 MCP 资源的列出、读取或订阅，不实现提示词、采样、引导、补全、Roots、Tasks、客户端日志消费或其他非工具能力。
- 不处理运行期间的工具列表变化；即使 Server 宣告 `listChanged`，也不刷新注册中心。
- 不实现 Server 健康检查、心跳监控、后台保活、自动重连、自动重新初始化或 stdio 子进程自动重启。
- 不实现长期 Server 主动推送 GET 流、SSE 断点续传或跨 HTTP 请求流的事件重放；只处理当前请求对应的 JSON 或 SSE 响应。
- 不实现 OAuth、动态客户端注册、授权元数据发现、浏览器登录或令牌刷新；HTTP 身份认证仅使用用户配置的静态请求头。
- 不从 MCP Registry 或其他来源搜索、安装、升级或卸载 Server；只连接用户明确写入配置的 Server。
- 不支持运行时新增、删除、启停或重载 Server 配置，也不增加 Server 管理命令或专用 UI。
- 不实现 JSON-RPC 批量请求或批量响应；每条协议消息独立发送和配对。
- 不建立跨 MewCode 进程的连接、工具列表或会话持久化缓存。
- 不把图片或音频型工具结果接入模型的多模态输入，也不把二进制结果保存为本地文件。
- 不主动读取资源链接或嵌入资源引用；工具结果中的资源信息只按 F26 转换为文本。
- 不新增完整 JSON Schema 引擎，也不在客户端校验远端工具的 `outputSchema`；输入参数沿用现有 MewCode 校验，Server 仍负责完整参数与结果校验。
- 不根据远端工具注解自动降低权限、开放并发或绕过人工确认，也不为单个 MCP 工具增加新的权限配置格式。
- 不承诺隔离远端工具在其 Server 内部产生的副作用；MewCode 的职责边界止于调用前权限决策、协议通信与结果处理。

## 验收标准

### 配置

- AC1（F1，N4）：使用一份不含 `mcp_servers` 的现有用户配置启动 MewCode，程序正常进入 REPL，六个内置工具及模型 Profile 行为与改动前一致。
- AC2（F1-F2）：用户级配置声明 Server A 与 Server B，项目级配置声明 Server B 与 Server C 时，最终启用 A、项目版本的 B 和 C；B 不继承用户版本中未在项目版本声明的字段。
- AC3（F3-F4，F6，N6）：有效 stdio 配置能够以配置的程序、参数、工作区目录和“继承环境后覆盖”的环境启动 Server；`${VAR}` 可在一个值中展开多次，程序及参数不经过 shell 解释。
- AC4（F3，F5-F6）：有效 HTTP 配置把展开后的自定义请求头发送到配置端点；系统协议头无法被用户值覆盖，`url` 和非 header 字段中的 `${VAR}` 保持字面值。
- AC5（F7）：配置文件包含非法 YAML、非法根结构或非 map 的 `mcp_servers` 时启动失败并指出文件；同一份合法文件中一个 Server 条目无效、另一个有效时，仅无效 Server 被警告并跳过。
- AC6（F6-F7，N7）：stdio 环境或 HTTP header 引用未定义变量时，仅对应 Server 被跳过，警告包含变量名和 Server 名但不包含任何已展开秘密值。

### 传输、握手与 JSON-RPC

- AC7（F8，N1-N2）：同时配置一个正常 Server 和一个在启动阶段无响应的 Server，正常 Server 在自身流程完成后即可注册工具；无响应 Server 到达超时后被跳过，MewCode 仍可进入 REPL。
- AC8（F9，N3）：stdio fake 观察到逐行 UTF-8 JSON-RPC 请求并能逐行返回响应；其 stderr 同时持续输出日志时不污染 stdout 协议解析，也不因缓冲区填满而死锁。
- AC9（F10，N3）：HTTP fake 使用 `application/json` 依次响应初始化、工具发现和工具调用时，MewCode 接受结果，并在初始化后的请求中携带协商版本与 Server 返回的会话标识。
- AC10（F10，N3）：HTTP fake 对初始化、工具发现或工具调用返回请求范围内的 SSE 流时，MewCode 从事件中取得对应 JSON-RPC 响应；未启动独立的长期 GET 推送连接。
- AC11（F11-F12）：Server 观察到首条请求为带 `2025-11-25` 的 `initialize`，随后为 `notifications/initialized`，再后为 `tools/list`；返回其他版本或未声明工具能力时，该 Server 不注册工具。
- AC12（F13，N5）：同一 Server 对多个并行请求按相反顺序返回响应时，每个调用仍得到自己的结果；重复响应、未知 id 和非法消息被隔离，任何请求都不会被错误完成两次。
- AC13（F13）：Server 发起 `ping` 时收到空成功响应；发起资源读取、采样或其他未协商请求时收到“不支持该方法”的 JSON-RPC 错误，且 MewCode 不执行对应能力。
- AC14（F14，N1，N5）：请求超过等待上限时，调用得到超时失败，待处理记录被移除，并在连接仍可写时观察到取消通知；随后关闭客户端不会继续等待该请求。

### 工具发现、命名与注册

- AC15（F15）：`tools/list` 连续返回两页并在第一页提供 `nextCursor` 时，两页中的全部有效工具都被注册，第二次请求携带第一页游标。
- AC16（F16-F17，N10）：合法且不超长的工具公开名精确为 `<server>__<tool>`；包含点号、非法字符或超长的基础名得到满足 `^[A-Za-z0-9_-]{1,64}$` 的稳定哈希名称；重复运行映射结果相同，不同原名不被静默映射到同一工具。
- AC17（F17，N8）：同一 Server 返回一个有效工具和一个非法、重复或冲突工具时，只跳过问题工具并显示带 Server 名的警告，有效工具仍可调用，问题定义不会触发本地代码执行或权限绕过。
- AC18（F18）：注册后的 MCP 工具描述与输入 Schema 出现在 Anthropic 和 OpenAI Provider 发送的工具定义中，模型按公开名调用时能找到对应适配工具。
- AC19（F19）：Server 在启动后发送 `notifications/tools/list_changed`，已注册工具集合保持不变，也不产生新的 `tools/list` 请求。
- AC20（N10）：相同配置与相同分页结果连续启动两次时，公开名称和 Provider 看到的工具顺序完全一致。

### 权限、调度与调用

- AC21（F20，F23）：无论 Server 注解声称工具只读与否，所有 MCP 工具都按副作用工具进入权限与独占调度；与其他工具同时出现时不并发执行且保持模型给出的调用顺序。
- AC22（F21-F22）：权限选择“拒绝”时 Server 未收到 `tools/call`；选择“仅本次”后只有当前调用放行；选择“本会话”或“永久”后，同一公开工具使用不同参数的后续调用也按现有作用域规则放行。
- AC23（F22）：权限拒绝以带公开工具名的失败结果返回 Agent，Agent Loop 可以读取失败并继续选择其他工具或生成最终回答。
- AC24（F24，F29）：连续两次调用同一公开工具时，Server 收到原始工具名和未经重命名的参数对象，两次调用复用同一已初始化会话且不出现新的 `initialize`。

### 结果、错误与隔离

- AC25（F25）：工具同时返回多个文本块和 `structuredContent` 时，Agent 结果按顺序包含全部文本以及可解析的 JSON 文本，且没有静默丢失任一部分。
- AC26（F26）：资源链接和文本型嵌入资源被转换为含 URI 与可用文本的描述，期间没有资源读取请求；图片和音频结果只包含类型、MIME 与省略标记，不包含 Base64 数据。
- AC27（F27，N8）：分别模拟 `isError: true`、JSON-RPC error、HTTP error、非法响应、超时和连接中断，每种情况都得到含 Server 与公开工具上下文的失败结果，REPL 与 Agent Loop 不崩溃，外部数据不触发 MewCode 本地执行。
- AC28（F28，N7，N9）：超长结果被截断并带现有截断标记；结果、警告、终端状态和异常文本中均找不到配置的环境秘密、认证 header 值或 HTTP 会话标识。
- AC29（F30）：Server 初始化或发现失败时没有任何该 Server 工具；Server 在运行期退出或会话失效时，待处理及后续调用快速失败，且没有观察到重启、重新初始化或重连。
- AC30（F31，N2）：一个 Server 运行期失败后，另一个 MCP Server 的工具和六个内置工具仍能成功调用，Provider、REPL 与 Agent Loop 继续工作。

### 关闭、兼容与端到端

- AC31（F32，N1，N9）：正常退出、启动中止和用户取消三种路径都会清理所有已创建客户端；stdio Server 先收到输入关闭，拒绝退出时再被终止；有会话标识的 HTTP Server 收到结束会话请求；一个清理失败不阻止其他清理。
- AC32（N5，N9）：完成超时、取消、传输断开和整体关闭测试后，不存在未完成的协议等待者、后台读取任务、子进程或未关闭网络客户端，也没有未处理的异步异常警告。
- AC33（N11）：Windows 与类 Unix 行为测试分别覆盖 stdio 启动、输入关闭、等待、终止和强制终止分支，产生等价的成功、失败与超时结果。
- AC34（N12）：完整自动化测试在没有真实 LLM key、外部网络和第三方 MCP Server 的环境中可重复通过，HTTP 与 stdio 场景均由本地 fake 或 mock 提供。
- AC35（N13）：同一套初始化、分页、调用、错误和结果用例分别通过 stdio 与 HTTP 传输运行时，除传输可观察信息外得到相同的注册工具和 MewCode 工具结果。
- AC36（F1-F32）：stdio 端到端场景从两层配置合并开始，依次完成子进程启动、初始化、分页发现、命名注册、模型选择、权限放行、工具调用、结果回灌和退出清理，并得到预期最终回答。
- AC37（F1-F32）：Streamable HTTP 端到端场景从带环境变量 header 的配置开始，依次完成初始化、会话标识复用、SSE 工具发现、权限放行、JSON 工具调用、结果回灌和退出清理，并得到预期最终回答。
- AC38（F7-F8，F30-F32）：混合故障端到端场景同时配置无效 Server、启动超时 Server、运行期失败 Server 和健康 Server；MewCode 只暴露可用工具，所有失败均有独立且不泄密的反馈，健康 Server 与内置工具持续可用，退出时全部资源被清理。
